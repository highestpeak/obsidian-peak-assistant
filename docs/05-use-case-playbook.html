这页解决什么

功能地图回答“Peak Assistant 有哪些能力”。这份 playbook 回答另一件更具体的事：用户坐在 Obsidian 里，手上有一个任务，应该点哪里、问什么、看到什么结果。

它面向两类人：一类是正在用插件的人，他们不想先学架构；另一类是维护者和 coding agent，他们要从真实任务回到功能文档和代码入口。这里的每个 case 都尽量避免内部黑话：先说用户意图，再说 UI 入口，最后才说背后的 Search、Chat、Copilot、Harness 或未来 Command Gateway。

阅读方式 不需要从头读到尾。打开目录，找到最像你当下那句话的 case；如果 case 后面标了“planned”，就说明它目前是设计方向或后续文档，不要把它当作已完成的用户功能。

先选入口

Peak Assistant 的入口不是一个。你要做的事情不同，应该从不同 surface 开始。

用户会说第一入口为什么详细文档
“我想问当前笔记 / 当前话题。” 侧边栏 ribbon：Open Peak Assistant；或 Chat 相关视图。 Chat 会把用户消息、会话历史、当前上下文和能力开关一起送进回答流程。 11 Chat Context
“我记得有这个概念，但忘了在哪。” Command Palette → Quick Search → Vault Search。 Search 会混合关键词、语义、标题、路径、图关系和点击反馈，不只找完全相同的词。 12 Search
“我想让 AI 看一下整个 Vault。” Quick Search → AI Analysis，或 Open Copilot → Vault。 这是跨笔记分析，不是单条搜索结果。它通常依赖索引、Search 和 Vault actions。 13-feature-vault-intelligence.html · planned
“我想润色、审阅或整理当前文档。” Command Palette → Open Copilot → Document。 Document lane 面向当前文档动作，例如 polish、review、suggest links、split、tags。 16-feature-document-copilot.html · planned
“我想配置模型、Web Search、profile 或第一次 setup。” Settings 或 Setup Wizard。 很多能力不是功能坏了，而是 provider、profile、index 或权限没有配好。 04-configuration-and-user-views.html · planned
“我想跑一个多步 agent，但不要失控。” 具体功能入口发起任务；底层应接入 Agent Harness。 Harness 负责模型选择、工具权限、trace、context、预算和停止条件。 21 Agent Harness

找资料和理解 Vault

这类任务的核心不是“让 AI 随便回答”，而是先把 Vault 里的相关材料找出来，再决定要不要让 AI 分析。

已在代码中确认Quick Search

Case 1 · 我记得一个概念，但忘了笔记标题 Vault Search

怎么做
  1. 打开 Command Palette，运行 Quick Search。
  2. 停在 Vault Search tab。
  3. 输入你记得的概念词、近义词或片段。
成功结果

结果列表会显示匹配笔记、路径、摘要或高亮，并显示结果数量与耗时。排序不是纯关键词次数；相关概念、标题路径和图关系也可能影响结果。

已在代码中确认Scoped search

Case 2 · 我只想在当前文件或某个 folder 里找 # / @ / :

怎么做
  1. 打开 Quick Search。
  2. 用 # 进入 in-file 模式，或用 @ 进入 folder 模式。
  3. 如果要跳到行号，可以用 : go to line。
成功结果

输入框附近的 mode label 会切到 vault、in-file、folder、line 或 help。这个反馈很重要：它说明你不是在做全库搜索，而是在限定范围内搜索。

已在代码中确认Vault Intelligence

Case 3 · 我想让 AI 总结某个主题在 Vault 里的材料 AI Analysis

怎么做
  1. 打开 Quick Search（默认 Cmd/Ctrl + Shift + K）。
  2. 切到 AI Analysis tab。
  3. 选 Vault Analysis mission。
  4. 输入主题或问题，例如“最近三个月我对 RAG 的看法有什么演变”。
  5. 可选：在 Copilot 侧栏切到 Vault tab，触发 Vault Health Scan（13-feature-vault-intelligence.html §Signals）或 Knowledge Gaps，让 AI 先扫一遍再总结。
成功结果

你应该拿到一份围绕 Vault 材料的分析报告，含引用清单、confidence 提示、以及 lint findings（若触发过 Vault Health Scan）。落 Vault 的位置默认 peak-assistant/analysis/。降级路径：检索无结果 → 提示"未找到相关材料"；模型失败 → 保留 partial + retry 按钮。深入见 13 · Vault Intelligence。

已在代码中确认AI Graph

Case 4 · 我想看一组笔记之间的关系 AI Graph

怎么做
  1. 打开 Quick Search → AI Analysis。
  2. 选 AI Graph mission，用自然语言描述你想看的关系（例："帮我看 tag=research 下 2026 年新加的笔记怎么连的"）。
  3. view 打开后：hover 节点看 title/summary/degree；单击节点在右侧栏 inspection panel 里看 backlinks / semantic edges / community。
  4. 点顶部 Highlight communities 用 Louvain 分组着色；Highlight bridges 用 Brandes betweenness 突出结构洞。
  5. 右上 Open in leaf 把当前视图切成独立 leaf；点节点标题回原始笔记。
成功结果

你得到一张按语义 / graph 关系聚合的图，节点来自 vault.sqlite 的 document 表，边来自 edges（wikilink / backlink / semantic edge / co-citation）。用户可从图节点直接回笔记。降级：数据不足 → 显示 "<20 nodes"; 无 embedding → 只画 wikilink 图。深入见 13 · Vault Intelligence · Graph 与 23 · Search Index。

写作和整理笔记

这类任务通常发生在当前文档旁边：用户已经在写，想要改得更清楚、找相关链接、拆分结构或补标签。

已在代码中确认Open Copilot

Case 5 · 我想润色当前文档 Document → Polish

怎么做
  1. 打开当前要处理的笔记。
  2. 运行 Open Copilot。
  3. 选择 Document lane 里的 Polish Document 或 Format Polish。
成功结果

你应该得到面向当前文档的改写或格式优化建议。详细文档还没写，所以现在只把它作为用户入口记录，不把内部实现展开在本页。

已在代码中确认Review / Correct

Case 6 · 我想检查内容是否有问题 Document → Review Article

怎么做
  1. 运行 Open Copilot。
  2. 进入 Document。
  3. 使用 Correct Content 或 Review Article。
成功结果

结果应该围绕当前文章给出问题、修改建议或审阅意见。未来 16-feature-document-copilot.html 要写清：它是否直接改文档，是否需要用户确认，如何保留原文。

已在代码中确认Links / Tags / Split

Case 7 · 我想给当前笔记补链接、标签或拆分建议 Document actions

怎么做
  1. 打开 Open Copilot → Document。
  2. 选择 Suggest Links、Suggest Links (Graph)、Suggest Tags 或 Suggest Split。
成功结果

你应该得到“这篇笔记还可以连到哪里、该打什么标签、是否需要拆成多篇”的建议。这个 case 和 Search / Vault Intelligence 有天然关系，后续文档要把引用来源写清。

AI 分析和多步任务

只要一个任务需要多轮模型调用、工具执行、权限控制、trace 或预算，它就不应该散落在某个 feature service 里临时写循环。

已写正稿Agent Harness

Case 8 · 我想让 AI 连续搜索、读取、判断，再给结论 Harness-backed task

怎么做
  1. 从具体功能入口发起任务，例如 Chat、Vault analysis 或未来 command gateway。
  2. 让 feature 只描述目标、可用工具、权限、预算和输出格式。
  3. 多步执行交给 Harness，而不是在 feature 里复制一条 loop。
成功结果

每一步模型调用、工具调用、权限判断、context 压缩和停止条件都能被 trace。失败时应该得到可解释的 AgentLoopResult，而不是沉默失败或继续乱跑。

已在代码中确认Context Pipeline

Case 9 · 我想让 AI “知道我现在在做什么” Context-aware answer

怎么做
  1. 普通问答：直接在 Chat 里发消息 —— Context Pipeline 会自动装配：activeFile（当前编辑的笔记，取 title + 前 N 段） + recentMessages（当前 conversation 最近 K 轮） + focusFolder（Settings → General → Focus Folder，若设置则限定 retrieval scope）+ 用户 profile（语言、tone、姓名）。
  2. 需要跨文档上下文：在 composer 里 @ 触发 attachment picker 手动挂笔记 / 网页 / PDF；# 触发 tag 语义检索；: 触发 mission / capability 选择。
  3. 多步 agent 任务：feature 把 ChatConversation + focusFolder + activeFile + budget 通过 RunEnvelope 传给 Agent Harness，不要在 UI 层拼 prompt。
  4. Debug context：Chat → 消息头齿轮 → Show context stack（会显示 pipeline 装配的每一层与截断比例）。
成功结果

回答能引用上下文（例如提到 activeFile 的具体段落）；context 超预算时按优先级降级：attachments 全保留 → recentMessages 从头截断 → focusFolder retrieval 减少 top-k → activeFile 只留 heading。底层 pipeline / 优先级 / 预算规则详见 22 · Context Pipeline；Chat 端的用户可见字段详见 11 · Chat Context。

配置、用量和状态

很多“功能不好用”的问题，根因是 profile、provider、index、Web Search 或权限没有准备好。配置文档要专门写，不能分散在每个功能页里。

已在代码中确认Settings / Setup Wizard

Case 10 · 我第一次安装，想把模型和基础能力配起来 Setup Wizard

怎么做
  1. 运行 Setup Wizard 或打开 Settings。
  2. 配置 provider、profile、search/index 相关选项。
  3. 回到 Chat 或 Quick Search 做一次最小验证。
成功结果

Chat 能回答，Quick Search 能返回结果，需要 AI 的能力能找到可用 profile。详细配置项、默认值和 Vault 里生成的 folder/file 形状，都应该进入 04。

已在代码中确认Web Search profile

Case 11 · AI Analysis 提示没有 Web Search profile Settings → Profiles

怎么做
  1. 打开 Settings。
  2. 进入 Profiles 相关配置。
  3. 把一个 profile 指定为 Web Search。
成功结果

回到 AI Analysis 后，Web Search 相关能力不再提示缺 profile。这个错误信息已经在 Quick Search UI 中出现，04 需要把排障路径写成用户手册。

已在代码中确认Usage Dashboard

Case 12 · 我想知道 AI 用量和成本情况 Usage Dashboard

怎么做
  1. 运行 Usage Dashboard。
  2. 查看模型、profile、时间范围或功能维度的使用情况。
成功结果

用户能判断哪些能力最常用、哪些 provider 成本较高、是否需要调整 profile。后续可并入配置手册，或单独写 17-feature-usage-dashboard.html。

未来能力别误用

有些能力已经有很重要的正稿，但不是“今天打开插件就能当成稳定功能用”。这页必须把边界说清楚，免得历史设计稿冒充现状。

用户会说现在怎么理解不要怎么做未来文档
“我希望写作时旁边自动出现相关线索。” 这是 Ambient Push 的方向：Current Work State / Session Thought Trace，不是旧式 Related Notes 侧栏。 不要把它插回旧架构，也不要把它当成第一阶段功能强行实现。 14-feature-ambient-push.html
“我想让 AI 帮我执行 Obsidian 命令。” 这是 Command Gateway：AI 判断和起草，用户授权，runtime 控边界。 不要让 AI 直接绕过权限执行命令；它是 T12 capstone，不是先做的小功能。 15-feature-command-gateway.html
“我想让插件自己改很多笔记。” 这类能力必须先经过 Harness、权限、预算、trace 和用户确认。 不要在 feature service 里写一个无 trace 的批量修改 loop。 21 Agent Harness；未来 Command Gateway 文档
