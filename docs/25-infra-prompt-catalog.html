1. 先看结论：固定按钮和 AI 动态建议是两层东西

截图里的“润色文本、补一个例子、转成表格”一直不变，是因为它们来自 Composer 配置里的固定快捷操作，不是 Copilot 临时生成的建议。

点击后，固定操作会把自己的指令、当前块和附近内容装进共享 Prompt，再交给模型。Copilot / Ambient 如果要根据正文持续提出新问题、新任务或新改法，应该走另一条“发现 → 建议 → Agent Run”链。当前代码里，固定操作是完整的；动态建议只有部分链路，不能把两者混成一个按钮列表。

2. Prompt 的唯一来源怎么工作？

功能代码只应该选择 Prompt、准备材料和发起运行；固定任务说明应该留在模板文件里。

一条正常的 Prompt 链 身份、正文、上下文和模型各有自己的位置
flowchart LR Entry["按钮、Copilot 或后台任务"] --> Pick["选择 PromptId
准备变量"] Pick --> Service["PromptService / AIServiceManager"] Service --> Registry["TemplateRegistry
ID、说明、system 配对"] Registry --> Body["templates/prompts/*.md
唯一固定正文"] Body --> Render["TemplateManager
把变量填进去"] Context["Context Pipeline
当前文档、来源、用户偏好"] --> Run["AI / Agent Run"] Render --> Run Model["模型路由与 Profile"] --> Run Run --> Result["文字、JSON、insight 或工具步骤"] Custom["用户自己的 Custom Prompt
Vault Markdown"] -. "独立来源" .-> Run

人话解释：PromptId 是名字，Registry 是通讯录，Markdown 是正文，变量是这一次的实际材料，模型路由决定找谁执行。它们不应该挤在同一个文件里。

要改固定任务说明

改 templates/prompts/<id>.md。如果是 Composer 的固定快捷指令，则改 templates/config/composer.json 的 capabilities.instructions。

要改这次给 AI 的材料

改调用者准备的变量或 Context Pipeline；不要把整份 Vault 直接塞进模板。

要改模型

日常只改 AI Setup；只有特殊 Prompt 才单独选择模型。当前 promptModelMap 虽能加载，但主执行链没有消费，不能当作已可用能力。

要让用户自定义

走 Vault 里的 Custom Prompt 文件和 override 机制；不要修改插件内置模板来冒充用户配置。

4. Copilot 和 Ambient 用哪些 Prompt 产生动态建议？

项目里确实有“根据内容继续生成”的 Prompt，但它们不是段落操作栏那三个固定按钮，也不是所有链路都已接到 Composer。

动态能力主要 Prompt现在真正做什么当前判断
文档 Auto Reviewcopilot-meta-agent-system-base + fast / complete suffix读取文档 signal、正文和用户偏好，多轮产出 insight，并可以继续讨论或起草修改。生产源码引用
Vault Reviewvault-meta-agent-system-base + fast / complete suffix读取 Vault digest，发现跨文档结构问题和行动项。生产源码引用
Copilot Agent 操作copilot-agent-*找链接、找知识缺口、补证据、写计划、写文章、检查任务等；属于用户触发的 agent playbook。生产源码引用
Chat 后续问题chat-suggest-followups根据最后一轮对话生成三个后续问题。生产源码引用
Chat 动作建议chat-suggest-actions模板已经注册，但当前扫描不到生产调用者。待接线或清理
Ambient 相关说明ambient-explanation-system/user解释“这条 pushed note 为什么和当前段落相关”，不是生成新的 finding。生产源码引用
Ambient 工作主题working-theme-inference推断当前工作主题，供上下文使用；它也不是正文建议生成器。生产源码引用
Composer 动态 finding没有独立、已接通的生产 Prompt当前 Brief 的 finding producer 主要还是规则扫描；完整 AI finding → 正文/Brief 投影 → Agent Run 仍是缺口。目标设计未接完
因此，正确产品关系是“固定能力 + 动态建议”并存

固定按钮保证随时可用；Copilot / Ambient 根据当前文档、相关材料和历史持续提出新建议。动态建议被用户运行后，也应该冻结 Prompt、上下文、步骤和结果，并进入 Generation History；没采纳不等于没生成过。

7. 这次审计发现的具体问题

5 个注册项没有生产调用者

ai-analysis-title、ai-analysis-followup、message-resources、chat-suggest-actions、gap-explanation。需要逐项判断是待接线、动态间接调用，还是旧能力残留。

一个 ID 和物理文件不同名

Registry 的 ai-analysis-title 实际加载 ai-analysis-dashboard-title.md。当前映射可以工作，但搜索、审计和人工维护容易误判。

仍有完整 Prompt 写在代码里

aiQueryParser.ts 的 Hyper Search system prompt 是明显例子；现有 no-inline 测试只检查少数英文开头，覆盖不到所有拼接方式。

Ambient 没有完整 AI finding Prompt 链

现有 Prompt 能解释相关性、推断工作主题，但没有看到一个已接通的“持续生成 Composer finding”的生产入口。

不要把“模板存在”写成“功能已经可用”

本页的状态来自 2026-07-28 当前源码静态审计。Registry 有记录只证明模板可被加载；生产引用只证明代码提到它；真正可用还需要入口、运行时、结果解析和 UI 反馈全部接通。

8. Prompt 目录已并入 AI Control Center

Prompt 只是一次 AI 动作的指令来源，不是完整运行合同。新的 AI Control Center 使用一个目录：默认按 AI action 梳理行为与配置，All Prompts 则把模板平铺成可搜索的 Prompt Library；模型路由诊断与 run history 不进入普通用户顶层导航。

Capability 是主对象

Vault Search Refine、AI Search、AI Graph、Composer transform、Vault Review 和 Chat turn 都是能力。一个能力可以有多个 Prompt、tool 和执行步骤，也可以完全没有文本 Prompt。

Prompt 仍可审阅和 override

默认正文、Vault override、system / user 配对、变量和版本继续在平铺 Prompt Library 中维护；共享 Prompt 保存前必须提示影响多少个 AI action。

模型在 action 中配置

companion template 不拥有模型；共享 Prompt 不应把所有调用者锁到同一模型。模型 default / override 只出现在对应 AI action 的 Configuration。

内部诊断不挤占主界面

run receipt 仍记录实际 Prompt、model、tools 和 artifact，但 Effective routing、Run history 与 evidence 留在 Advanced、Debug Trace 或所属产品历史中。

可审阅产物

AI Control Center 正式设计 · 全仓 AI 能力与运行链审计 · 新版可点击页面 mock。这些都是设计产物，没有修改产品代码或真实设置。

9. 以后统一维护 Prompt，按这套规则

发生什么变化必须一起更新不应该做什么
新增一个内置 Prompt增加 Markdown 正文、PromptId、PromptVariables、TemplateRegistry metadata、生产调用和测试；同时更新本目录。只加文件，不注册；或只在 React / service 里写一段字符串。
给 Prompt 增加变量更新模板占位符、PromptVariables 类型和所有调用者；明确变量是必需、可选还是按需读取。用 any 绕过缺失变量，或把大段上下文硬塞进一个字段。
增加 JSON / typed result把输出合同写进 system 模板和 schema；记录解析失败、重试和 raw output。只在 Prompt 里说“返回 JSON”，却没有程序校验。
新增 Composer 固定建议更新 composer.json 的 action 与 instruction、capability 注册、适用块、Prompt 映射和投影测试。把固定建议说成 Copilot 动态推荐。
新增动态 finding明确 producer Prompt、上下文、证据、Agent Run、stream 步骤、review surface 和 Generation History。只生成一句建议后丢掉 Prompt、证据和未采纳结果。
发现代码内固定规则判断它是稳定 Prompt 正文还是本次动态包装；稳定正文迁到 templates/prompts。靠 no-inline 测试的四个英文正则当作完整治理。

新增 Prompt 的最小检查单

PromptId 有名字 → PromptVariables 有类型 → Registry 有用途、分组、system 配对和输出合同 → Markdown 有唯一正文 → 调用者只传变量 → stream / agent 记录 Prompt 身份 → 结果进入对应历史 → 本页能查到。
