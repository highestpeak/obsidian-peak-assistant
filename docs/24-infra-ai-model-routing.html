24 · Infrastructure · AI model routing

AI 模型路由：每个用到 AI 的地方在用哪个模型，什么时候降级、什么时候升级。

这篇写给要回答“这次 AI 调用到底跑的哪个模型？为什么？”的维护者。Peak 里所有 AI 调用都经过同一套解析——用途槽（slot）→ 起始 tier → 可选的运行时升级 → 未配置时的降级 fallback。读完你能对任意一个 AI 触点，说清它的模型来源、升级条件、降级链。

  • 唯一解析入口：ProfileRegistry.resolveSlot(slot)——harness 与 SDK 两条路径都走它。
  • 唯一配置面：Settings → AI Setup 的五行（Conversation / Fast Lookup / Research / Use stronger model / Knowledge Index）。

0. 这份文档怎么读。

本文是 runtime routing map + source-code reading guide。它不解释每个功能做什么（那在各自的 feature 文档里），只回答一件事：某个 AI 触点的模型是怎么被选出来的。

本文读者

要排查“这次为什么用了 deepseek-r1 而不是 qwen”、或要改模型路由的工程师 / AI coding agent。

读完能做什么

对任意 AI 触点说清：用哪个槽、起始 tier、能不能升级、没配时降级到哪、改哪一行 Settings 生效。

本文不做什么

不讲 Provider/Profile/MCP/Skill 五层供给（见 18），不讲 Harness 运行时全貌（见 21）。

1. 一张图：三层解析。

任何一次 AI 调用，模型都由三层依次决定。理解这三层，整份文档就通了。

图 · slot → tier → fallback
①  用途槽 slot ────────────────────────────────────────────────
    功能按"用途"声明自己要哪个槽：
    fast · research · stronger · conversation · knowledgeIndex
    （fast/research/stronger 同时是 harness 的三级 cascade tier）

②  起始 tier + 运行时升级（仅 harness agent） ────────────────
    TierController 从 preferred tier 起步，
    某步自评分低于阈值 → 沿 fast → research → stronger 升一级
    （只升不降，每轮上限 1 次）

③  降级 fallback（解析时，非运行时） ─────────────────────────
    resolveSlot：该槽没显式配置 → 回退到 role → 再回退到 profile 默认
    fast     → Fast Lookup ?? agent-fast role
    research → Research     ?? agent role
    stronger → Stronger     ?? Conversation(chat → agent)
    conversation → Conversation(chat → agent)
    knowledgeIndex → Knowledge Index(embedding)
关键区分：升级 ≠ 降级。
  • 升级（cascade / escalation）是运行时行为：一次多步 agent 跑到一半，模型不确定 → 临时切到更强的 tier。只发生在走 TierController 的 harness agent 上（AI Analysis 及其后续对话）。
  • 降级（fallback）是解析时行为：某个槽你没在 Settings 里配 → resolveSlot 回退到旧 role，再回退到当前 profile 的默认模型。跟运行质量无关，纯粹是“没配就用替代”。

3. 五个槽 + 降级规则。

槽是唯一的用户配置单位（Settings → AI Setup 五行）。resolveSlot 是唯一解析入口——harness 的 bindings.ts 和 SDK 的 queryWithProfile 都调它，所以改一行 Settings 到处生效。

槽 slotUI 行降级 fallback 链典型消费方
fastFast LookupFast Lookup 配置 → agent-fast roleRefine、搜索解析、Review fast、后续对话、上下文压缩
researchResearchResearch 配置 → agent roleAI Analysis、报告生成、Graph、Review complete、Copilot、知识直觉、Ambient
strongerUse stronger modelStronger 配置 → Conversation(chat → agent)仅作升级兜底（见 §4）
conversationConversationConversation(chat) → agent主 Chat、Auto 默认
knowledgeIndexKnowledge IndexEmbedding profile语义搜索、索引构建

3.1 降级规则的完整形式

对 fast / research，SDK 路径（queryWithProfile）在 resolveSlot 之上还有一层最终兜底——回退到当前 profile 的默认模型：

modelId =
    resolveSlot('research')?.modelId          # ① Research 显式配置
    ?? （resolveSlot 内部）agent role.modelId  # ② 旧 Agent role
    ?? profile.primaryModel                    # ③ 当前 profile 默认主模型
                                               #    （fast 槽对应 profile.fastModel）

harness 路径（bindings.ts）里，若 resolveSlot 整体返回 null（该槽和其 role 都没配），该 tier 直接从 bindings 里缺席，TierController 会 fall-forward 到下一个已绑定的 tier（resolveStartTier / nextBoundTier）。

降级 · 实例

你只在 Settings 里配了 Research = OpenRouter · deepseek-r1，没单独配 Fast Lookup、没配 Stronger。此时：

  • resolveSlot('research') → deepseek-r1（① 命中）。
  • resolveSlot('fast') → Fast Lookup 空 → 回退 agent-fast role；若 role 也空 → SDK 路径再回退 profile.fastModel。
  • resolveSlot('stronger') → Stronger 空 → 回退 Conversation；Conversation 空 → 回退 agent role。

3.2 配置怎么落到槽（镜像同步）

三个 harness tier 配置存在 settings.harnessSettings.{localFastConfig, localDeepConfig, onlineConfig}（字段名沿用旧名，不影响槽语义）。main.ts 在 bootstrap 与每次 saveSettings() 时经 ProfileRegistry.setTierConfigs() 把它们镜像进 registry，resolveSlot 才能读到当前值。所以改任意一行 AI Setup，保存后立即对所有路径生效。

4. 升级规则（cascade / escalation）。

只有走 TierController 的 harness agent 会升级（AI Analysis、其后续对话）。SDK 一次性路径不升级。

4.1 机制

  • 起步。从 policy.preferred 的 tier 开始（AI Analysis=research，后续对话=fast）；若该 tier 未绑定，fall-forward 到下一个已绑定 tier。
  • 每步自评。onStepFinish 用 scoreStep 给这一步打分（见公式）。
  • 触发升级。若 allowEscalation 且 未超本轮上限 且 score < escalationThreshold → 沿 fast → research → stronger 升到下一个已绑定 tier。
  • 模型也能自己要求。model 可调 escalate 工具（带 reason）主动升级。
  • 只升不降。升上去就不回落；每轮最多升 maxEscalationsPerLoop 次。

4.2 打分公式

score = 0.5 · schemaPassRate   # 工具调用的 schema 校验通过率
      + 0.3 · toolSuccess      # 工具执行成功率
      + 0.2 · language         # 文本确定性（对冲/不确定措辞扣分）
                               # scoreStep.ts:41 · clamp 到 [0,1]

升级条件： score < escalationThreshold

4.3 当前实际生效的参数

AI Analysis / 后续对话只向 TierController 传了 preferred，其余走 DEFAULT_TIER_POLICY：

参数实际生效值含义
allowEscalationtrue允许升级
escalationThreshold0.6score < 0.6 触发
maxEscalationsPerLoop1每轮最多升 1 级
升级 · 实例

Research=deepseek-r1，Stronger=qwen3-max。跑 AI Analysis：起步 research（deepseek-r1）。某步一个工具 schema 校验失败 → score 掉到 ~0.35 < 0.6 → 升到 stronger（qwen3-max）跑后续步骤。本轮已用满 1 次升级，不再升。若 Stronger 未绑定，则无处可升，继续用 research。

⚠ 已知 gap：Settings 里的升级旋钮当前未接入。

Settings → Profiles 有 allowEscalation 开关、maxEscalationsPerLoop 滑块（存在 harnessSettings，默认 threshold 0.4 / max 3），但 VaultSearchAgent / FollowupChatAgent 只向 TierController 传了 { preferred }，没有把这些字段接进 policy。所以真正生效的是 DEFAULT_TIER_POLICY（0.6 / 1），UI 上调这几个旋钮当前不改变运行时行为。要让它们生效，需在构造 TierController 时把 harnessSettings 的 escalation 字段并入 policy。

5. 三条典型路径详解。

5.1 一次完整的 AI Analysis

同一次分析跨了两条解析路径，注意区分：

  • 搜索阶段（列文件夹、grep、读笔记、submit_plan）：harness agent，槽 research，可升级到 stronger。
  • 报告生成阶段（分段成文、Mermaid）：SDK queryWithProfile，槽 research，不升级。
  • 结果面板后续对话（Topic/Graph/…）：harness agent，槽 fast，可升级。

因为搜索与报告生成都归到 research 槽，改一次“Research”对整条分析链一致生效——这是 2026-07-23 统一 resolver 之后的行为；此前报告生成走独立的 agent role，会和搜索漂移。

5.2 主 Chat 一条消息

槽 conversation（= Conversation 行）。经 harnessChatRunner 绑成单 tier、allowEscalation:false——永不升级。Assistant 指定了固定模型时以 Assistant 为准，否则 Auto 默认回到 Conversation。

5.3 报告生成 / Graph / Review（SDK 路径）

全部经 queryWithProfile：primary=resolveSlot('research')，fast=resolveSlot('fast')。没有 tier cascade——SDK 内部可能多轮工具调用，但模型不会中途换 tier。Review 的 fast/complete 模式分别落到 fast/research 槽。
