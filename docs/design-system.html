系统总则

不是把所有东西涂成同一种颜色，而是让同一种意图只有一种视觉与行为表达。

01 · Principles

一个视觉真源

peak-tokens.css 定义 Peak Default；组件只读取 semantic roles，不读取 Obsidian visual variables，也不在 surface 内再造一套颜色和圆角。

组件按意图复用

Button、Segmented、Toggle、Row、Chip、Popover、Candidate、Receipt 按交互任务选择。不能因为外形相近，就把普通 Button 拼成 view switch。

产品保留领域语义

Composer 编辑器、Streamdown、CodeMirror、Cytoscape、React Flow 与 Recharts 保留专用内核；它们共享主题、shell、状态与交互契约，而不是被塞进万能组件。

密度不改变字号

Compact / Comfortable 只改变间距、行高和信息展开程度。默认正文、label 与 metadata 字号保持稳定，避免每个页面形成自己的缩放体系。

拒绝宿主视觉

Obsidian 可以承载 Peak，但它的主题、裸标签规则和第三方 CSS 不能穿过 Peak Theme Boundary。

02 · Boundary

Obsidian 只提供环境

  • ownerDocument、window、viewport 与 DPR
  • reduced motion、forced colors 等辅助功能信号
  • 用户明确选择 Follow 时的明暗偏好信号
  • 不提供 Peak 的颜色、字体、字号、圆角与阴影

Peak Boundary 自己解析

  • Theme Pack + Appearance + Density + Accessibility + Fonts
  • 普通 DOM、Modal、Popover、Portal 与 popout 使用同一 resolved theme
  • 非法或缺失 Theme Pack 原子回退 Peak Default
  • light DOM reset 只是迁移防线；Shadow Root 是长期硬边界

Theme 是一等能力

控制器放回主题章节，不再挤在全局导航。切换下面的选项，会直接改变使用生产 CSS 的 specimen。

从补丁变成约束

08 · Governance

冻结契约

确认 semantic roles、Theme schema、Boundary、primitive inventory、Graph vocabulary 与合法例外；建立当前扫描基线。

建立主题运行时

Theme Resolver、validation、preview、atomic fallback、themed Portal host 与 popout ownerDocument 传播。

收敛公共组件

合并并行 Button；统一 Segmented、Input、Row、Overlay、AI state、Result Browser 与 Graph chrome。

按 family 整体迁移

Settings/Onboarding → Search → Chat → Composer chrome/sidecar → File Atlas/Graph → Usage Dashboard。

静态门禁

Peak scope 禁止新增 Obsidian visual vars、未登记 literal color/radius/shadow、raw button 与 surface-local segmented。扫描基线只降不升。

Hostile theme 验证

准备夸张 button、input、font、radius 和 focus 的 Obsidian 测试主题；检查真实 computed style，而不是只看 source 与 build。

真实宿主验收

Light/Dark、自定义 pack、Compact、Reduced Motion、Portal、popout、keyboard 与 fixed geometry 必须在真实 Obsidian 里分别验证。
