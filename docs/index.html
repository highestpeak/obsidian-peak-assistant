怎么用这个索引

第一次看项目，先不要从历史稿开始。根目录编号正稿是当前项目状态的可维护入口。

这个索引只回答“该打开哪份文档”。每份功能自己的用户行为、运行路径、代码证据，放在对应编号文档里。旧根目录文档没有删除，只是不再作为主入口出现。

阅读起点

先建立整体模型，再进入具体功能

    • 代码组织 — 目录职责、依赖方向和读代码顺序。
    • 用户任务入口 — 从用户要完成的工作反查功能入口。

六大产品功能

按用户看到和使用的功能组织
  1. 1
    General Search 快速找笔记，并继续浏览标题、语义结果和知识关系。
    • General Search / Hyper Search — 搜索体验、查询语法、排序、高亮与结果浏览。
  2. 2
    AI Analysis 让 AI 面向整个 Vault 做调查、解释和结构判断。
    • Vault Copilot — Vault 健康、知识缺口、hub、结构洞和分析报告。
  3. 3
    Composer 阅读、编辑和改写当前文档；AI 能力在同一个写作表面内工作。
    • Composer 里的 AI 到底怎么工作 — 用人话解释固定能力与 Copilot / Ambient 动态建议的区别、按钮点击后的完整链路、上下文、持续步骤、等待方式和生成历史。
    • Prompt 总目录 — 列出 Composer 固定指令、Copilot / Ambient 动态建议 Prompt，以及项目全部 151 个内置 Prompt 的来源、变量和调用状态。
    • AI Control Center — 系统维护 AI 能力、运行前后步骤、Prompt、模型路由、工具策略、预期行为与真实 Run；旧 Prompt Control Center 已作为其中一个工作区合并。全量审计交互稿
    • Document Copilot — polish、review、links、split 和 tags。
    • Ambient Push — 在写作位置安静呈现相关材料与可行动建议。
  4. 4
    Atlas · Doc Switch 看清当前文档的块级结构，并在打开的文档之间切换。
    • File Atlas — 文档对象树、资源层、Inspector、Graph 和 Doc Switch。交互稿
  5. 5
    Chat Studio 承载通用对话、资源输入、Assistant、媒体和结构化产物。
    • General Chat — 对话表面、消息交互和输入语义。实施规格讨论总图
  6. 6
    辅助设置 完成首次配置、系统维护和常用入口管理，不与主要工作表面争夺注意力。
    • Onboarding — 首次配置、能力说明和 readiness 检查。交互稿
    • Usage Dashboard — AI 用量、预算、成本、模型分布和告警。
    • Command Center — 与原生 Command Palette 并存的策展启动器：可配置紧凑瀑布分组、自然宽度混合按钮、真实快捷键提示与稀疏 Home。V6 交互原型 · 研究 · 全局命令治理
    • Settings — AI Setup、Knowledge Index、Tools、Media Generation 和 Advanced。Mental model

共享基础设施

功能复用这些能力，但用户不需要把它们当成功能入口
  • AI 运行与上下文 统一会话上下文、agent 执行、模型选择和能力授权。
    • Chat Context — 会话、附件、focus folder、Assistant 与媒体请求的上下文装配。
    • Agent Harness — 多步 agent 的模型调用、工具权限、trace 和停止边界。
    • Context Pipeline — Chat、AI Analysis、Composer 与 Ambient 共用的上下文管线。
    • AI 模型路由 — 用途槽、fallback 与升级规则。
    • Prompt 总目录与统一维护 — PromptId、模板正文、system 配对、变量、调用者与目录外 Prompt 来源。
    • AI Control Center 与统一运行目录 — 从能力动作出发解释 execution step、Prompt、模型、工具、artifact 与 Run 的所有权；同时保留逐 Prompt 正文 override，但不再让 Prompt 冒充运行单元。能力审计可点击 mock
  • AI 供给与命令边界 管理模型、工具和命令如何被产品功能安全复用。
    • Provider · Model · MCP · Skills — AI 供给、配置与排障。
    • Command Gateway — 产品命令的授权与 runtime 边界；它不是用户侧 Command Center。
  • 知识索引 为 Search、AI Analysis、Ambient Push 和 Atlas Graph 提供可复用的检索底座。
    • Search Index — SQLite、chunk、embedding、node/edge 和维护任务。

跨功能规则与平台

同时服务多个产品功能
  • 共享产品能力 这些文档定义跨功能的长期交互和 artifact 边界。
    • Shared AI Instruction Composer — Chat Studio、Composer Copilot、AI Graph 与后续 AI 表面共用的 PromptInput、context、附件、draft 和 submit / stop 能力；各 surface 只提供 adapter。
    • 共享模型选择器 — Chat Studio 的 ComposerModelSelector 是当前运行时模型选择的标准交互；Composer Copilot 直接复用同一组件、搜索、筛选、Profile 分组、能力标签和选中态，只用 execution-safe Profile scope 限制可执行模型。任何新 AI surface 禁止再写本地模型下拉；后续统一收敛到共享目录下的 ProfileModelPicker 组件族。
    • 共享 Segmented 动画切换 — 视图、密度、时间范围和工作模式等互斥状态统一使用公共 Segmented；需要连续空间反馈时启用 animated-pill，复用同一滑块、spring 参数和 reduced-motion 行为，禁止各功能复制一套按钮或动画。
    • AI Search Simulator Sidecar — 独立 localhost Provider，以 OpenAI Chat + Anthropic Messages 双协议替代模型推理，完整保留 AI Search 的生产编排、工具、报告和 UI；后续其他 AI surface 的确定性流程测试优先复用该 sidecar 边界。
    • AI Search 统一模式入口 — Vault Search 保持独立；AI Search 默认，AI Graph 与 Vault Intelligence 从同一个低频下拉进入，并复用历史列表与键盘语法。可交互 mock
    • AI Graph Artifact Platform — 持久化、可版本化的知识关系 artifact；全部 graph 在 AI Search 的 AI Graph mode 中以紧凑历史列表浏览，Update graph 通过 graph adapter 消费 Shared AI Instruction Composer。交互原型研究报告
    • Peak File Workspace — Image、HTML 和 PDF 共用的预览、AI sidecar 与版本保存。视觉方案能力审计
    • Peak 全键盘导航系统 — 主要工作表面共用的焦点、选择和键盘模型。视觉报告研究报告

维护结论
  • 需要多步模型调用、工具执行、权限或 trace：先接入 Agent Harness。
  • 需要“让模型知道当前工作”：先接入 Context Pipeline。
  • 需要搜索、图关系、retriever 或索引维护：先接入 Search Index。
  • 需要用户配置、profile、provider、开关或可见设置：先接入 Config / User Views。
  • 绕过这些底座在 UI 里临时拼逻辑，就是开始建第二套系统。

阅读场景：桌面/编辑器。新 root 正稿默认 HTML；主文档补写时继续使用 technical-doc-architect。
