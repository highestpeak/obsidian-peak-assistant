怎么用这个索引

第一次看项目，先不要从历史稿开始。先读根目录编号正稿：它们应该是当前项目状态的可维护入口。

这个索引只回答“该打开哪份文档”。每份功能自己的用户行为、运行路径、代码证据，放在对应编号文档里。旧根目录文档没有删除，只是不再作为主入口出现。

功能和基础设施怎么连起来

用户功能不是独立小系统。Chat 需要 context pipeline；Search 依赖 index 和 retrievers；Vault Intelligence 复用搜索、lint 和 digest；Ambient 复用搜索、图索引和 context；Agent 类能力必须走 Harness。这张图把 产品功能 与 共享基础设施 的依赖关系一次画清。

读图：上层是用户功能，下层是共享底座。加新能力时，先判断它复用哪个底座；不要为了一个功能复制一套 context、search 或 agent loop。

维护结论 如果某个新功能需要多步模型调用、工具执行、权限或 trace，它应该先解释自己如何接入 Harness；如果它需要"让模型知道当前工作"，它应该接入 Context Pipeline，而不是在 UI 里临时拼 prompt。四条底座（21/22/23/04）是硬约束——绕过它们就是开始建第二套系统。
