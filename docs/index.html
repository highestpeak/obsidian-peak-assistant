怎么用这个索引

第一次看项目，先不要从历史稿开始。先读根目录编号正稿：它们应该是当前项目状态的可维护入口。

这个索引只回答“该打开哪份文档”。每份功能自己的用户行为、运行路径、代码证据，放在对应编号文档里。旧根目录文档没有删除，只是不再作为主入口出现。

文档地图

根目录文档按主题分三组。这里列的是长期阅读入口，不记录每一波开发状态。

入门 & 地基（01、02、04、05）

项目是什么、代码怎么读、配置怎么改。第一次接触先看这几份。功能全景已经并入本页 功能和基础设施怎么连起来。

  • 01 · 架构与运行时边界 — Capability Contract、RunEnvelope、No Dual System。
  • 02 · 代码组织 — 目录职责、依赖方向、读代码顺序、改动入口。
  • 04 · 配置项 & 用户视图 — Settings、profiles、Vault 里长出的 folder/file。
  • 05 · 用户任务入口 — "我想做 X" → 从哪个功能开始、怎么做、成功长什么样。

产品功能（11–18）

用户看得到的能力。每份聚焦一个功能。

  • 11 · Chat Context — 回答前如何组装会话、附件、focus folder、能力开关。
  • 11A · Chat Studio UI/UX — 当前三栏元素、状态与代码证据；完整目标、功能合同、实施 DAG 与验收见 Chat Studio 权威实施规格；反馈来龙去脉见 讨论总图。
  • 12 · Hyper Search — 快速找笔记：关键词、语义、标题、图关系、点击反馈和高亮。
  • 13 · Vault Intelligence / AI Analysis — 让 AI 看整个 Vault：健康、知识缺口、hub、结构洞、lint 和分析报告。
  • 14 · Ambient Push — 写作时在固定位置显示相关笔记；解释 trigger、候选、信号和排序。
  • 15 · Command Gateway — AI 起草、用户授权、runtime 守边界。
  • 16 · Document Copilot — Document lane：polish / review / links / split / tags。
  • 17 · Usage Dashboard — AI 用量、预算、成本、模型分布、告警。
  • 18 · Provider · Model · MCP · Skills — 五层 AI 供给：Provider / Profile / Role / MCP / Skill 各自解决什么，怎么配、怎么排障。

基础设施（21–23）

功能共用的技术层，多个 feature 都会依赖。

  • 21 · Agent Harness — 多步 agent 的模型调用、工具权限、trace、context、停止边界。
  • 22 · Context Pipeline — Chat / Agent / Ambient 如何共享上下文装配和渲染规则。
  • 23 · Search Index — SQLite 表、chunk、embedding、node/edge、维护任务。

不在这张地图里：关键远期设想（已决策待建、调研候选、backlog）登记在 roadmap.html；局部 UI 小需求登记在 planned-requirements.html。

维护结论
  • 需要多步模型调用、工具执行、权限或 trace：先接入 21 Agent Harness。
  • 需要“让模型知道当前工作”：先接入 22 Context Pipeline。
  • 需要搜索、图关系、retriever 或索引维护：先接入 23 Search Index。
  • 需要用户配置、profile、provider、开关或可见设置：先接入 04 Config / User Views。
  • 绕过这些底座在 UI 里临时拼逻辑，就是开始建第二套系统。

阅读场景：桌面/编辑器。新 root 正稿默认 HTML；主文档补写时继续使用 technical-doc-architect。
