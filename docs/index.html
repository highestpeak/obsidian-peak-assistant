根目录清理规则

下一步不要直接批量删除。先给旧文档定身份，再迁移到合适区域。

现在的问题处理方式
`docs/` 根目录有过多 Markdown只保留 `index.html` 和少数过渡文件；只清理根目录散落文档，不动 `superpowers/` 和 `gstack/`。
旧 roadmap / TASKS 仍在根目录标成 historical，不再作为当前计划入口。
功能文档和算法文档混在一起新正稿统一进 `ground-truth/capabilities-and-algorithms.html`，每个能力写 input、pipeline、output、config、tests。
配置散在代码和文档里配置项文档必须同时连接 `templates/config/`、settings UI、fallback defaults 和用户可见文件夹结构。
视觉报告数量很多`docs/gstack/` 原位保留，只在索引里标成 design reference，不移动目录。
现代化计划和证据很多`docs/superpowers/` 原位保留，只通过索引区分 canonical、evidence、historical。

HTML 规则

以后重点维护文档默认写 HTML。Markdown 可以继续作为历史证据或短期工作记录，但不要让它承担新的正稿职责。

规则解释
每份正稿顶部写 status例如 current、draft、evidence、historical、superseded。
每份正稿写 canonicalFor明确它对哪个主题拥有最高解释权。
每份正稿列 source links引用旧 Markdown、audit、issue map，但不把旧文档混成同层目录。
每次改完跑 link check防止再次出现“列出来但打不开”的问题。
