怎么读这个 roadmap

四段自上而下就是项目在时间轴上的位置：过去里程碑 → 已决策待建 → 调研候选 → 远期想法。每一段都是状态快照，不是承诺。

"已决策"意味着有 spec、有共识、只等排期；"调研候选"意味着 docs/research/ 里有报告但决策未落；"远期 Backlog"是无 spec 的想法，不承担交付责任。

如何维护本表

触发时机动作写到哪
一个 Phase / 大波 shipped progress.md 加详细条目 + 本表 已完成的关键里程碑 加一行（只在是关键节点时） progress.md + roadmap.html
新 spec / plan 落地 本表 已决策待建 加一行，指向 spec 文件 roadmap.html
新调研完成 调研原稿写到 docs/research/YYYY-MM-DD-slug/README.md；本表 调研候选 加一行 docs/research/ + roadmap.html
Backlog 想法产生 本表 远期 Backlog 加一行（一句话即可）；正式跟踪前不要展开细节 roadmap.html
状态迁移 Backlog → 调研候选：加研究报告；调研候选 → 已决策：加 spec；已决策 → shipped：本表挪进 Done + progress.md 记录 逐段迁移

关键节点判定：能用一句话向新读者解释"我们做了什么、他能感知到什么"的才算。逐 session 的 UI 微调、bug 修复、局部 refactor 不上这张表——留在 progress.md 就够。
