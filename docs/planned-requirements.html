AI Control Center 全量配置闭环

PR-AI-CONTROL-CENTER-CONFIGURATION-CLOSURE

所有生成式 AI、AgentLoop、embedding、rerank、media、deterministic helper、delegated child/tool 与 User-defined 行为，都必须拥有明确的 capability-step owner 和适合其执行类型的真实配置；不能继续存在“能保存但运行时不读取”的假设置。

  • 完整删除无生产 caller 的 ai-analysis-title、message-resources、chat-suggest-actions 与 gap-explanation。
  • 把 Hyper Search parser 与 Agent context compact 的 system/user instruction 迁入 Prompt Registry，并补全 analysis.followup 的 user/system 映射。
  • 把 Composer 的 21 个 preset instruction 与 Link Tidy 默认 instruction 纳入各自 action Configuration。
  • 动态汇总 Custom Prompt、Vault Skill、Chat Assistant、Project / Conversation instruction 与 MCP tool policy，不复制第二份 owner state。
  • 按 execution kind 提供 Prompt、model、output、tools、approval、budget、route、scope 或 threshold；schema、安全边界、writeback 与 stop condition 保持只读。
  • 每个 Save 控件必须有 resolver-consumption test，receipt 同时记录 requested 与 effective configuration，并完成真实 Obsidian 修改后下一次 run 的消费验证。

完成条件：0 个无 owner Prompt、0 个稳定 inline instruction 绕过 resolver、0 个无消费证明的可保存配置；旧 promptModelMap 与绕过 PromptService 的兼容路径完成迁移和清理。
