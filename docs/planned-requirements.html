AI Control Center 与 My Content 生产闭环

PR-AI-CONTROL-CENTER-CONFIGURATION-CLOSURE

AI Control Center 只管理真正影响下一次 AI 运行的 owner-backed 配置；My Content 只管理用户明确创建、保存、导出或 materialize 的 Peak 产物。两者都不能暴露“能保存但运行时不读取”的假设置，或把内部运行与存储细节交给用户。

  • 统一 Custom Prompt 的 Handlebars 渲染：禁止 action 内手工变量替换或拼接用户可编辑模板；变量说明来自同一声明。
  • 先建立真正被 query / agent route 消费的 action-policy resolver，再迁移旧 promptModelMap；没有消费者就不显示可保存控件。
  • 内置 prompt 只在所属 AI action 中编辑；移除全局 All prompts、Behavior / Configuration 双 tab、普通用户可见的 run history 与 effective routing。
  • Custom Prompt 与 Chat Assistant 分别提供真实创建/编辑入口；Vault Skill、embedding、确定性 parser/reranker、trace 与内部 background job 不进入普通用户 Control Center。
  • My Content 仅投影 Profile、保存的 AI Search/Graph/Chat 产物、materialized Hub、生成媒体与明确保存的项目文件；提供类型、来源和时间范围筛选。
  • 每个保存项必须有 resolver-consumption test；真实 Obsidian 的 modify-save-next-run/open 验证不能以 Mock 代替。

完成条件：0 个无消费证明的可保存 AI 配置；Custom Prompt 统一经 PromptService/Handlebars 渲染；Control Center 和 My Content 都由真实 registry / owner records 驱动，并通过 focused tests、build 与真实 Obsidian 验证。

Peak Sheet AI 创建与多视图闭环

PR-PEAK-SHEET-VIEW-ADAPTER-SPIKES

先建立共享 DatasetDraft、Dataset、FieldDefinition、ViewDefinition、Compute 与 DatasetPatch 合同，再让 Copilot 生成的 CSV / 扁平 JSON Array 经预览确认创建 Peak Sheet；任何 AI 操作或视图都不能拥有第二份记录状态。

  • Copilot 可以生成 CSV 或扁平 JSON Array；系统将其解析为 DatasetDraft，用户确认字段和数据后创建 revision 1、receipt，并直接打开表格。
  • CSV / JSON Array 只是创建入口，不是 canonical Dataset；创建后的 AI 修改必须走 DatasetPatchPlan、FormulaPlan、FilterPlan、ViewPlan 或 ComputePlan，禁止整表覆盖。
  • Glide Data Grid 只作为表格 viewport 候选；字段、公式、统计、组合筛选 / 排序 / 分组、AI 与持久化继续由 Peak 管理。
  • FullCalendar 只使用免费 MIT Standard 插件验证 range CRUD、drag / resize、sidecar 与失败回滚；禁止 Premium / Scheduler。
  • 看板保持自研，不使用 Atlassian Pragmatic Drag and Drop；显式 Move、键盘路径和 pointer drag 共用同一 DatasetPatch。
  • 现有 Composer Markdown 表格继续保留，不改造成 Dataset grid，也不由 Peak Sheet 替换。
  • 只有 AI 创建闭环、组件 gate、跨视图 revision、focused tests、build 与真实 Obsidian 交互证据全部成立后，才能完成本需求。

状态边界：此登记冻结实施顺序与采用标准，不代表 production runtime 已开始，也不把 Roadmap 中的 Peak Sheet 从 research candidate 自动升级为交付承诺。
