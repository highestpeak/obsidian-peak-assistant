PR-SHARED-AI-INSTRUCTION-COMPOSER

把自然语言指挥 AI 的输入体验提升为独立共享产品能力，与 AI Graph Artifact Platform 平级。Chat Studio、Composer Copilot、AI Graph Update 和后续 AI surface 都消费同一套 shared PromptInput capability，而不是分别实现输入框、附件、引用、draft、history 和提交状态机。

共享范围包括文本、@ / [[ / / context trigger、附件与去重、IME、Enter / Shift+Enter / Escape、focus、draft / history、loading / streaming / error、submit / stop 与 accessibility。各 surface 只提供自动 context、placeholder / chrome slot 和 submit adapter，并持有自己的 runtime 与输出语义。

当前 Chat Studio Composer 与 Composer Copilot sidecar 已共同消费 PromptInput / PromptInputBody / PromptInputAttachments，但完整 platform capability 仍是 implementation pending。验收必须由真实 component import、contract test 与跨 surface behavior test 证明，不能只复制 DOM / CSS 或做视觉仿制。

PR-AI-SEARCH-UNIFIED-MODES

Quick Search modal 顶层只保留 Vault Search 与一个 AI workspace selector，并保持原有左右等分布局。两侧可点击区域必须占满同一顶栏高度，文字严格垂直居中；嵌套在 menu anchor 内的 AI selector 不能贴近顶边。普通打开默认 AI Search；低频的 AI Graph 与 Vault Intelligence 从同一下拉进入，并且不跨 modal 记住低频 mode。恢复中的 run、history record 与 artifact deep link 可以直接恢复对应模式。

移除输入框里重复的 Vault Analysis / AI Graph mode pill和独立 Vault Intelligence 顶栏按钮。三种 AI mode 复用 Shared AI Instruction Composer、history list 与键盘语法；每个 adapter 只改变 placeholder、suggestions、run envelope、history projection 与 detail route。

AI Graph 不再拥有独立 All AI Graphs Library。全部 persisted graphs 在 AI Graph mode 中用一列紧凑 history row 浏览；不显示 Vault / Web / Mixed、Graph type filter rows 或 graph preview card grid。Vault Intelligence 在这里拥有 Vault graph overview、hubs、health 与 recent reviews；它不再转跳旧 Copilot Vault workspace，选择 mode 本身也不自动触发 scan。

键盘接入既有全键盘体系：Tab 在组件间移动；mode menu 使用方向键、Enter / Space 与 Escape；modifier shortcut 只作可发现的加速层，并且不能抢 input、PromptInput 或 IME。

Cross-surface · AI Graphimplemented · interaction QA pending

PR-COMPOSER-AI-GRAPH

AI Graph 升级为独立、持久化、可版本化的知识图谱 artifact，而不是 AI Search 某次运行里附带的一张文件关系图。每张图拥有稳定 graphId、不可变版本、来源、证据和 review 状态；全部 graph 在 AI Search → AI Graph 的紧凑历史列表中浏览，AI Search、Composer / File Atlas、Vault Search 与 Chat 重开的是同一份 graph。

创建来源可见：每个 history row 显示不可变的 creation surface 与主要上下文，例如 Created in File Atlas · AI 编辑器生态调研.md。File Atlas 必须记录稳定 file ref 与当时的可读文件名；AI Search / Vault Search 记录 query，Composer 记录文档 / 选区，Chat Studio 记录 project / conversation。图从别处更新时不覆盖创建来源，更新位置进入 version / run provenance；完整来源在 Graph Detail 中查看和跳转。

节点不仅是 Vault 文件，还支持词汇 / 概念、人物、组织、产品、事件、流程、主张、网页与 custom object。关系保存 predicate、qualifier、evidence、confidence、生成方式和 review 状态；Vault、Web、粘贴文本和已有 Graph 都可作为 source。Web 必须由用户主动开启，snippet 不能单独充当证据，成功验证后自动保存新版本，但不自动改写笔记或 Vault links。

关系方向标记：renderer 必须读取 relation 的 directed 语义，而不是把所有关系画成无方向线。directed relation 在 target 端显示清晰箭头；symmetric relation 不显示箭头。Hierarchy 的 parent → child、Timeline 的 earlier → later 必须始终可辨；Bridges 的纯结构连接保持中性，只有具体有向 predicate 才显示箭头。Inspector 同时以文字显示 source → predicate → target，不能只依赖颜色或箭头形状。

自然语言更新入口：Graph Detail 的主修改动作命名为 Update graph，直接输入“希望这张图如何变化”，自动带入 current graph / head version、当前选中 node 或 relation、已有 sources 与 review context；不要求用户回到首次创建表单重新选择 Graph type。AI 必须先给 added / changed / removed nodes、relations、evidence 与 review status 的 semantic diff，只有用户接受后才创建新的 immutable version。

共享能力依赖：Update graph 是 Shared AI Instruction Composer 的 consumer。AI Graph 只提供 graphId、baseVersion、selection、sources / lens / review context adapter，并把 submit 路由到 semantic diff；输入核心由平级共享能力拥有。

Sources 与 Update 分离：Sources 只管理来源、可用性与 freshness。Add / remove source 或检查到 Web source changed 都不能自动改图、触发 run 或创建版本；用户可明确选择 “Use source changes in Update graph” 再进入更新预览。Graph Detail 不提供语义含混的顶层 Add sources / Refresh 作为更新入口；Create Graph 只负责首次生成。

Composer 只提供当前文档 / 选区 context、入口、preview 与打开 Graph Detail 的 adapter，不另建 agent、runtime 或 store。canonical body 使用 versioned JSON artifact，运行事件使用 JSONL 并只引用 artifact，SQLite 作为可重建 browse / search projection；Markdown 仅用于显式 export。

PR-COMPOSER-GRAPH-EMPTY-FOLDER-COLLAPSE

Folder tree 图谱不要为“本级没有直接可见内容、只是通向下级目录”的中转目录绘制独立边框和大块留白。例如 B-2-创意和想法管理 若本级没有直接文件节点，就不应只为包住下一层目录再画一层框。

目录框只在该层直接拥有当前图谱中的可见内容节点时显示；纯目录链自动折叠，后代节点与它们真正有内容的最近目录组继续正常呈现。折叠只影响布局，不丢失层级信息：完整 Vault path 仍保留在节点详情 / tooltip / 打开文件行为中。搜索、scope 或 filter 导致本级内容不可见时，也按当前可见结果重新判断。

来源：2026-07-28 owner screenshot feedback。下一步：用深层单链、同级多分支、过滤后空目录三类 fixture 做布局 mock。
