T11Z governance rules · truth-source wave

高风险真相源可以碰，但必须按治理规则碰

这份规则回答一个具体问题：Provider/Model catalog、Prompt/Template registry、 SQLite/Chat persistence 这些高风险区域到底能不能做代码瘦身？答案是： 可以，但不能混进 T11Y Surface Grammar Wave 顺手做。 它们需要单独的 truth-source wave：先声明唯一真相源、派生层、兼容层和 golden tests，再改代码。

结论 为什么高风险 通用规则 Provider/Model Prompt/Template Persistence 怎么执行 Claude 约束

1. 结论：不是禁止，是要换一套 wave contract

7,849 本轮抽样高风险核心文件 LOC，不含所有调用者
3 类 模型目录、Prompt/Template、Chat/SQLite/Tag 持久化
先测试 任何格式/默认值/迁移改动都要先加 golden 或 registry tests
可分波 T11Y 做 UI surface；T11Z+ 做 truth-source wave

这些区域能带来真实瘦身，但它们不是“重复 JSX”那种安全重复。 它们掌握的是产品事实：模型默认值、prompt id、template path、用户 prompt override、 chat markdown 格式、SQLite schema、tags_json legacy decode。动它们时，第一目标不是少几行， 而是把 事实源和派生层 重新整理清楚。

2. 为什么不能混进 Surface Wave 顺手做

真相源

JSON、TS registry、SQLite schema、markdown 格式，决定“事实是什么”。

→

派生层

selectors、display descriptors、typed accessors、runtime registry。

→

兼容层

legacy id rewrites、old settings migration、markdown parser、tags_json decode。

→

用户资产

settings、profiles、chat markdown、SQLite rows、tag graph。

如果 Claude 在 UI 瘦身时顺手改这些区域，很容易出现“build 过了，但用户旧数据坏了” 或“测试改了默认值，却没意识到 settings/onboarding/profile 语义漂移”。所以不是不能碰， 是必须单独设 gate。

3. 通用治理规则

规则 含义 停止条件
1. 先声明唯一真相源 每个 wave 必须先写明 source of truth、derived selectors、compatibility layer、runtime consumer。没有这四层，不许实现。 如果两个文件都像“真相源”，但无法证明谁派生谁，停止在 read-only。
2. Readers before writers 先让所有读取路径通过 selector/codec，再改写入路径。不要一上来改数据格式。 如果要同时改 reader 和 writer，且没有 golden fixtures，停止。
3. Golden tests before migration 模型默认值、prompt metadata、markdown parse/build、SQLite row map、tags_json decode 都要先有锁定测试。 没有 test surface 或无法新增 focused tests，停止。
4. 兼容层不能当重复删除 旧 model id rewrite、legacy settings、旧 markdown、legacy tags_json decode 是用户资产保护层，不是普通 dead code。 如果收益来自删除兼容层，必须 owner 明确批准。
5. 不做万能 manifest 真相源收敛不是把所有东西塞一个 JSON。runtime factory、product ranking、UI display、user settings 可以分层。 如果出现 EverythingCatalog / RuntimeBag / 宽泛 descriptor，停止。
6. 不隐藏行为变化 默认模型、PromptId、template path、schema column、markdown heading、tag id 任何变化都要写成 explicit decision。 如果 implementation note 只说“refactor”但实际改默认/格式，拒收。
7. LOC 是副产物 这些波次的主目标是事实源单一、派生清晰、兼容可测；LOC 减少是结果，不是唯一 KPI。 如果为了达到 LOC target 改核心语义，停止。

4. Provider / Model Catalog：可以碰，但要分清四种事实

当前文件 它像什么事实 治理判断
data/model-catalog.json bundled runtime model metadata：provider、model、capabilities、token limits、apiModelId。 可作为默认 bundled catalog；但要承认 TemplateManager JSON 会覆盖它。
templates/config/models/*.json runtime-loaded provider model data，ModelRegistry.loadFromTemplateManager 会 merge/override。 这是可配置/可覆盖层，不应和 bundled catalog 长期手写重复。
templates/config/curator-catalog.json Curator agent ranking/product decision：tier、benchmark、RAM、budget、language strengths。 不能直接并进通用 model catalog；generic metadata 可复用，curator-specific ranking 保留独立。
src/core/profiles/presets.ts profile creation defaults：baseUrl、primaryModel、fastModel、embedding defaults。 可以从 provider descriptor 派生，但默认值变化必须 explicit，不许顺手改。
ProfileRegistry.MODEL_ID_REWRITES 用户旧 settings 的兼容迁移。 不能当重复删；可以搬到 catalog alias/compat module，但必须保持行为。
推荐目标形态： src/core/providers/catalog/ bundled-model-catalog.ts # imports JSON, validates shape provider-model-selectors.ts # display/capability/token selectors model-id-compat.ts # legacy id rewrites + tests profile-preset-selectors.ts # preset defaults derived from descriptors templates/config/models/*.json # runtime override data, still supported templates/config/curator-catalog.json # curator-only ranking/product hints

Provider/Model wave 的硬规则：不许一边“瘦身”一边偷偷改变默认模型。 例如 claude-sonnet-4-6、claude-haiku-4-5、OpenRouter prefix、 Agent SDK 3.x 到 4.x rewrite，都必须由 tests 锁住。

5. Prompt / Template：可以碰，但 PromptId 类型安全不能丢

当前文件 事实角色 允许的瘦身方向
src/core/prompt/PromptId.ts Prompt id enum、prompt groups、configurable lists、PromptVariables 类型。 保留 typed PromptId 和 PromptVariables；可把 group/list/metadata 从 descriptor 派生。
src/core/template/TemplateRegistry.ts TemplateId union、ConfigTemplateId、template path、metadata、label、description、systemPromptId。 可抽 descriptor table 或从 prompt-meta block/manifest 派生；不能丢 path 和 override 关系。
src/service/prompt/PromptService.ts runtime render/override loader；通过 TemplateManager 取内容，支持 vault prompt override。 可以收敛 render/override cache helper；不能绕开 TemplateManager 或破坏 override 文件名。
templates/config/*.json Settings/Onboarding/Chat/Dashboard copy 和 runtime config。 TS fallback 可变薄，但无 TemplateManager 时仍要启动。
推荐目标形态： src/core/prompt/ PromptId.ts # 保留 enum + PromptVariables prompt-descriptors.ts # label/group/configurable/systemPromptId 派生源 prompt-descriptor-selectors.ts src/core/template/ TemplateRegistry.ts # 更薄：TemplateId + path mapping + accessors template-descriptors.ts # metadata table or generated manifest templates/prompts/*.md # 内容仍在文件里 templates/config/*.json # runtime config/copy still supported

Prompt/Template wave 的 stop rule：如果实现方案要求把 PromptId 退化成裸字符串，或要求删掉 vault override 支持，就停止。这不是瘦身，是拆掉地基。

6. SQLite / Chat Persistence：可以碰，但数据格式是用户资产

当前文件 事实角色 治理判断
ChatStore.ts Vault markdown + SQLite conversation/message/resource 双写 orchestration。 可抽双写 helper、meta mapper、resource upsert helper；不能退役 Vault markdown。
ChatConversationDoc.ts 用户可见 markdown conversation 格式 parser/builder/append。 格式变化必须 golden-test；优先抽 section/json/tool-call helper，不改 headings。
ChatConversationRepo / ChatMessageRepo SQLite row schema mapping、upsert、list/count/archive queries。 可抽 row mapper / boolean mapper / JSON codec；不能改 schema 或语义。
UsageLogRepo Usage Dashboard 的时间窗、cost、provider/model 查询。 可抽 date bucket / json_extract helper；Usage Dashboard 功能必须保留。
TagService.ts tags_json encode/decode、legacy arrays、functional/tag/context sanitization。 可抽 tag blob codec；legacy decode 不能删。
推荐目标形态： src/core/storage/codecs/ json-codec.ts markdown-section-doc.ts chat-conversation-codec.ts sqlite-row-codec.ts tag-blob-codec.ts src/core/storage/vault/ChatStore.ts # 变薄：orchestration + IO，不再内嵌所有 mapper/codec src/core/storage/sqlite/repositories/*Repo.ts # 变薄：query ownership + repo semantics，不重复 JSON/boolean/date mapper

Persistence wave 的硬规则：任何 markdown、SQLite、tags_json 的 reader 兼容能力都必须先保留。 旧格式 reader 可以迁到 codec，但不能因为“旧”就删除。

7. 怎么执行：可以分三条 truth-source wave

波次 建议范围 Hard target 必须先有的测试
T11Z-A Provider/Model catalog selectors、profile preset selectors、model id compat module、duplicate defaults cleanup。 事实源清晰 + -0.8k 到 -2k LOC profile-registry.test.ts、新增 model catalog/preset compatibility tests。
T11Z-B Prompt/Template descriptor table、metadata selectors、PromptId group/list derivation、thin TemplateRegistry。 事实源清晰 + -0.8k 到 -2k LOC prompt-meta.test.ts、新增 TemplateRegistry path/systemPrompt/config tests。
T11Z-C Persistence Codec Chat markdown codec、row mappers、json/date/tag codecs、ChatStore thinning。 读写兼容 + -1.5k 到 -4k LOC test/chat-docs/ChatConversationDoc.test.ts、repo tests、tag blob legacy tests。

8. Claude 执行时必须带上的约束

这三类可以交给 Claude 做，但每次只能选一类 truth-source wave。 Prompt 必须要求 Claude 先做 read-only plan：列 source of truth、derived layers、 compatibility readers、tests to add、expected LOC delta。Codex/owner 审过后再实现。

必须报告 拒收信号
source of truth before/after map。 只说“consolidated configs”，但没说明谁是源、谁是派生。
compatibility layer inventory。 把 legacy rewrites、old markdown、旧 settings migration 当 dead code 删除。
golden tests / focused tests 列表。 只跑 build，不跑 profile/prompt/chat/repo/tag focused tests。
explicit behavior changes。 默认模型、prompt id、template path、schema column、markdown heading、tag id 被悄悄改了。
boundary audit 保持 0。 为了瘦身让 UI/app/service/core 重新交叉依赖。
