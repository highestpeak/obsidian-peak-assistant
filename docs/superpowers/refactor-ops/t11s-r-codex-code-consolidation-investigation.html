2. 思维导图：代码瘦身不是“删功能”，而是 7 种不同工作

Peak Assistant 代码瘦身

目标是减少重复实现、旧入口、半接线、全局状态和配置双维护，同时保留产品能力。

1. 直接删除

dead UI、unused exports、旧 shim、无 consumer adapters。

最快1k ~ 3k

2. UI 壳合并

Copilot panel、Settings section、Dashboard card、Chat row。

最大头之一5k ~ 10k

3. 旧路径退休

ContextBuilder fallback、service type shims、compat no-op。

架构收益高1k ~ 3k

4. 半接线补完/隐藏

Usage Dashboard slot、Chat coming-soon、console-only verb。

需要 owner 判断1k ~ 2k

5. service/core 抽象

Search Graph Inspector、retriever、SQLite repo、document loaders。

高收益高风险5k ~ 10k

6. 配置/文案归档

Settings/Onboarding/Dashboard strings、Prompt/Template registry。

可维护性2k ~ 5k

7. 外圈卫生

tests guard 合并、docs/mock 归档、package pruning。

另算5k ~ 15k+

4. 为什么代码这么多？不是一个原因，是五个原因叠加

原因 A：功能线真的多

Chat、Quick Search、Copilot、Usage Dashboard、Index/Search、Vault Lint、Onboarding、Settings、Agent Harness 都是真功能。这里不能用删功能来“瘦身”。

原因 B：每条功能线自己长了一套 UI 壳

Copilot panel、Dashboard card、Settings section、Chat row、Quick Search round block 形态相似，但各自实现。

原因 C：pre-launch 兼容路径没有及时退休

例如 ContextBuilder fallback、service type shims、graph no-op、旧 import surface。

原因 D：配置、文案、registry 有双维护

TS fallback + JSON config + hardcoded table 同时存在，读起来像三套来源。

原因 E：边界重构增加了 adapter/port 脚手架

T11R 把边界清到了 0，这是好事；但有些 adapter/port 如果没有真实 consumer，就要接入或删除。

原因 F：测试和文档在仓库里堆叠

这会影响阅读体验，但不能和产品源码混算；它应该是 repo hygiene，不是产品能力瘦身。

Chat 三栏

Vault X-Ray

默认保留，除非 owner 明确说退役。

SQLite schema

只能在 fixture/snapshot 保护下改。

测试/文档

可以整理，但必须单独汇报，不能冒充产品源码减少。

8. 给 Claude 的口径：不是让它再扫一堆，而是按合同执行

下一份 handoff 应该长这样： 一次性给 Claude 一个大 prompt，但要求它先输出 candidate matrix 和 expected delta；Codex/owner 审过后再实现。 实现时按 DAG 执行所有 safe/medium-safe tracks，不再拆成 G/H/I/J 这种小碎步。
合同项 要求
Primary metric 产品 code LOC 净减少至少 2.5k，目标 4k+；test/docs/package 单独汇报。
Required tracks Deletion-first、Runtime tail、Copilot shell、Stub/half-wired cleanup、Shared UI directory cleanup。
Forbidden scope 不得删除 Usage Dashboard、Chat 三栏、Vault X-Ray、核心搜索/agent 能力；不得引入 god component / god port。
Stop rule 如果达不到 -2.5k 且没有完成 runtime/stub/copy cleanup，就标记 partial，不准包装成 major wave。
Owner review 每轮必须给“改了哪些文件、为什么读这些文件、删除比例、模块影响图、下一阶段分数”。
