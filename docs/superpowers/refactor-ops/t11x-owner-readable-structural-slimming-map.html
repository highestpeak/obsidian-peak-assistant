1. 一页答案：不是删功能，是把重复形态收成“语法层”

约 26k T11X 新增池的现实产品源码减量上限，不能承诺单波全吃
约 62k 乐观上限，包含高风险、生成资产、测试-only 和依赖治理
0 当前 boundary audit 目标值要继续守住，不能为了瘦身打破边界
6 个 真正应该按模块理解的收敛战场，而不是 L-BA 字母清单

现在的问题

  • 很多屏幕都在手写同一种 card、row、header、empty state、status pill、action footer。
  • 文件类型、provider/model、prompt/template、settings descriptor 在多个地方重复登记。
  • T11O/T11R 后边界变干净了，但 app 层留下了大量合法但重复的 shell、adapter、compose 样板。
  • Chat、Quick Search、Usage、Copilot 都是活功能，所以不能用“删屏幕”换行数。

改完应该长这样

  • UI 页面只写业务差异，重复的 screen grammar 由共享 primitives 承担。
  • 文件类型、模型目录、prompt/template metadata 有明确 source of truth 和 typed accessor。
  • app 层仍然是 weave 点，但 modal/view/adapter 样板被小 helper 收敛。
  • 功能入口不减少：Usage Dashboard、Chat 三栏、Quick Search、Copilot、Settings、Onboarding 都保留。

这份可读版的判断是：下一轮不要再做“小文件删除型瘦身”。真正有用的是 Surface Grammar Wave 加 Catalog/Taxonomy Wave 加 App Weave Boilerplate Wave。先抽共同形态，再批量迁移 callers，最后删除旧局部实现。

2. 逻辑地图：从“哪里胖”到“怎么瘦”

代码为什么还有 11 万行级别？ 主要不是一个功能太大，而是同一种形态在多个产品面重复出现。 所以下一阶段目标不是删产品，而是把重复形态变成可复用语法。
UI Surface Grammar

Copilot、Quick Search、Usage、Chat、Settings 都重复写 row/card/panel/status。

Catalog / Taxonomy

文件类型、provider/model、prompt/template、settings copy 多源重复。

App Shell / Adapter

边界清零后，app 层合法承担 weave，但 shell/compose/adapter 有机械重复。

Runtime Ceremony

agent、tool、MCP、command、notice、generation 都有 run/wrap/result 样板。

Data / Persistence Codec

SQLite row map、Markdown/JSON section、tag blob、chat double-write 可收窄 helper。

Repo / Dependency Hygiene

包体积、worktrees、generated assets 影响“笨重感”，但不算产品源码 LOC。

4. 六大战场：你应该按这六块理解，不要按 L-BA 字母读

战场 要改哪里 改法 现实收益 风险级别
A. UI Surface Grammar Copilot、Quick Search、Usage Dashboard、Chat、Settings、Onboarding、Project/Conversation lists 建立 5-8 个真实 primitives：SurfacePanel、SurfaceList、SurfaceRow、StatusPill、ActionFooter、ReportHero、KpiGrid、EmptyState。 -8k 到 -15k 中 需要视觉 smoke，但功能风险可控。
B. Catalog / Taxonomy file kind、attachment display、provider/model catalog、PromptId、TemplateRegistry、settings strings 建立 typed source-of-truth 和 selectors；UI/loader/settings 从 selector 派生，不再各自手写映射。 -3k 到 -7k 高 涉及配置、模型默认值、loader 支持矩阵。
C. App Weave Boilerplate app view/modal shell、ReactRenderer mount/unmount、compose*、thin adapters、AppRuntimeRegistry、DevToolsBridge 保留 app 层所有入口和 named API，抽 app-owned shell/helper，不回退到 service singleton。 -1.5k 到 -4k 中 Obsidian lifecycle 要验。
D. Runtime / Tool Ceremony Copilot action registry、MCP tool wrapper、agent run ceremony、ReportOrchestrator、command notice 抽 action recipe factory、tool result wrapper、small run helper、withProgressNotice；不合并业务语义。 -3k 到 -7k 中高 必须守住现有 action/tool id 和输出格式。
E. Data / Persistence Codec SQLite repo row map、Usage date SQL、ChatStore 双写、Markdown/JSON section、Tag blob 抽 codec、row mapper、date bucket、JSON fence、tag blob parser；不改历史数据格式。 -2k 到 -5k 高 需要 golden tests 和 repo tests。
F. Package / Repo Hygiene recharts、ai-elements、mermaid、playwright、lucide/motion、.claude/worktrees、docs/gstack、generated CSS 作为 side track 做包体积和本地磁盘治理，不拿来冒充产品 LOC 瘦身。 0 到 -0.5k LOC 低中 对源码少，对安装体积/目录感受大。

最稳的大波次顺序是：先 A，再 C+D 的安全子集，再 B/E 的高风险子集。 这样每一步都能真实减少代码，同时不会把 Usage Dashboard、Chat 三栏、Quick Search 或 Copilot 误删。

5. 改之后代码应该长什么样

src/ui/components/surface/ SurfacePanel.tsx SurfaceList.tsx SurfaceRow.tsx StatusPill.tsx ActionFooter.tsx EmptyState.tsx ReportHero.tsx KpiGrid.tsx src/ui/components/primitives/ Button.tsx IconButton.tsx Row.tsx FormRow.tsx Pill.tsx ... src/core/catalog/ file-kind-catalog.ts provider-model-catalog.ts prompt-template-descriptors.ts src/app/shell/ ReactItemViewShell.ts ReactModalShell.ts mountReactWithServices.ts src/app/compose/ forwarding-adapter.ts runtime-slot.ts notice-command-helpers.ts src/core/storage/codecs/ json-fence.ts markdown-section-doc.ts tag-blob-codec.ts row-map-helpers.ts

目录修正： 不新增 src/ui/primitives 第三套 UI 根目录。 当前已有 src/ui/components/primitives，新的 surface grammar 应该放在 src/ui/components/surface：它和 primitives 平级， 表示比 Button/Row 这类 primitive 高一层的跨 screen 组合语法。旧 src/ui/component 里的可复用件要逐步迁移或退役，避免 component / components 两套根长期并存。

现在 改后 你读代码时会更容易在哪里
每个 screen 自己写 card/header/row/status/footer。 screen 只选择业务数据和 action；视觉结构由 surface primitives 提供。 读一个新 screen 时不用重新理解布局语法，只看数据和行为。
文件类型在 loader、Chat 附件、PromptInput、KnowledgeIndex 各处判断。 FileKindCatalog 提供 extension、kind、label、icon、color、preview ability。 新增一种文件类型时知道只从 catalog 和必要 loader 入手。
每个 Modal/ItemView 重复 ReactRenderer mount/unmount。 app shell helper 承担生命周期；具体 view/modal 只声明 type、title、component、props。 Obsidian weave 更显式，不再被样板淹没。
Copilot action 和 MCP tool 到处重复 schema/result/run wrapper。 recipe factory 生成固定 ceremony；复杂 action 保留手写。 28 个 action 的差异会更突出，review 时更容易找行为变化。
Markdown/JSON/SQLite row map 各自 safe parse、upsert、date bucket。 codec/helper 统一低层 ceremony，业务 repo 保留实体语义。 数据兼容风险集中在 codec tests，不散在几十个 repo 方法里。

8. 护栏：这些不能为了减少行数牺牲

护栏 为什么 执行时怎么检查
不删 Usage Dashboard 用户明确要保留；瘦身只能来自 screen grammar 和 data helper。 Usage Dashboard view、palette/setting entry、核心 screens 仍存在。
不删 Chat 三栏 三栏是产品必要形态，不是重复入口。 ChatView、ProjectListView、ConversationOutlineView 注册与打开行为保持。
不破坏 boundary 0 T11R 的核心成果是 service/core 不再碰 Obsidian，UI 不再 import app。 npm run audit:boundary 继续 0 flagged。
不创建 god-port / runtime bag 这会把刚清掉的隐式依赖换个名字带回来。 新增 port/helper 必须窄命名、窄职责、有真实 consumer。
不改历史数据格式 Chat markdown、SQLite、tags_json 是用户资产。 先 golden tests，再动 codec；没有测试只能调查。
不把高风险池塞进低风险波次 Search/index、model catalog、prompt/template、native sqlite 会造成隐性回归。 Wave 3 必须独立 owner review，不用来凑 Wave 1 数字。

9. 新代码依赖治理：瘦身不能把旧边界问题带回来

新代码位置 允许依赖 禁止依赖 原因
src/ui/components/surface/* React、Lucide、@/ui/components/primitives、纯展示 utils、type-only domain shapes。 @/app/**、@/service/**、obsidian、AppContext、Zustand store 写入、new Notice。 surface 组件只能是展示语法。数据读取、命令执行、vault/editor 操作都留在 view hook 或 app port。
src/core/catalog/* 纯数据、纯函数、core types、JSON-derived descriptors。 React、UI components、app/service、Obsidian types、runtime singleton、TemplateManager 实例。 catalog 是事实源，不是运行时装配点；它必须能被 service/ui/app 安全读取。
src/app/shell/* Obsidian API、ReactRenderer、ServiceProvider、app-owned ports。 把 shell helper 下放到 UI；把 service runtime singleton 或 mutable global 放回来。 Obsidian Modal/ItemView 生命周期属于 app weave，不能重新污染 UI 层。
src/app/compose/* AppContext、app adapters、port implementation、runtime binding。 EverythingPort、RuntimeBag、把 raw app/plugin 透传给 UI/service。 compose 是集成点，但必须窄端口、命名清楚、依赖显式。
src/core/storage/codecs/* 纯 parser/serializer、schema、golden-testable helpers。 SQLite connection、vault IO、Notice、UI state、AppContext。 codec 可以被 repo 和 tests 复用，但不能隐藏真实 IO。
