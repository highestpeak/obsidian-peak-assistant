T11X-F 深扫：远古路径、伪活代码与重复表面瘦身地图

这份报告回答一个具体问题：为什么前几轮看起来只能减几百行，但直觉上项目里还有大量旧代码？ 结论是：全文件静态死代码确实很少，真正的水分主要藏在“被 barrel export 假激活的组件”“入口状态不可达的旧 agent” “无人生产数据的 UI 状态”“debug/test globals”“重复 presentation grammar”里。

范围：read-only code review 不改产品代码 保留 Usage Dashboard / Chat 三栏 / Quick Search / Copilot 边界治理不得回退
核心结论 为什么之前少 删除地图 证据池 深扫新增 公共入口 半成品面 执行波次 代码阅读顺序 不要误删

1. 核心结论

71 LOC
全文件静态不可达。这里确实很少，不是主要战场。
1,399 行
jscpd 发现的字面重复行。集中在少数模块，不是随机噪音。
4.4k-7.2k
更新后的可信功能保留型净削减池。主要来自“合并重复结构”和“收掉过渡面”，不是删功能。
+1.5k-2.6k
需要产品/owner 决策的额外空间：隐藏 DocSimple、stub 诊断面、dev globals、Knowledge Intuition 重写等。
判断：你说“肯定不止这么一点”是对的，但不是因为有几千行全文件 0 import。 真正要做的是从 file-level dead code 转向 symbol-level + entry-state + ghost-state + old-surface 审计。

2. 为什么之前看起来只能删很少

静态 import 图

从 main.ts 追到 src/**，大部分文件都能被 import 到。

→
假活性

barrel export、legacy shim、factory fallback 会让旧代码“看起来还活着”。

→
真正瘦身点

要看真实 UI 入口、store producer、mode enum、prompt registry、runtime factory。

扫描层级能发现什么这次结论
全文件 import reachability 完全没人 import 的文件 只有 4 个文件 / 71 LOC；不是主要空间。
export / barrel 层 只被 index.ts 挂着、没有真实消费者的 symbol PromptInput 旧子组件、harness barrel、若干 helper export。
入口状态层 有 factory、有 fallback，但 UI mode 永远不会走到 DocSimpleAgent 是最典型例子。
store producer 层 组件会渲染，但没有任何地方写入数据 FileChangesList / fileChanges 状态疑似幽灵。
表面语法层 功能活着，但 screen/card/KPI/row grammar 重复 Usage Dashboard、Vault Review、Quick Search 可以收敛，但不是“删功能”。

4. 关键证据与判断

DocSimpleAgent 为什么可疑

  • src/service/agents/DocSimpleAgent.ts:79 要求 scopeValue。
  • src/ui/view/quick-search/SearchModal.tsx:114 正常 Analyze 传 undefined。
  • SearchModal.tsx:75-78 mode label 只有 vaultFull / aiGraph。
  • useSearchSession.ts:233-285 只有不是 vault/graph 才 fallback 到 DocSimple，但没有 visible mode 能稳定进入。

PromptInput 为什么是低风险

  • PromptInputSubmit / PromptInputFileButton / PromptInputSearchButton / ToolButton / TokenUsage 只被 barrel export。
  • 真实 Composer 使用的是 PromptInput、PromptInputBody、PromptInputAttachments、usePromptInputContext。
  • SuggestionTags 组件未用，只有 SuggestionTag 类型被 store 牵住。

Chat 幽灵状态为什么要谨慎

  • FileChangesList 会被 view-Messages.tsx 渲染，但没有发现 setFileChanges(...) producer。
  • useChatSession 没人调用，但里面负责把 conversation meta 同步到 UI store。
  • 这说明旧路径可能已经断挂，也可能是一个潜在 bug。正确做法是先迁移副作用，再删文件。

哪些不是死代码

  • Usage Dashboard 的 chart components 多数经 components/charts/index.ts barrel 使用，不能用入边少误删。
  • KnowledgeIntuitionAgent 仍由 command / Maintenance / dev tools 入口使用，不能静默删除。
  • ai-elements/reasoning.tsx 被 message rendering 使用，不是死组件。
  • StreamdownIsolated / wikilink hover / multi-lens graph 仍是活 UI 能力。

现在能确认：项目里不是没有空间，而是空间已经从“删掉一个巨大死文件” 变成“把十几个活系统里的重复壳抽掉”。这类瘦身单次不能承诺 -8k， 但可以通过 2 到 3 个结构波次稳定拿到几千行，并且让代码更可读。
