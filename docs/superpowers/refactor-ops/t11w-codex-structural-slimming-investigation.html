5. 推荐执行组合

主执行包：A + B + C + F + G + H/I

这是下一次真正应该给 Claude 的大包：Copilot panels、Quick Search V2、Usage Dashboard、SQLite repo helpers，再加 Copilot Vault Review 和 Settings/Onboarding 或 Chat grammar 至少一个第二圈池。

现实预估：-7k 到 -11k。
乐观预估：-12k 到 -15k。

如果要达成 -8k hard floor，必须不是“新增 helper 后保留旧 body”，而是让 helper 真正替换掉重复 body。否则又会变成 partial。

跟随包：J + K

Search Graph Inspector / Index output helpers、Shared UI root 整理适合作为跟随 track。它们能改善结构，但不应该为了 LOC 强拆算法或强行统一视觉系统。

规则很简单：J 必须净减少；K 必须跟随真实迁移，不做只有路径变化的目录体操。

不要把所有“大文件”都当成可删代码

indexService.ts、ddl.ts 这类文件很大，但大不等于重复。这里很多是 indexing、PageRank、semantic edge、Kysely type contract。 如果纯拆文件，最可能发生的是文件变多、LOC 变多、风险变高。下一波只接受“重复 body 被 helper 替换”的净减少。

7. 修正后的 T11W 接受标准

我建议 T11W 仍然保留 -8k hard floor，同时增加 -12k stretch。 这不是为了好看，而是为了逼实现真正替换重复 body，而不是只加 helper。

  • -12k 以上：接受为 T11W stretch wave，说明主池和第二圈至少吃掉了 5 个以上真实重复池。
  • -8k 到 -12k：接受为 T11W major wave。
  • -5k 到 -8k：只能接受为 structural progress，不算 major wave 完整达成；必须写清楚哪些池子没有推进。
  • -5k 以下：说明没有吃到主重复池，不能再包装成大波次。
