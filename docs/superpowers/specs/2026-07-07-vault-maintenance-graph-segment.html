当前 surface 决定

Vault graph overview 不再由 CopilotPickerContent 或旧 Vault tab 挂载。它由 Search Modal 的 VaultIntelligenceWorkspace 读取现有 Vault review runtime；进入 mode 只读取 projection，只有明确点击 Quick / Complete review 才启动运行。

下方线框是历史布局参考
其中的三栏 Copilot tab chrome 已失效；review 时以 AI Search 统一入口 Mock 为准。

为什么要有这个 segment

Obsidian 自带 graph 展示的是太细的文档级网络。Vault Intelligence 更需要先给用户一个能扫读的 Vault 结构图：哪些 hub 是主干，当前文档在哪个社区里，最近一次 review 看到什么，以及下一步该看 report 还是重新分析。

  • 用户不应该为了理解 Vault 状态，逐个展开每篇文档的小节点。
  • Vault 相关操作不要散成独立命令；它们应该聚在 Copilot 的 Vault tab。
  • graph 不是装饰，它是进入 hubs、report 和 review intent 的导航面板。
当前边界
这份文档只定义 segment 的信息架构和低保真线框。三栏 compare panel、最终视觉样式、交互动效和完整组件实现不在这里定稿。

这个 segment 需要收拢什么

区域用户要知道什么入口动作
Vault stats Vault 当前规模、最近 review 时间、是否已有 cached report。 决定是直接看 report，还是重新 research。
Overview graph 主 hubs、当前文档位置、社区边界、桥接缺口。 查看 all hubs，或定位 current note。
Hubs 哪些 hub 已存在、哪些过期、哪些需要桥接或更新综述。 打开 hub、生成 / 更新 hub、复核 stale hub。
Last report 最近一次 Vault review 结论、变化量、建议 intent。 View last report，继续 ask AI，或重新跑 Research。

心智模型

1. 先看 Vault 状态规模、last reviewed、changed notes 和 cached report 告诉用户是否需要重跑。
2. 再看结构图圆形 graph 先展示 hubs 和当前文档位置，避免文档级 graph 噪声。
3. 进入具体 hub用户可以看所有 hubs，也可以从当前文档跳到所属 hub。
4. 回到 reportlast report 保留 review 结果，Research 是重新生成，不是唯一入口。
不要做成什么
不要把 graph、hub generation、last report、Vault review 拆成四个分散命令。它们都属于 Copilot Vault tab 的 Vault Maintenance segment，区别只是用户此刻要看结构、看报告，还是生成综述。

后续需要重新设计的问题

  • 三栏 compare panel 最终怎么组织，还需要单独设计。
  • graph 的节点密度、缩放、hover detail、current note 定位需要交互原型验证。
  • last report 和 Research 的优先级要根据实际使用频率调整。
  • hub list 是否按健康度、最近变化、PageRank 或用户 pin 排序，需要结合真实数据再定。
相邻需求
Document tab 的 current-note local graph 和 Search drawer 的 hub context 不在这份 Vault segment 草图里展开；两项旧方案及其当前 File Atlas 归属见 Contextual Hub Local Graph Surfaces。
