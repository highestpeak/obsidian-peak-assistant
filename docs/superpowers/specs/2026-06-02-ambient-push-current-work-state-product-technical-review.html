Ambient Push 应该从 Related Notes 升级为 Current Work State

本文单独整理 Ambient Push 的产品需求、现有技术实现、已沉淀需求文档和下一轮重构方向。 它与主架构手册互相引用，但不把 Ambient 的细节塞进系统总览里。 实施顺序上，Ambient Push 应该等待主架构中的 Capability + RunSession + Backend + Ports 地基完成后再进入实现。

Backlink: Peak 系统架构理解手册 · 能力全景

Core judgment

Ambient Push 的核心不是“推相关笔记”，而是“在写作现场指出下一步缺口”。

旧实现已经能在写作暂停、切换文档或手动刷新时推送相关 notes，并记录反馈。 但产品语义仍停在 Related Notes，用户会觉得它只是另一个推荐侧栏。 目标形态应该是：当前段落旁边出现一个小提示，说明这段缺什么；右侧 Current Work State 解释系统现在以为什么作为上下文，并允许用户展开最近工作轨迹、纠正判断和启动深度检查。 这不是沿着旧 AmbientPushService 继续加功能，而是新架构完成后的 Ambient capability 落地。

1. 产品定义：Ambient 是“写作下一步提示”，不是“相关推荐侧栏”

用户写作时最大的痛点不是“有没有更多相关 note”，而是“不知道自己当前这段还缺哪一步，也不知道 vault 里是否已有能支撑这一步的材料”。 所以 Ambient 的第一屏必须围绕当前段落，而不是围绕推荐列表。

产品判断： Related Notes 是现有实现形态，不应该继续作为产品主语。 新主语应该是 Current Work State 和 Open Writing Moves： 系统先说自己以为用户在做什么，再指出当前段落可推进的下一步。
新增判断： Ambient 还应该整理本次 writing session 里散落的想法，但不要把它做成 todo list。 用户在多个文件里写下的临时段落、反方观点、补证据念头和“还不知道放哪”的句子，应该被组织成 Session Thought Trace：它帮助用户安放思考，而不是替用户思考。

User question “你为什么现在提醒我？”

答案不能是三类信号名，而要能展开为 recent files、repeated themes、recent actions。

User question “我点了会发生什么？”

动作必须 preview-first：不会直接写入正文，先给比较段、证据列表或缺口报告。

User question “它是不是理解错我了？”

右侧必须允许用户纠正 focus，例如 Architecture、Monetization、Not this。

User question “什么时候该跑 Agent？”

Deep check 不是实时推荐；它读当前 section、recent notes、nearby sources，返回 gaps、counterarguments、outline。

User question “我刚才那些散落想法去哪了？”

Ambient 应该能把本次 session 里的 loose thoughts 聚成主题，并建议它们可能属于哪一节，但不能把它们粗暴变成 todo。

User question “我应该继续怎么写？”

系统不替用户决定结论，而是给可撤销的下一步：放进 outline、生成 bridge paragraph、找证据、park for later。

3. 目标体验：Current Work State + Session Thought Trace + Paragraph Prompt

目标界面不应该要求用户理解内部信号名。用户看到的是：系统现在以为什么作为上下文、为什么这么判断、当前段落缺哪一步、 本次 session 里有哪些散落想法还没有安放，以及点一下能安全地得到什么。

Editor marker 1 missing move / 2 loose thoughts

放在当前段落旁边。它不应该是问号；它表示“这里有一个可行动缺口”或“有散落想法可能属于这里”。

Paragraph popover 当前段落缺什么

第一句直接说缺口或可安放的想法：例如“需要补反方比较”或“这两个 loose thoughts 可能属于这里”。动作必须 preview-first。

Right leaf Current Work State

右侧不是 Thread 或 Reminders，而是系统当前上下文判断。它让用户确认或纠正系统正在用什么 state 做推断。

Trace drawer Recent Work Trace + Session Thought Trace

Recent Work Trace 解释系统判断依据；Session Thought Trace 整理散落想法和可能归属，不把它变成 todo list。

Default collapsed 为什么不能一上来铺满日志

Ambient 不能变成 activity log 面板。默认只展示“recent files · 4 / themes · 5 / actions · 7”，用户怀疑时再展开。

Expanded audit 展开后看什么

最近打开/编辑的文件、反复出现的主题、搜索和 Copilot 动作。它们证明“系统为什么以为我在做 X”。

Thought trace 散落想法不是 todo

它们是用户 session 中尚未安放的思考残留：反方观点、补证据念头、桥接段落、临时句子。Ambient 只建议归属和下一步。

User agency 帮助捋清，不替代思考

系统可以建议“放进 Differentiation section”或“park for later”，但不能自动把想法定性成任务，也不能静默改正文。

4. 技术架构：把 note push 拆成 Work State、Thought Trace、Writing Move、Evidence Source

当前 AmbientPushItem 适合表示 note suggestion，但不适合表示“当前段落缺哪一步”。 目标架构应引入四个层次：当前工作状态、session 思考痕迹、写作动作、证据来源。这样 UI 才不会被 note card 形状绑住。

实施边界： 下面的数据层次是新架构里的 Ambient capability domain，不是要求在旧 AmbientPushService 里继续塞字段。 旧 trigger/search/store 可以迁移为 adapter；新的能力入口应由 Capability Contract 声明，由 Run Envelope 承接动作，由 Ports 读取 vault/search/provider，由 Artifact Store 保存 preview。

4.1 触发策略：不要让实时 agent 成为成本黑洞

触发默认动作是否调用模型用户感受
写作暂停 3-5 秒 + 文本变化 cheap layer 计算 paragraph-level candidate。 默认不调用。 只出现小 marker，不弹 modal。
当前工作状态变化 更新右侧 Current Work State 和 Recent Work Trace。 达到活动阈值后 debounce 推断。 用户能看到系统理解的上下文。
同一 session 内多处编辑同一主题 归纳 Session Thought Trace 和 Unplaced Ideas。 可先规则聚类，必要时低频调用模型。 用户看到“这些想法可能属于哪一节”，不是 todo list。
用户点 Preview comparison 生成短 preview artifact。 可以调用便宜模型。 先预览，不写入正文。
用户点 Deep check / 长停顿后确认 Agent 读 section + recent notes + nearby sources。 调用模型，但有明确 scope 和成本策略。 得到 gaps、counterarguments、insertable outline。
Obsidian 启动 Morning Briefing 维护型提醒。 默认数据查询，不混入当前段落模式。 这是 session-start，不是 writing-time prompt。

5. 产品需求：每一个动作都必须有明确用户意图

这部分不是 UI 文案清单，而是交互合同。后续代码实现应围绕这些动作写测试：触发什么、展示什么、是否写入 vault、如何记录反馈。

用户看到的动作用户意图系统执行写入策略
Preview comparison 我想看看这段反方比较怎么写。 基于当前段落、work state 和 evidence sources 生成短段落。 不自动写入；确认后插入。
Find supporting notes 我不想 AI 写，只想找能支撑这段的材料。 返回 note list，但每条必须带 reason 和可打开来源。 可插 link；用户确认。
Check section gaps 我想知道这一节还缺什么。 读取当前 section、recent notes、nearby sources，生成 gap report。 生成 artifact，不直接改正文。
Place in outline 我想知道这些 loose thoughts 应该放到文章哪一节。 把 unplaced ideas 映射到现有 headings，输出 placement preview。 只展示建议位置；确认后才移动或插入。
Draft a bridge paragraph 这些散落想法之间有关系，但我还没写出连接段。 基于 thought cluster 生成一段 bridge paragraph preview。 预览优先；用户确认后插入当前段落附近。
Park for later 这个想法现在不适合写进正文，但我不想丢。 把 idea 放进 session parking area 或稍后提醒列表。 不污染当前文档；可写入用户确认的 scratch / inbox 区。
Not what I mean 系统理解错当前工作状态。 记录 negative feedback，展示 focus correction。 只更新 state/feedback，不改 vault。
Focus correction 我不是在写产品价值，我是在写架构或商业化。 覆盖当前 work state focus，并影响后续提醒。 保存 session override，可选持久化 preference。
反目标： 不做实时大模型持续扫描；不把 Morning Briefing 塞进当前段落旁边；不把右侧做成所有 related notes 的大列表； 不让系统静默写入正文；不要求用户理解 trust、lens、evidence stack、thread 这些内部词。

6. 任务拆分：先把产品语义改对，再扩算法能力

这不是按周排期，而是按依赖拆任务。第一批任务的目标是让 UI mental model 站住；算法增强要服务 writing move，而不是继续堆更多 note candidate。 但这些任务必须排在主架构地基之后：先有 Capability Contract、Run Envelope、Ports 和 Artifact Store，再实现 Ambient 的具体 capability。

7. 测试策略：Ambient 必须测“少打扰”和“可解释”，不只测函数返回

Ambient 的风险不只是 bug，而是误触发、乱打扰、文案不明、成本失控和误写正文。 测试要覆盖 trigger、state inference、popover contract、feedback 和 deep check boundary。

Unit paragraph extraction、outlink dedup、trace aggregation、theme inference fallback。 用 fixture lines 测 marker 是否只在非空段落出现。
Contract WritingMove 是否有 headline、whyNow、safeActions、evidence source。 空 evidence 不能生成 “Find supporting notes” 结果；必须提示 no source。
Thought trace SessionThoughtTrace 是否只归纳 loose thoughts、unplaced ideas 和 suggested destination，不生成任务清单。 fixture 中含有临时想法和 TODO 文本时，系统能区分“待安放想法”和“真实任务”。
Store feedback、dismiss、focus override、recent trace 展开状态。 点 Not this 后下一次同段落不应立刻重复同一 move。
Integration writing pause → marker → popover → preview artifact。 fake vault + fake search + fake provider，确保不写入正文。
Manual QA Obsidian editor scroll、切文件、阅读模式、右侧 leaf 宽度、移动端。 marker 不遮挡正文，popover 不被右侧面板截断。
Cost guard 实时层不调用模型，deep check 有明确触发和 scope。 模拟 10 分钟写作，LLM 调用次数符合上限。
验收判断： 用户看到 Ambient 时，应该能在 5 秒内说出三件事： 系统以为我在做什么、这一段缺什么、点按钮会发生什么。 如果还需要解释 Thread、Lens、Trust、Evidence Stack 这些词，说明产品语义还没改对。
