## 3. 六个月时间线（阶段叙事）

### 阶段 0：Ideation（2026-03，9 个 Codex 会话）

在 vault 根目录反复问同一个问题："我的独立开发产品 idea 的综合评价 给我快速致富路 给我符合我的现状的方案"。此时插件仓库只有 13 个 commit。**这个项目是从"独立开发变现"的动机出发的**——这解释了后面所有"要上线、要 smooth、要能给新读者一句话讲清"的诉求。

### 阶段 1：猛建期（2026-04）

- 交互形态：**极少消息、超长任务**。4 月总共 5 条真实输入，其中一条是完整的《Refactoring Plan: Peak Assistant Multi-Module Overhaul》工作包，其余是"继续吧"×N。
- 工具分工：git co-author 显示 4 月有 221 个 commit 由 Claude Opus 4.6 署名、67 个 Sonnet 4.6——**4 月的主力是 Claude Code**，Codex 只开了 6 个会话。
- 产出：346 commits，fix 率 25%（六个月最高）。
- 特征口头禅："继续"首次出现（04-11），从此贯穿至 08-05，共出现在 17 个不同的日子。

### 阶段 2：功能爆发 + 第一波 QA 风暴（2026-05）

- 5 月 500 commits 是全年产出之最；progress.md 的 Phase A→Z 大部分诞生于此。
- 交互形态改变：Codex 会话跳到 44 个，你开始**贴截图报 bug**："两个叉号"、"这里都没边框了"、"为什么一打开就开始 indexing 这不对吧？"——短平快、一图一诉求。
- 同时出现第一批**架构反思型会话**："给我整个仓库代码的设计报告……因为我用ai写了太多代码，我决定要好好review一下"（05-28）。
- 设计规范意识萌芽："先不要写代码仅仅设计，写完了存在 docs/superpowers/specs/"（onboarding 重设计，05-29）。
- 特征词：这个月"仔细/深入"密度 12%、"review/审"13%，都是高位。

### 阶段 3：大重构 + Review 模式 + 支线（2026-06）

- commit 构成翻转：feat 只剩 19，refactor 78 + docs 67——**从造功能转向治理代码**。大重构分支 `codex/peak-modernization-refactor` 于 06-12 创建。
- 发明了一种新交互模式（06-28 起多次复用）："我们接下来就是**我review代码，然后告诉你我的想法，但你不要改代码**，等我说改你再改"——人读代码、AI 当讲解员。全年最忙的一天就是 06-28（125 条消息），全部花在这种代码走读上。
- 支线任务：面试准备（story card 文档、知识点抽取）占了 06-01 和 06-08 两周的多个会话——**同一工具池同时服务两个人生项目**。
- "你现在将作为真正大重构的引导形决策助手……我决定先把现在项目里的内容批量 commit 一下"（06-10 与 06-22 各出现一次）——大批量补 commit 的习惯在这时已成形。

### 阶段 4：双工具峰值与派单模式成熟（2026-07）

数据上最密集的一个月：507 条消息、288 次截图粘贴、97 条浏览器批注（全年 101 条几乎都在 7 月）、193 个 Codex 会话。

- **Claude Code 回归并明确分工**（现存转录从 07-09 开始）：Claude 负责 commit 管家（"先帮我把目录里的内容提交一下吧"）、模型编排（"实现是opus做的，设计流程审计流程是fable去做"，07-25）、过夜托管（"你不要停 一直干到结束，因为我要去睡觉了"，07-15；"好了你自己去执行吧……我要去睡觉了 不要问我了"，07-27）、工作流元分析（07-28 的效率诊断，即本报告姊妹篇）。
- **Codex 负责 UI 实现循环**：mock（"你设计一套ui给看看呢 画出mock来"，出现在 5 个不同日子）→ 开工令（"好了 你开始做吧"，4 天内真实出现 36 次）→ 截图验收（"截个图看看"/"每个方案都截图一下吧"）→ 不满意（"还是很不喜欢……"，4 天）→ 循环。
- **派单/handoff 实践自发成型**：你让 AI 生成可直接贴到新会话的 handoff（"下面这份可以直接贴到新会话里当 handoff"，07-22）；Composer 侧栏设计有一段固定的"新会话开机咒语"（"我们要继续 Peak Composer editing view 的设计，但只聚焦 Intelligence 侧栏，**不再在旧大对话里继续迭代**"）在 7 天里反复使用——你自己发明了"上下文重置 + 聚焦单task"的实践。
- **07-27 假 PASS 事件周**：当天出现 13 连 fork 风暴、"还是差距很多啊 你得生成一个文档和我们的设计稿一样"、"你要在这个项目的 agent.md 记下来，关于obsidian debug和computer use的技巧……否则每次我们都花大时间和精力"，以及第一个**独立视觉裁判 prompt**："You are an independent visual QA reviewer. Read-only"——踩坑当天你已经摸到了正确解法（运动员-裁判分离）。
- **工具痛点被反复说出**："好慢啊 每次都去截图嘛 这太慢了"出现在 6 个不同的日子——computer-use 截图循环是 7 月最大的时间黑洞之一。
- 07-28 出现"单独开 worktree 去实现"、"启用subagent……你去规划谋划审计"——隔离与分工意识落地。

### 阶段 5：录屏 QA 与收敛上线（2026-08）

- **新 QA 形态：录屏驱动**。你录了至少 30 个 iShot mp4，逐个丢给 AI："仔细看这个视频依然有很多问题啊……"（08-04 到 08-06 密集）。相比截图，一段视频报 5-8 个交互问题，信息密度高得多——这是你自己迭代出来的高效 bug 报告方式。
- **克制语气达到峰值**：8 月"不要/别"密度 31%（全年最高）、"别写代码/先不要改"16%（7 月才 2%）、"仔细/深入"17%、"调研/分析"11%——**你明显转向了"先想清楚再动手"的驱动方式**。
- 代码治理："你仔细review一下整个项目的代码……都二十万行了……真的需要这么多吗"（08-06）。
- 收口动作（08-10，今天）："我们把现在代码都合并到master里吧，直接rebase合并"——**390-commit 的大重构分支已并回 master**（现在分支只剩 14 个新 commit）；"上线前我需要自己在单独知识库批量全部使用一遍……readme仔细写"。
- 工具使用：Claude 本月几乎归零（1 条消息），226 个 commit 全部没有 Claude 署名——8 月是纯 Codex 月。

## 8. 你自己发明的、值得固化的实践

数据里能看到一批**你自发迭代出来的高杠杆行为**（多数没有写进任何规则文件）：

2. **Handoff 移交文书**（07-22 起）：让 AI 产出"可直接贴到新会话"的交接文档、HANDOFF.md。
3. **录屏 QA**（08 月）：一个 mp4 顶十张截图，一次报出一组交互 bug。是目前你所有 QA 方式里"单位人力信息量"最高的。

5. **"我 review 你解答"代码走读**（06-28）：治理二十万行 AI 代码的可行方式，且天然免疫假完成。
6. **排除法指令风格**："不要/别"16% + "别写代码"的爬升——对 AI 过度执行的有效缰绳。
7. **睡前托管**：把整夜交给 AI 长跑，早晨验收——配合 worktree 隔离（07-28 你已经开始用）就是完整的异步工作流。

## 9. 数据里的效率损耗点（本次挖掘新增）

与 [07-28 诊断](../2026-07-28-ai-workflow-efficiency-diagnosis/README.md)的 12 条建议互补，本次纯数据视角新看到四个损耗：

1. **Codex Desktop fork/重放风暴**。原始记录 3812 条"用户消息"里只有约 1188 条是真的；07-27 一天同一会话被 fork 成 13 个文件（相邻只差 4 秒）。这不直接烧你的时间，但说明**当天 Codex Desktop 处于崩溃-重开循环**——恰好叠加在假 PASS 事件日，环境不稳定加剧了那天的混乱。
2. **同一设计任务跨 5-7 天反复重启**。"你设计一套ui给看看呢"（5 天）、Composer 开机咒语（7 天）、"还是很不喜欢，先梳理一下 chat ui"（4 天）——Composer/Chat UI 这两个主题的设计循环各自横跨一周以上、多次从头拉起。缺一个"上一轮结论 + 已否决方案"的滚动清单，导致每轮都在重新对齐审美。
3. **截图循环慢被抱怨了 6 天而没有立项修**。"好慢啊 每次都去截图嘛"是唯一进入高频句 Top 5 的痛点。你 07-27 已经意识到（"要记到 agent.md……必要时刻可以录屏"），8 月也确实转向了录屏——但"harness 数值 diff + 独立裁判"的自动化通道（诊断报告建议 3）仍未落地。
4. **多诉求消息的漏做追讨**。"然后就是/还有就是/另外就是"式的 3-4 连发诉求，与"这个没做呢还啊"式追讨在数据上成对出现。一条消息一个诉求、或让 AI 先复述任务清单再动手，可以消掉这类返工。

另外两条趋势值得点名表扬（数据支持的正向变化）：8 月"别写代码"16% 与"仔细/深入"17% 的双爬升说明**设计先行纪律已经内化**；大重构分支六周未合并的问题在 08-10 已解决（并回 master，分支只剩 14 个新 commit）。
