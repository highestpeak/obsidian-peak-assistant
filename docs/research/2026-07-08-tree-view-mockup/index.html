Interaction Model — 点击行为共享 A 与 C

Tree view 里三种点击目标各自跳转到 vault 的对应位置。所有跳转默认关闭 modal（除非按住 Alt 保持 modal 常驻，方便连续检索）。
Click folder

Reveal in file tree

点击 tree view 里的 folder 行 → 打开 Obsidian 左侧 File Explorer，展开到该 folder，并 scroll 到可见位置（match 到 Obsidian 的 file-explorer:reveal-active-file 逻辑，用 folder path 代替 file）。

folder row click → close modal → reveal folder in left File Explorer
Click file

Open file

点击 tree view 里的 file 行 → 用当前 active leaf 打开该文件（等价于 workspace.openLinkText）。Cmd + click 在新 tab 打开。

file row click → close modal → open in active leaf
Cmd + click → open in new tab
Click preview snippet

Jump to line

点击右侧 preview 里任何一条 highlighted match line → 打开文件并 scroll 到该 line、光标停在 match 位置。若 match 在某个 heading 下，附带展开该 heading 上下文。

preview match click → close modal → open file with cursor at line

Design Judgment — Round 3 (post-feedback)

Changes from v1:
  • 删除 Variant B（中间态）—— 拥挤就拥挤到底，不要三档梯度
  • 默认改为 Variant A（Obsidian-native compact）
  • 新增 Interaction Model：folder / file / preview 三种点击都跳转到对应位置

为什么 A 作为默认是对的（重新审视）

  • Tree view 的独有价值本来就是"我在 vault 结构里定位这个文件" —— Obsidian 用户对文件树的位置有肌肉记忆，alpha-sort 反而让他们能扫得快。
  • 需要相关性排序时用户会切回 List view（默认就是 score-sort）；Tree 定位在"结构导航"，功能上没必要重复排序模型。
  • Compact 24px 单行 = 一屏容纳 18 条结果，避免像 Detailed 那样滚半天。日常搜索命中数一般 < 20，一屏能装完。

为什么 C（Detailed）保留价值

  • 调研场景：不知道哪篇最相关、需要看 heading anchor + snippet 判断的时候，Detailed 一屏能提供决策所需的所有信息，不用逐条 preview。
  • Heading anchor 是关键差异化：让用户看到 "match 在哪个语义单元下"，是 List view 也没有的信息。
  • "body only" 标记有语义价值：告诉用户"这个 match 不在任何 heading 下"，暗示可能是随笔或未组织好的笔记。

三个点击行为的一致性设计

  • 三种点击都关闭 modal（不停留），因为用户已经用眼睛完成了"找"这个动作，点击是"跳过去"的意图。
  • Alt + click 保持 modal 常驻，方便"连续跳转 → 回到搜索 → 继续跳"的调研工作流。
  • Cmd + click file 在新 tab 打开（沿用 Obsidian 全局约定）。
  • preview snippet 里可点击的 highlighted line 需要有清晰视觉反馈 —— 现在用轻微 hover 底纹 + 轻微阴影，避免"整段文字都能点"的迷惑。

最终方案：Tree view = Compact（默认） + Detailed 两档，工具栏右侧一个 Compact / Detailed 胶囊 pill 切换（沿用现有 view mode toggle 的滑动动画样式）。folder / file 一律 alpha-sort（对齐 Obsidian 文件树习惯），score-sort 靠 List view 提供。
点击行为：folder → reveal in file tree · file → open file · preview line → jump to line。默认关闭 modal，Alt 保持常驻。

还没定的开放问题

  • Detailed 模式下 heading anchor 怎么取？ 方案 1：取 match 所在 heading（可能是 h2/h3/h4）。方案 2：只取最近的 h1/h2。倾向方案 1，因为 h4 也能给用户提供语义位置。
  • Compact 模式下要不要显示右侧 preview pane？现在的 mockup 保留，因为 hover file 时能看到 top match snippet；但也可以在 Compact 模式下把 preview pane 隐藏、hover 时用 tooltip 替代。倾向保留 preview pane 保持模式一致性。
  • 点击 folder 后 reveal 到左侧 File Explorer 时，是否 auto-focus File Explorer？倾向不 focus，让用户视线不被 hijack。
  • 密度 toggle 状态是否持久化到 settings？倾向持久化，用户对密度偏好稳定。
  • Detailed 模式下如果结果超过 20 条，UX 变差 —— 是否需要"自动降级到 Compact"？倾向不自动降级（用户已经选了 Detailed 就是要看细节），但可以在 toolbar 显示 "20+ results — consider Compact" 提示。
  • 键盘导航已在上方 Keyboard Navigation 段决定：↑/↓ 只在 file 之间跳，folder 跳过。
