## 你现在该干什么(按顺序)

### 第一步 · 今天就做,三件防事故的小事

1. **`.gitignore` 加两行:`telemetry/` 和 `composer-comments/`。**
   为什么:Composer 每次运行都在往仓库根目录写你的使用日志,现在没被 git 忽略,哪天 `git add -A` 就把私人记录提交上去了。
2. **打一个"保命 commit"。**
   为什么:现在有 115 个文件改了没提交,其中 6 个新源码文件已经被其他代码 import——手一抖 `git clean` 或切分支,项目直接编译不过且**找不回来**。commit 时记得把这 6 个文件、12 个新测试、3 份新 spec、4 个调研目录一起 add 进去。
3. **改 `manifest.json` 的作者信息。**
   为什么:现在写的作者是 "Obsidian" 官方——是建项目时的模板残留,等于冒名,哪天分享出去就是事故。

### 第二步 · 接下来只做一件事:把 Document Copilot 接活

用人话说:Composer 里那个 AI 侧边栏,**看起来能用,其实是空壳**——发消息永远在转圈、AI 的主动发现根本进不来、"相关材料"永远是 0。三根线都没接上。

而这恰恰是整个项目最值钱的部分:外面调研了一圈,**主动式 AI 提示和深度检索报告在 Obsidian 生态里几乎没有竞品**,但前提是它得真的能动。

具体三根线(细节在 03 文件):
- sidecar 会话真正执行起来(接通 mark* 那组接口);
- AI 发现(ingestFinding)接上 AmbientPushRuntime;
- Composer 自己发出"用户在编辑"的信号(现在它不发,所以 ambient 永远沉默)。

**动手前先加几个日志埋点**——不然"相关材料=0"这个 bug 连是哪一步断了都查不出来。

### 第三步 · 明确暂停的东西(不做也是决策,省心)

- **三份 7-28 新 spec(AI Graph 平台等)冻结**:旧的 Composer 还没收尾,别开新战线。spec 可以继续写,代码不动。
- **Terminal / Claude Code 集成:放弃**。外面已有 103 个同类插件,最火的 Claudian 免费还做得好,这仗不用打。
- **Command Center、Onboarding:停止投入**。前者代码里已无任何入口,后者只有"发布给别人用"才有价值,而项目现在根本发布不了(包 24MB、依赖本机 node_modules、无发布流程)。想让别人用,更便宜的路是把能力开放成 AI 可调用的接口(SKILL.md / MCP),不是上架商店。
- **Usage Dashboard:不砍,但"保真删假"**(owner 复议裁决,见下文复议记录)。用量追踪是真需求;要删的是 6 屏里的假东西——8+ 个点了没反应的按钮、写死的金额、不落地的 Apply。留真实数据的屏,假的部分等有真实链路再回来。

### 第四步 · 文档大扫除(开个专门 session 让 AI 批量干,不用你手动)

## 这次体检的五个重要事实(人话版)

1. **六个功能里,外部最没有竞争的是三个**:Composer(自绘编辑器)、Ambient(AI 主动提示)、AI Analysis(深度检索报告)——差异化投入优先砸这里。Chat、File Atlas、用量面板不是不要(见下方 owner 复议记录),而是投入方式不同:Chat 当稳定管道维护、Atlas 修断点做深、Dashboard 保真删假。
2. **外面变天了**:Obsidian 官方定案自己不做 AI,只把 vault 开放给外部 AI 工具;新王 Claudian(把 Claude Code 塞进 Obsidian)8 个月 154 万下载,免费。自建聊天界面这条路已经死了,开放接口才是顺风路。
3. **架构不再是护城河**:Reflect Open 把和 Peak 几乎一样的架构(markdown 事实源 + SQLite 索引 + 自带 key + 改动审阅)整套开源了。Peak 剩下的独特性就是第二步那三根线,所以它们必须接活。
4. **学术研究的提醒**:人和 AI 混着写的内容,6 天后作者自己只能认出 37.7% 哪句是自己写的——所以"AI 写的块打上标记 + 能回看来源"值得做成正式功能;另外,图谱可视化会让人过度相信 AI 的错误结论,AI Graph 以后要做就得带"防轻信"设计。
5. **一个躺着的机会**:所有竞品最大的翻车点都是"大 vault 索引跑不完、崩了、反复重建"。Peak 把索引做到崩溃安全 + 坏了能自愈,就是用户能立刻感知到的最大差异。

## Owner 复议记录(2026-07-28,与评审结论的三处出入)

评审原文([03 附件](./03-four-reviews.md))保持原样作为记录,以下三条按 owner 意见修正了本页行动清单:

1. **Chat Studio 保留——评审本来也没说砍。** 4 分砍的是"在聊天 UI 上继续做差异化"这条路(Claudian 免费 154 万下载,赛道没得打),不是 Chat 本身。Chat 是 AI Analysis、Composer sidecar 共用的会话管道,必须留。正确投入方式:当稳定管道维护——ribbon 默认入口修成指向 Studio、删掉 25+ 个已无入口的旧组件,让它更稳而不是更花。
2. **File Atlas 继续做深。** Owner 认为它导航体验差异化、好用;外部证据也站这边——结构导航方向没有强竞品,同类全部小于 1 万下载、没有赢家。评审 3 分打的是当前执行断点而非方向:图布局不持久、Send to Copilot 死按钮、Modal 关了即丢状态、File Atlas 与 File Workspace 两个名字/两份 spec 互不认。行动从"收缩"改为:**修掉这几个断点 + 命名归一,继续做深**。唯一保留的提醒:别把力气花在"取代 Recent Files"这类浅功能上,差异化在"结构 + 图 + inspector"的组合导航。
3. **Usage Dashboard 保真删假。** 用量追踪是真需求(自用要看;若将来公开,BYOK 用户对 token 成本高度敏感,是用户调研里最强信号之一)。评审 2 分打的是形态:6 屏里大半是假的(8+ 死按钮、写死金额、不落地的 Apply),违反项目自己的 disabled-never-fake 纪律。行动:保留真实数据的用量/成本屏,删掉或隐藏假交互;Budget/Optimization 等有真实链路再回来。

复议后,真正"砍掉"的只有两样:**Terminal 集成**(103 个同类插件的红海)和 **Command Center**(代码零入口的残留)。
