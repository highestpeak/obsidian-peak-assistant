AI Search Tab · UI/UX Review

Quick Search modal 的 AI Search 空闲态（建议卡 + 历史列表 + 模式切换）全链路审阅：截图证据 + 代码根因 + 重设计 mockup。
读者：本插件维护者 证据：src/ui/view/quick-search/ + src/service/context/ 约 5,000 字 · 10 分钟 2026-07-09

综合判断

骨架正确，交付粗糙：三层各缺一道工序

这个 tab 的信息架构没问题——建议、历史、模式切换是对的三件套。问题集中在"最后 10%"：模板变量能以 {activeDocumentTitle} 原文漏到用户面前、同一个时间戳渲染两遍、历史列表无去重、footer 数字染成链接色却不可点、placeholder 是等宽字体。十个问题没有一个带 TODO 标记，全部是无人认领的静默缺陷。

按层归因：数据管线（pattern → suggestion）缺输出校验，LLM 发现的 pattern 未经 template/variables 一致性检查直接入库；列表层缺展示聚合，每次 run 一条新纪录原样倒出；视觉层未迁移到 pk-* 原语体系，也没有登记迁移债。修复不需要重构，但需要在这三层各补一道工序。

重设计 Mockup（After）

重画原则：数据先诚实（能显示的都真实、显示不了的不显示），再谈精细。所有值沿用 --pk-* token，卡片/行对齐 Row/Chip 原语规格。

✓ #1 填充失败的 pattern 不再产出卡片——第 6 张 {activeDocumentTitle} 卡直接消失，宁缺毋滥（4 张够用，凑 6 张不是目标）。
✓ #2 标题不再两段式切断：整句渲染，变量用 accent 底色 inline 高亮，一眼可读、也保留了"这是模板"的暗示。
✓ #3 "独立开发想法评价" 三条聚为一行 ×3 runs，"Deep analysis of 01-gate…" 两条聚为 ×2；点击进最近一次，展开可见历次。
✓ #4 时间只保留右侧一处；meta 行只放 sources。
✓ #5 "869 analyses" 假链接移除；真实入口 "View all 312 →" 移到 Recent 区头（312 = 聚合后的会话数，非行数）。
✓ #6 placeholder 用 sans（修 .cm-scroller 字体继承）。
✓ #7 footer 移除 "↑↓ Navigate"，补上真实存在的 esc；列表键盘导航做好后再加回。
✓ #8 建议卡语言统一（示例用英文句式承载中文变量；实际语言跟随设置）。

前后对比要点

  • 建议区从"6 张凑数"变为"N 张可信"。数量由通过校验的 pattern 决定，上限 6、无下限。一张漏变量的卡对信任的破坏，大于两张空位的损失。
  • 卡片信息密度下降、可扫读性上升。原版三层（切断的标题 / 变量倾倒的副标题 / chip）读一张卡要来回两次；新版一层整句 + 一枚 scope chip，视线单向。
  • 历史列表从"日志"变为"会话"。用户关心"我分析过什么"，不关心"系统写过几行记录"。聚合徽标保留了频次信息（×3 本身是信号：这个主题你反复在问）。
  • 所有可点的都真的可点。假链接是这一面最伤信任的模式（另见 02 篇 Vault Intelligence 的 no-op 问题，同一病根）。
