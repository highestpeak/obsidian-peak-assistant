01 / Mental model

从“背快捷键”改成“沿层级移动”

直接 hotkey 只适合少数高频入口。完整可达性来自稳定导航路径： 大区域快速跳，组件逐个过，组件内部按空间结构走。

01

所有动作先可导航

忘记全部加速键，用户仍可通过 focus path 到达每个可见动作。快捷键不替代基本可达性。

02

Composite 只占一站

列表、树、tabs、toolbar、grid、graph 只占一个 Tab stop；进入后使用方向键。

03

编辑器优先

输入状态中，字符、方向键、Tab、斜杠和问号属于编辑器；应用导航不能偷键。

02 / Evidence

三个研究方向，指向同一件事

学术研究强调学习与记忆，产业模式强调 composite 与区域跳转， 用户信号强调跨 pane 的焦点断裂。答案不是更多隐藏按键，而是更可预测的焦点架构。

03 / Focus architecture

一个焦点，三种状态，六层所有权

Focus 是键盘指针，Selection 是集合状态，Active 是当前打开/预览。 这三者分开后，方向键移动不会意外执行昂贵动作或修改选择。

Selected block

Active document

All three

三栏只用四站

Header 与 splitters 通过所在 zone 的 Tab 到达，不把 F6 环切得过碎。

消息是阅读单元

上下移动 message group；Enter 进入正文链接和控件；Escape 回 message group。

流式稳定

新 token 和新消息只播报状态，不把用户从左栏、Outline 或 Composer 拉走。

05 / Guardrails

四条红线，避免“全键盘”反而更难用

键盘系统最危险的失败不是少一个 hotkey，而是偷键、长 Tab 链、异步抢焦点和关闭后丢失位置。

不让每一行都进 Tab 顺序

长列表、树和消息必须是 composite；否则完整可达会退化成几十次 Tab。

不在编辑状态抢裸字符

`?`、`/`、方向键、Space 与 Home/End 在 editor/input 中由编辑器拥有。

不让 AI 更新移动焦点

Process 完成、结果刷新、建议到达和消息流式更新只通过状态播报反馈。

不默认抢全局组合键

五个 surface 注册 Obsidian commands；数字 direct-focus preset 只在用户选择并处理冲突后启用。

06 / User validation

设计完成，不等于已经验证

本轮用户研究是公开资料的二手定性研究。上线前仍要让真实用户完成跨工作区任务， 特别验证屏幕阅读器、中文输入法、detached window 和窄屏 drawer。

Final design verdict

完整键盘体验是一套导航架构，不是一张巨大的快捷键表。

Peak Assistant 应该让每个动作先通过稳定焦点路径到达，再为高频入口提供可发现、可定制、 可冲突检查的加速键。这样五个工作区可以拥有各自专业行为，同时仍然像同一个产品。
