Copilot Command Center Redesign

最终 UX Wireflow：从入口到 Review 的完整流转

这版报告按 wireflow 阅读：每个小框都是一个真实界面节点，箭头标注用户点击的按钮或 agent 产生的分支。 入口 panel 只负责捕捉 intent；Auto 和手动工具都会进入同一套 Agent Run / Review Surface； 最终根据 artifact 自动落到 Changes、Insights、Sources、Chat。

1
入口不是工具目录

默认只展示 Auto 和 3-4 个当前最相关动作，其余能力通过搜索或 Show all tools 找到。

2
Auto 是 ReAct，不是固定流水线

Agent 边观察边调用工具，trace 是行动记录，右侧 diff 随工具结果逐步更新。

3
结果层不是二选一

Auto 可以同时产生 diff 和 insight。Diff 负责可应用改动，Insight 负责解释、来源、下一步和继续对话。

Auto 路径

点击 Run Auto进入 Auto Review。Agent 不预先暴露一堆功能卡片。
ReAct trace 持续更新Observed note -> Called Connect links -> Read sources -> Called Add evidence -> Revised proposal。
右侧 diff 同步更新每个变更块标注 provenance，例如 Connect links、Add evidence、Task check。
Insights 同时沉淀Agent 的判断、未应用建议、sources 和 follow-up 问题进入 Insights tab，不挤进 diff。
完成后进入可 apply 状态Apply reviewed changes 只在 diff 稳定后可用，支持 reject 和 undo。

手动工具路径

点击推荐动作例如 Improve note、Connect links、Add evidence。
仍然允许 agent 调辅助工具用户点的是入口意图，不是限制 agent 只能用一个工具。
写入类进入 Diff Review最终结果是整篇文档 diff，不是多个功能 section。
分析类进入 Insight ReviewSummarize、Vault Health、Knowledge Gaps 等不直接改文档，但可以继续对话、保存、或升级成 diff。

Auto 里 Diff 和 Insight 如何共存

不是“写入 vs 只读”的功能分叉，而是一个 run 的两个结果层
1. 一个 Agent Run，多个 Artifact

Auto 启动后不先问用户选哪些工具。Agent 在 ReAct 里边读上下文边调用工具，最后可能同时产生可应用的 change artifact 和解释性的 insight artifact。

Trace Change artifact Insight artifact
2. 有改动时，Diff 是主视图

用户最关心“会不会改我的笔记”。所以只要有修改建议，右侧默认打开 Changes，红绿 diff 逐行展示；每一行都可追溯到对应工具和来源。

Changes Insights Sources
3. 没改动时，Insight 是主视图

如果这次只是体检、总结、发现 gap，界面不显示空 diff。它展示结论、证据和下一步，并保留输入框继续追问：也可以点 Create proposal 转成新的 diff run。

Ask follow-up Save to note Create proposal
EInsight 区域可变尺寸

Insight 不是固定右侧小栏。它默认作为 diff 的旁路上下文出现；当内容变成长报告、vault health、knowledge gaps 或研究总结时， 用户可以切到更大的阅读区域，继续追问或把某段 insight 转成新的 change proposal。

Docked rail: 默认旁栏

有文档改动时使用。Changes 占主区域，Insights 作为 280-360px 旁栏，展示风险、来源、未应用建议和 follow-up。

Split view: 可拖拽阅读

用户拖动分隔线，Changes / Insights 可以 60/40、50/50 切换。适合一边看 diff，一边看长解释和来源。

Full width: 报告模式

点击 Insights tab 或 expand 后，Insights 占满主区域。顶部仍保留 Changes badge，底部保留 Chat / Save / Create proposal。

按钮到界面的映射

实现时可直接按这张表连 routing
Command Center: Document / Vault / Setting ->

打开入口面板，并切到对应 tab。Document 是当前 note；Vault 是 vault intelligence；Setting 是系统和能力管理。

入口面板: Run Auto ->

进入 Auto Review。左侧 live ReAct trace，右侧按 artifact 展示：有改动就默认 Changes + Insight rail；没有改动就默认 Insights full width；始终可以继续对话。

入口面板: 推荐写入类工具 ->

进入同一个 Diff Review shell。工具名称只是 initial intent；agent 仍可自然调用其它工具，diff line 上标 provenance。

入口面板: 推荐分析类工具 ->

进入 Insight Review shell。它不直接写回原文，但不是静态只读页：默认全宽阅读，可追问、保存、打开来源，或 Create proposal 进入 diff。

Diff Review: provenance badge ->

点击或 hover 可展开对应 trace/tool evidence：这个变更为什么出现，来自哪个工具和源文档。

实现口径

给后续代码改造用
核心决策： 入口 panel 只负责 intent capture；agent run 只展示用户可理解的行动 trace；最终 review surface 按 artifact 类型分为 Changes 与 Insights。 写入类能力不再各自弹不同 panel，而是统一生成 patch/diff artifact；分析类能力统一生成 insight/report artifact，支持继续对话和升级成 diff。 Insight 区域支持 docked rail、split view、full width 三种阅读尺寸。Auto 和手动工具的差别只是 initial intent 不同，后续都允许 agent 在 ReAct 循环里自然调用工具。
