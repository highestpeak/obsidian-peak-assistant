PRODUCT RATIONALE · TARGET REFERENCE

不是另一个聊天框，
而是知识工作的临时工作台。

Peak Chat Studio 以 Vault 为长期记忆、以对话为临时工作台、以可追溯产物为结果。它的差异不在于暴露更多模型和 Agent，而在于把“找证据 → 形成结果 → 写回知识库”连成闭环。

长期记忆Vault / Project

事实、文档、链接和历史工作的 source of truth。

临时工作台Conversation

表达意图、组合证据、追问、纠正和分支。

可继续结果Artifact / Note

可定位、可审阅、可保存、可再次编辑。

研究边界本轮是 owner 反馈 + 本地能力盘点 + 官方竞品桌面研究 + HCI 文献分析，不是已完成的外部用户访谈。

02

五个真正的用户工作

能力优先级从用户要完成的工作出发，而不是从模型能力列表出发。

01Recall从已有材料找回事实

项目范围 · Vault 检索 · 引用定位

02Synthesize跨材料建立结构

多资源 · 表格/图表 · 追问

03Create生成可继续使用的产物

预览 · 保存 · 打开 · 版本

04Maintain更新知识而非复制答案

目标文件 · Diff · 回执 · 回滚

05Research本地不足时补充外部资料

来源计划 · Web 授权 · 引用

竞品不是模板，是决策证据

学习成熟心智，保留 Peak 的 Vault-native 差异。

产品学习不照搬
ChatGPT自动路由、Projects、渐进展开、分支与历史搜索所有能力都塞进 + 或模型菜单
Codex项目线程、运行中 steer、产物 review、按需授权普通知识 Chat 常驻代码环境控制

PerplexityAuto 与具体模型并存、研究关注来源把 Chat 收缩成纯搜索答案页

05

能力取舍

先验证核心心智，再形成写回 Vault 的闭环。

P0核心心智
  • Composer 三问工作契约
  • Auto + specific model
  • 来源边界与 reply anchor
  • 大纲/资源筛选与真实定位
  • 菜单、标题、运行反馈完成度
P1Peak 闭环
  • 引用与 source bundle
  • Artifact receipt、版本、写回 Vault
  • AI 创建助手
  • 运行中 steer 与按需授权
  • 项目/Vault 检索解释
暂不做避免控制台化
  • 公共助手商店
  • 常驻 Provider/temperature 面板
  • 第二套 Vault 全文搜索
  • 每条回答重复 Assistant 身份
  • 内嵌 follow-up Composer
06

下一轮验证，不问“喜欢吗”

让真实知识库用户完成任务，观察他们是否建立正确心智。

  1. 只根据一个项目的三份文档回答
  2. 加入 Vault 文档并确认被使用
  3. Auto → 具体模型 → Auto
  4. 对旧回答定向追问
  5. 找到生成文档并保存回 Vault
  6. 用 AI 创建证据助手并检查规则
