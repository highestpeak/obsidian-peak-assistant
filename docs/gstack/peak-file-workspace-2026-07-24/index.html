最重要的架构决定

DocumentLoader 继续负责读取与索引；新的 app-owned File Workspace 负责 View 和安全生命周期； 三种文件只提供 renderer 与操作，不建立第二套 AI runtime。

01 · PRODUCT MODEL

不是三个 viewer，是一个文件工作区

用户只学习“打开、选择、操作、审阅、保存”。文件类型决定工具，不改变候选和版本心智。

文件是主角 中心 renderer 保持最大面积；AI sidecar 可收起，不把工作区做成 dashboard。
候选先于写入 AI edit、HTML patch 和 destructive operation 都先进入 review。
复用现有 runtime Media、AI Gateway、Permission、receipt 与 usage tracking 不按文件类型复制。

07 · SOURCE OF TRUTH

每种文件有不同真值，但同样可恢复

一致的是审阅与权限，不是强迫所有文件采用同一种保存方式。

文件Canonical source默认接受动作禁止
Image原图 + accepted version filesSave as new version无 backup 覆盖原图
HTML`.html` sourceAccept reviewable patch未校验 hash 直接写入
PDF原 PDFSave annotation companion把 OCR 冒充原文
Runmachine recordPersist receipt / trace用 Save to Vault 代替历史
HTML 与 SVG 的安全边界

Safe preview 不提供 same-origin、parent、Node、Electron、Obsidian 或 unrestricted network。 Interactive mode 仍在 sandbox 中，只通过 allowlisted message schema 与宿主通信。

08 · DELIVERY

先验证宿主边界，再逐类型接入

这是完整方案的实施顺序，不是把未完成阶段包装成已交付 MVP。

Phase 0
Characterization 与四个 spike

Extension takeover、HTML sandbox、PDF companion、popout lifecycle。

输出 go/no-go 与最终 open mode，不动 production extension。
Phase 1
Foundation

Manifest、app-owned registry、common shell、candidate、version/save ports。

Feature flag 下完成生命周期与 boundary tests。
Phase 2
Image

PNG/JPEG/WebP、crop/mask、programmatic transform、AI edit、version/replace。

第一条真实“打开文件到安全保存”的闭环。
Phase 3
HTML

Source/Preview/Split、safe sandbox、resource resolver、element patch。

本地浏览器式查看与 AI source editing。
Phase 4
PDF companion

Page/selection context、OCR gate、annotation Markdown、citation/export。

Native PDF 不退化，AI 阅读链路闭环。
Phase 5
扩展与收口

JSON、CSV、Office、Audio、Video、SVG；清理重复 preview 路径。

新增文件类型不再复制 shell 或 AI runtime。
