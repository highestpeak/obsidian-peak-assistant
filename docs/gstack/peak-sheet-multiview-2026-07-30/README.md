## 这次重做解决什么

旧稿把 Table、Chart、未来视图和 Ask Peak 同时铺在画布上，上一轮又过度收敛成字段类型 + 多视图，结果更像低配多维表格。本版不做表面润色，重新建立计算工作面的优先级：

```text
自由 Sheet（单元格 / 区域 / A1 引用）
├── 基础公式、格式与选区统计
└── 结构化 Dataset（字段 / 记录 / 计算列）
    └── 多视图与只读分析
        └── AI 辅助（解释、生成受限计划）
```

产品价值不从“有几个页面”开始，也不从“有多少字段类型”开始，而是从用户能否直接计算、格式化、比较和解释当前数据开始。

Mock 不再提供常驻的“数据表 / 分析页”左侧栏。Peak Sheet 运行在 Obsidian 内，文件与工作区导航由宿主负责；当前界面只聚焦一个 Dataset。其他 Dataset 只有在真实跨表切换需求成立后，才进入标题旁的轻量切换器，不重新造一套应用导航。

借鉴分两层：

- “门”表格示例：高信息密度、紧凑网格和字段内微型数据图形；不把深色主题本身当成设计要求；
- 飞书多维表格：`数据表 → 视图 → 字段 → 记录` 的层级、视图标签、字段配置入口，以及数据表级独立仪表盘。

参考资料：[飞书——多维表格产品分析](https://www.woshipm.com/evaluating/5935411.html)。本 Mock 借鉴产品结构与交互原则，不复刻品牌视觉或完整功能范围。

## 视觉与交互原则

- **字段类型是地基：** Mock 明确展示文本、数字、单选、多选、日期、复选框、链接与公式；不同类型决定输入、校验、排序和显示。
- **单 Dataset 聚焦：** 默认界面不展示虚构的多表工作区，也不把 Dashboard 做成左侧一级页面；当前数据集、视图和字段操作占满主画布。
- **计算表格是主编辑面：** 默认首屏直接进入带列标、行号、选区、公式栏和格式工具的高密度 grid；分组默认关闭，避免一上来就像多维表格报表。
- **公式不是五个演示函数：** 函数库按数学、逻辑、条件聚合、文本、日期和信息判断组织；自由单元格公式与 Dataset 计算列共享 parser / evaluator，但保留各自引用语义。
- **格式不是装饰：** 数字、货币、百分比、日期时间、时长、自定义显示、对齐、换行、字体强调、填充、边框与条件格式都贴着选区操作；语义值和显示格式分离。
- **视图是投影：** Table、Board、Calendar、Gallery 和 Dashboard 共用 Dataset revision 12，不复制记录。
- **统计贴近选区：** 状态栏直接显示当前选区的计数、求和、平均值、最小值和最大值；列统计与分组统计是后续层，仪表盘只是这些结果的进一步消费。
- **仪表盘是次级分析页：** 使用统一筛选驱动 KPI、趋势、漏斗、渠道回复率与机会优先级。
- **AI 退到辅助层：** 默认隐藏；打开后先生成受限 ComputePlan，用户接受后才改变当前视图。
- **字段配置是真正的结构操作：** 展示字段列表、类型与单选选项，而不是装饰性说明弹窗。
- **移动端用于消费：** 查看指标、行动窗口与审批；不承诺完整 grid 编辑。
- **主题不承担设计感：** 默认使用石墨深色工作台，同时保留纸面浅色切换；高级感来自三层线条、材质、密度和微型数据图形，而不是把背景简单涂黑。

## 字段模型

字段类型决定原始值、校验、排序和编辑器；显示格式只决定同一个值如何呈现。两者不能混成一份不断膨胀的“类型清单”。

| 层级 | 当前类型 | 说明 |
|---|---|---|
| 基础值 | 单行文本、多行文本、数字、复选框 | 最小稳定值类型；邮箱、电话等属于文本校验 preset |
| 选择值 | 单选、多选 | 存储稳定 option id，颜色与标签样式属于 view metadata |
| 时间值 | 日期与时间 | 一个类型覆盖仅日期、日期时间和时区显示 |
| 引用值 | 链接、Vault 附件 | URL 与可解析 Vault 资源；附件不等于跨记录 Relation |
| 计算值 | 公式 | 从本记录字段派生，受限 evaluator，不执行任意脚本 |
| 系统值 | 自动编号、创建 / 修改时间 | 由 Dataset adapter 维护；自动编号不是稳定 record ID |
| 后续关系能力 | Relation、Lookup、Rollup | 需要独立关系模型，继续后移，不伪装成普通字段 |

以下属于**格式或单元格表现**，不新增底层字段类型：货币、百分比、千分位、评分、进度条、数据条、时长、日期格式、对齐、换行和条件色。

当前表格用 17 个字段验证这一模型：文本、单选、日期、公式、多选、复选框、链接、附件、日期时间、百分比进度和多行备注都出现在同一个连续 grid 中。新增的 K–Q 列分别是技能标签、已收藏、JD 链接、附件、面试时间、进度和备注。

## 单元格显示契约

同一种字段必须覆盖真实数据状态，不能只画一个“最漂亮的有值示例”：

| 状态 | Table 中的显示规则 |
|---|---|
| 空值 | 统一显示低对比 `—`；没有空 Tag、空边框或“未填写”胶囊 |
| 单行长文本 | 固定一行、列内省略；完整值保留在 title / 详情编辑器 |
| 多行文本 | Table 只投影首行并省略；编辑态负责完整换行内容 |
| 单选 | 一个语义色 Tag；26px 高、11.5px 字号，不使用装饰圆点 |
| 多选 | 最多显示两个中性 Tag；剩余显示 `+N`，完整集合保留在 title |
| 链接 | 图标 + 可读 host/path；长地址省略，空链接回到统一空值 |
| 附件 | 单附件显示文件名；多附件显示堆叠图标与数量；无附件显示空值 |
| 日期时间 | 有值显示 `日期 · 时间`；`待确认`是业务状态，空值仍显示 `—` |
| 数字 / 进度 | 数字右对齐并使用 tabular numerals；图形只辅助，不替代明确数值 |
| 复选框 | `true / false` 都是有效布尔值；未勾选不是空值 |

Tag 也分两种视觉职责：阶段使用受控语义色；技能标签统一为中性色。不会再为了“丰富”让同一组技能交替使用青色和紫色。

## 视觉质感重构

2026-07-31 的视觉纠偏不再把“高级”理解为换成深色，而是重建以下系统：

- **三层线条：** 普通单元格使用最低对比 hairline；冻结列、表头和区块边界使用更强结构线；选区和活动单元格只使用一条鼠尾草绿数据边，不让所有边框争夺注意力。
- **矿物色主题：** Graphite 使用暖黑、石墨灰和低饱和鼠尾草绿；Paper 使用暖灰纸面、墨色文字和相同的鼠尾草绿。两者不再使用通用 SaaS 蓝作为默认视觉身份。
- **连续数据密度：** Fixture 从 12 行扩为 20 行可见记录，去掉首屏大片空白；44px 行节奏同时保留主信息、辅助职位和微型数据图形。
- **材质而非大色块：** 数据单元格只带极轻微斜纹，冻结列通过阴影和结构线分离；标签继续是紧凑矩形，不使用大圆角胶囊。
- **语义色受控：** 绿色只表达当前选区、有效公式和正向状态；紫、蓝、琥珀、红只服务阶段与条件规则，不铺满导航和空白区域。

本轮进一步只收敛 Table 的单元格，而不借看板或仪表盘掩盖基础表格问题：

- **一行一个阅读基线：** 主记录从“头像 + 两层小字”改为 20px 标识、13px 公司名和同一基线上的 11px 职位，长内容在本列内截断。
- **Tag 回到正常控件尺寸：** 阶段和优先级统一为 24px 高、11px 字号、4px 圆角；工作模式不再套第二层边框，而用细竖线区分类别。
- **列宽服从内容：** 公司、下一步和薪资获得更真实的宽度；日期、薪资和公式结果使用 tabular numerals，数字按列稳定对齐。
- **微型图形不覆盖数据：** 匹配度从铺满单元格的背景条改为 22px 环形刻度 + 明确数值，等待天数保留短条和单位，减少大片色块。

## 可操作路径

1. 查看默认选区 `G2:G6`、活动单元格 `J6`、公式栏和底部选区统计。
2. 点击“自动格式”查看数字 / 货币 / 日期等格式，再打开“条件格式”查看数据条和高亮规则。
3. 点击“函数”查看按类别组织的基础函数库、公式作用域、类型检查和结果预览。
4. 点击“字段”，再打开“字段类型”选择器，查看自由表格升级为结构化 Dataset 后的字段能力。
5. 在顶部切换“全部记录 / 求职看板 / 面试日历 / 岗位画册 / 决策仪表盘”。
6. 点击“分组”切换表格的阶段分组；它不是默认展示状态。
7. 点击“分析”生成计划，并应用“高价值待跟进”临时视图。
8. 点击 revision 左侧的 Dataset 图标查看数据边界；点击手机图标查看移动端只读仪表盘。

## 范围边界

- 首版能力顺序是 free-cell grid → formula / formatting / selection statistics → structured field schema → read-only analysis view；AI ComputePlan 在这些能力之后。
- Board、Calendar、Gallery 和 Dashboard 在 Mock 中用于验证 View adapter 与信息架构，不等于同时进入首版承诺。
- Mock 展示较完整的基础函数类别和格式语言，但不是同一实施波的承诺；Relation、Lookup、Rollup、数组公式、跨 Sheet 引用和任意脚本计算均为后续能力。
- 富格式属于 Sheet / View metadata；Markdown 导入导出不承诺无损保存样式，也不会把样式编码进原始单元格字符串。
- 没有生产 Dataset runtime、稳定 record ID、formula evaluator、ComputePlan executor、真实计算、同步或写回。
- 页面记录、revision、图表与计划结果均为静态 fixture。
