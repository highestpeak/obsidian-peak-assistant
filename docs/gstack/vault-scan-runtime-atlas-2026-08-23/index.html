Scan Vault：从点击开始，到可审核产物

把 UI、Controller、Index、两个 Agent 会话、证据、进度、持久化和最终写入边界放进同一张地图。设计者可以验证产品心智，程序员可以沿命令、状态和产物直接实现。

最重要的边界：Scan 只产生机器知识、证据和可审核工作，不修改用户文件。用户在 Completed 后明确选择 Proposal 并 Apply，才进入写入链。

不是“AI 做完就算完”：完成权在系统手里

Agent 能推理和提出产物，但 scope、证据、进度、预算、状态迁移、完成门和写入权由 controller/validator 掌握。

单写者
UI + Projector

显示一个真值 projection，发出 start/pause/inspect/choice。React 不自行拼业务百分比。

ScanRunController

父状态机与 DAG；调度 controller、checkpoint、预算、stage gate。

BuildIndexController

三条 per-file lane、route capacity、backpressure、terminal receipts。

Discovery Controller

frontier、investigation、finding registry、completion gate。

Review Controller

atoms、jobs、workKey、artifact validator 与 package freeze。

CompletedPublisher

只提交已经验证的 package；不调模型、不临时生成 task。

1 · Discover：准备运行，不是发现 Community

这是确定性 preflight。四个 gate 把易变的用户选择变成一个可恢复、可审计的 FrozenScanPlan。

0 个必需 Agent
Gate 1Scope frozen路径、hash/mtime、排除、不可读。
Gate 2Baseline pinnedIndex/graph revision 与 cursor。
Gate 3Routes resolvedroute pools、capacity、retry、budget。
Gate 4Work graphDAG、manifests、ProgressPlan。
CheckpointFrozenScanPlan暂停恢复使用同一 fingerprint。
NextDispatch ready work开始逐文件 Index 与 collectors。
可选 AI planner：可以建议优先级，但不能改变 scope、路线或完成权；它失败时确定性计划仍能继续。

3 · Vault-wide discovery：反复调查的 Agent Harness

Relationship、Community、Hub、Bridge 是输出类型，不是顺序。Controller 根据最新 frontier 反复选择下一项调查；Agent 只能用受限工具读冻结证据并提出 proposal。

Agent session 1
一轮调查与回到 frontier可以重复 0..N 个 bounded attempts
Controller chooses

→

→

accepted / revised / rejected finding → reprioritize frontier → 下一轮

4 · Prepare review：产物生成也是 Agent 驱动的

Discovery 结束后，系统冻结 findings + deterministic issues。一个统一 ReviewPreparationAgent session 执行 0..N jobs；每份普通 review work 必须先生成 artifact，再通过 validator。

Agent session 2
1Normalize atoms类型、identity、provenance、去重。
2Provisional graphowner question、surface、boundary、anchors。
3Partition jobs冲突串行，无冲突 bundles 可并行。
4 · AgentDraft artifactsmerge/split/defer + explanation/options/citations。
5 · SystemValidate & reviseschema、citation、identity、boundary、exit。
6Freeze packagestable workKey、receipts、task plan。
UI 因果：Session stream 是当前 job 的生成过程。只有 draft 通过 validator 并被 Controller commit，对应 Review work 行才能从 Queued/Generating 变成 Ready、Needs choice 或 Recovery。

一个 Agent，不是按 task kind 建十一个 Agent

0 findings 时 0 jobs。普通 reviewable work 至少一个 drafting job；复杂 bundle 可拆分，互不冲突的 jobs 可并行，但 canonical workKey commit 仍串行。Completed 后的 ProposalDraftAgent 是另一条 Scan 后能力，不计入本阶段。

5 · Publish：短、确定、可重试

Publish 没有模型调用。它只提交已经冻结并通过验证的 package；如果提交失败，重试相同 package，不重新跑 Agent。

Completed 页面只读取这个 snapshot。`Ready for review` 代表 validated ReviewWorkArtifact 已存在；用户作出 choice 后，才创建 revision-guarded source diff，Apply 后再 re-index 和 Verify。

没有“总发现数”，百分比怎么走

Pause、Resume、Stop：不丢昂贵工作

Pause 不是瞬间冻结 provider。系统先停止派发新 work，再等待安全 checkpoint；成功 receipt 永远复用。

Checkpoint
Pause

状态 running → pausing → paused。安全点包括 document receipt、tool result、finding commit、review job commit。

Resume

校验同一 FrozenScanPlan fingerprint 与 source revisions；无 receipt 的调用新建 attempt，成功调用不重复。

Stop

收束为 stopped-partial，保留 Index 与机器事实；不从不完整 findings 自动制造正常 Completed tasks。

产物在哪，谁能写什么

机器产物进入 registered JSON/JSONL 与本地可重建 projection。Scan 中没有用户文件 writer。

Write boundary
Canonical run truth

FrozenScanPlan、per-run events、EvidenceManifest、findings、ReviewPreparationPackage、Completed body。

Rebuildable local projection

FTS、vectors、file/lane status、finding filters、Work queue queries。丢失后由 canonical artifacts 重建。

User-owned content

只有 Completed 后的显式 accepted Proposal → Apply 可以写；写前 revision guard，写后 re-index + Verify。

目标合同与当前代码不是同一件事

UI Mock 和本报告定义目标；当前 Runtime 是基础资产，但不能用它的临时四阶段结构反向删掉 Prepare review。
