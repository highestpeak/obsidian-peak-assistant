RESEARCH → BOUNDARY → COMPOSER-ALIGNED PROTOTYPE

不是给每种文件堆一套工具栏，而是让原生文件表面进入 Peak 的 AI 工作流。

本轮设计重置先承认 V1 失败：它把能力矩阵直接铺成界面，AI 入口不够明显，Image 缺乏画布中心感，Canvas 与 Excalidraw 又错误地被重新发明。新方案统一使用 Composer 的主内容区、Intelligence 侧栏和候选变更审阅。

Current design direction · production implementation pending

为什么上一版必须推翻

这不是圆角、颜色或间距问题，而是产品结构不成立。

Rejected V1

  • 把“我们支持什么”当成了“用户应该一直看到什么”。
  • 每种格式长出自己的长工具区，AI 被埋在次要位置。
  • Canvas / Excalidraw 用仿制表面替代用户已熟悉的原生体验。
  • Code 被扩成简陋 IDE，超出了轻量读改的真实需求。

重置后的判断

  • 文件本身永远是主角。图片、PDF、网页、代码或画布占据最大的视觉空间。
  • AI 永远可见。所有格式共享 Composer Intelligence，明确展示当前 context、建议动作、回答和候选审阅。
  • 原生编辑器拥有自己的语言。Obsidian Canvas 和 Excalidraw 的卡片、工具、属性、连线与快捷操作不被 Peak 重做。
  • 只支持高频核心动作。Peak 不需要成为 Photoshop、Acrobat 或 VS Code 的复制品。

统一设计原则

01

Composer 是共享骨架

沿用文档标题、中央工作区、右侧 Intelligence、底部 prompt 和 Accept / Restore / Retry 候选审阅。

02

Native surface first

能由原生查看器或编辑器可靠完成的事情，不另造一层 Peak UI。

03

Context before tools

每个工作区先声明 AI 实际看到什么；回答回到文件，写操作先生成 candidate。

六种文件的产品边界

下面的“不要做”与核心能力同样重要，它们阻止每个文件工作区膨胀成第二套专业软件。

Image

Canvas-first
Core
Crop、Rotate、Resize、Compress / Convert；工具贴近画布与选择。
AI
Describe / OCR、去背景、选区移除或替换、扩图、候选对比。
Reuse
复用 Composer 的图片渲染、选择语义、上下文与候选审阅。
不要做
完整图层系统、滤镜市场、Photoshop 级参数面板。

HTML

Preview-first
Core
Preview / Edit / Split，实时预览，源码高亮，小范围修改。
AI
解释页面、改选中区域、检查交互/脚本/数据持久化风险。
Boundary
本地预览明确隔离脚本；外部操作与持久化需要单独授权。
不要做
默认进入源码、把危险脚本伪装成普通文档交互。

PDF

Read + cite
Core
可靠阅读、缩放、页缩略图、搜索与标注。
AI
摘要、问答、建议问题；每个事实答案携带页码引用并回跳。
Write
原 PDF 默认只读；高亮和回答可 materialize 成带源链接的 Markdown。
不要做
把聊天结果和 PDF 页面割裂，或假装拥有完整 PDF 编辑能力。

Code Source

Focused edit
Core
预览、语法高亮、行号、轻量编辑、Changes diff。
AI
解释选区、提出小补丁、审查当前文件；引用其他 Vault 源文件。
Boundary
运行、测试、构建是独立的授权与环境，不混进文件编辑器。
不要做
Symbols 导航、项目树、调试器或简陋版 IDE。

Obsidian Canvas

Native Canvas
Core
保留原生卡片、文件/media 嵌入、group、edge、selection toolbar、zoom 和 create toolbar。
AI
解释选区邻域、建议缺失连接、从 group 生成 brief。
Write
新节点或新边先以候选状态预览，再写回开放的 Canvas 文件。
不要做
重画一套“类似 Canvas”的节点图产品。

Excalidraw

Native editor
Core
原生选择、shape 工具、属性、library、zoom/pan、arrow binding 和导出。
AI
解释图、从 prompt 生成、改写 label、整理布局。
Integration
Peak Intelligence 是宿主侧栏；场景编辑仍由 Excalidraw 完成。
不要做
用 Peak 自己的画布和属性面板替换 Excalidraw。

Composer 复用合同

六种格式都必须复用

  1. 统一标题栏与 source 状态。
  2. 始终可见的 Intelligence 侧栏。
  3. 明确的 current file / selection context。
  4. 同一套 prompt、模型选择和历史入口。
  5. 写操作统一进入 Accept / Restore / Retry。

格式自己拥有

  1. 主内容 renderer / editor。
  2. 格式原生导航与 selection controls。
  3. 查看、编辑和写回能力边界。
  4. AI 可以引用的 context granularity。
  5. candidate 如何在源表面预览。
状态边界：本页与交互原型是 design reference，不代表 Image / HTML / PDF / Code / Canvas / Excalidraw 已经在生产插件中完整交付。

本轮可审阅产物

优先看六个工作区之间是否像同一个 Peak 产品，同时检查每个原生编辑器是否仍然一眼可识别。
