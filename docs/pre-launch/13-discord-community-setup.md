## 任务目标

建立一个小而清楚的 Peak Assistant Discord 社区，承接公告、安装帮助、问题反馈、使用案例和早期用户交流。首期目标不是营造虚假的“大社区”，而是让新用户知道去哪里开始、在哪里提问，以及谁会处理反馈。

## 1. 建群前决定

- [ ] 确定服务器名称、头像、简介和公开邀请链接。
- [ ] 明确社区语言：英文为主，是否保留中文交流入口。
- [ ] 明确 Owner、管理员和备用管理员账号。
- [ ] 写清这是社区支持入口，不承诺实时客服或固定响应时限。
- [ ] 决定哪些问题留在 Discord，哪些问题应转为 GitHub Issue 或安全私报。
- [ ] 准备隐私、安全、行为规范和举报方式。

## 2. 首期频道结构

频道保持精简，出现真实需求后再拆分：

- [ ] `start-here`：产品简介、安装入口、文档、规则和提问方式。
- [ ] `announcements`：版本、重大修复、已知问题和活动公告，仅管理员发布。
- [ ] `help-and-feedback`：安装、使用问题、Bug 线索和一般反馈。
- [ ] `showcase`：用户分享 Vault 工作流、Graph、Composer、HTML 报告和其他成果。
- [ ] `general`：不适合上述频道的一般讨论。
- [ ] 如中英文消息已经互相干扰，再增加单独的中文频道；不要一开始创建大量空频道。

## 3. 入群与固定内容

- [ ] Welcome 消息说明 Peak Assistant 是什么、当前状态和支持边界。
- [ ] 固定安装文档、README、网站、GitHub、FAQ 和已知问题链接。
- [ ] 提供问题反馈模板：版本、系统、复现步骤、期望结果、实际结果和必要日志。
- [ ] 提醒用户隐藏 API key、Vault 私密内容、个人信息和付费凭证。
- [ ] 提供功能建议模板：用户场景、当前做法、阻塞点和期望结果。
- [ ] 放入两至三个真实示例，避免新成员进入后面对完全空白的社区。

## 4. 权限与治理

- [ ] 默认角色只能在允许的公共频道发言，公告和规则频道限制写入。
- [ ] 禁止 Spam、骚扰、恶意推广、凭证分享和未经同意公开他人 Vault 内容。
- [ ] 明确删除消息、禁言、封禁和申诉规则。
- [ ] 安全漏洞、数据损坏和隐私问题提供非公开报告渠道。
- [ ] 记录管理员交接、服务器所有权和恢复方式。
- [ ] 定期检查失效邀请、异常权限和被滥用的 webhook/bot。

## 5. 首期人工运营

- [ ] Owner 人工查看新消息、回复问题并维护 FAQ。
- [ ] 将可复现 Bug 转成正式修复任务或 GitHub Issue。
- [ ] 将反复出现的安装和理解问题回流 README、文档与 Landing Page。
- [ ] 将优秀案例征得用户许可后再用于网站或宣传。
- [ ] 机器人、自动分流和监控仅在人工工作量明显过高后评估。

## 完成条件

- [ ] Discord 服务器、权限和最小频道结构已经建立。
- [ ] 新用户可以仅依靠 `start-here` 找到安装、文档和反馈入口。
- [ ] 规则、隐私提醒、问题模板和安全私报路径已经发布。
- [ ] 网站、README 和发布帖子使用同一个有效邀请链接。
- [ ] Owner 完成一次普通成员视角的入群和发帖检查。

## 不要做

- 不在没有真实交流量时建立几十个细分频道。
- 不用机器人数量、自动欢迎消息或虚假成员制造社区繁荣感。
- 不把 Discord 当作唯一的正式 Bug、版本或安全记录。
- 不公开转发用户内容、日志或 Vault 截图，除非取得明确许可。
- 不承诺无法持续做到的实时支持。
