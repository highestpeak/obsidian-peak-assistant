## 任务目标

让没有参与开发的人仅依靠公开材料完成核心流程，暴露 owner 已经习惯、但新用户无法理解的问题。

## 1. 选择试用者与环境

- [ ] 选择至少一位没有参与开发的朋友。
- [ ] 尽量使用与 owner 不同的机器或 Obsidian 环境。
- [ ] 使用无私人信息的测试 Vault。
- [ ] 记录系统、Obsidian、插件、Provider 和模型版本。
- [ ] 不提前口头讲解产品结构。

## 2. 准备代表性任务

准备 3–5 个能够代表核心价值的任务，例如：

- [ ] 完成安装和首次配置。
- [ ] 找到一份 Vault 内容并理解相关上下文。
- [ ] 使用 AI 完成一次有来源的工作流。
- [ ] 在 Composer 或 Chat 中继续已有上下文。
- [ ] 找到数据位置、费用或隐私说明。

任务只描述目标，不提示具体按钮和点击路径。

## 3. 观察与记录

- [ ] 第一次成功所需时间。
- [ ] 找不到的入口。
- [ ] 看不懂的概念。
- [ ] 与网站文案不同的实际结果。
- [ ] 错误和放弃点。
- [ ] 是否能从错误中自行恢复。
- [ ] 对隐私和数据位置的疑问。
- [ ] 对 Provider 和费用的疑问。
- [ ] 对可信度和来源证据的疑问。

Owner 尽量不现场指导。一旦必须解释，就把解释内容记录为产品或文档问题。

## 4. 使用后检查网站与文档

- [ ] 试用产品以后再检查网站功能介绍。
- [ ] 检查网站是否夸大或遗漏前提。
- [ ] 检查是否使用了新用户不理解的内部术语。
- [ ] 检查 README 是否足够完成第一次成功。
- [ ] 检查详细文档能否解决真实出现的问题。
- [ ] 让技术读者检查贡献指南是否能找到正确入口。

## 5. 修复与复测

- [ ] 将问题分为 P0、P1、P2 和观察项。
- [ ] P0/P1 问题指定 owner。
- [ ] 修复后由原试用者或另一位新用户复测。
- [ ] 无法立即修复的问题写入公开限制。
- [ ] 不适合首次公开的功能退出发布范围。

## 完成条件

- [ ] 试用者不依赖 owner 口头指导即可完成核心流程。
- [ ] 外部试用暴露的 P0/P1 问题已修复并复测。
- [ ] 网站、README 和详细文档覆盖真实出现的疑问。
- [ ] 未修复问题已经公开降级或退出首次公开版本。

## 不要做

- 不边试用边教点击路径。
- 不只问“你觉得怎么样”，要观察实际任务表现。
- 不让熟悉项目的协作者冒充第一次使用者。
