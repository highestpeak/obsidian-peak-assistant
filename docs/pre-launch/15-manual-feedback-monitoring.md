# 15 · 人工反馈监控与回流

> [返回上线前 TODO](../pre-launch-todo.md)
>
> 优先级：P1 · 持续运营任务
>
> 状态：首期人工执行，暂不建设自动监控系统
>
> 关联任务：[Discord 社区搭建](13-discord-community-setup.md)、[社区与平台发布计划](14-community-launch-distribution.md)

## 任务目标

上线后由 Owner 手动查看各个平台的评论、私信、讨论和 Issue，把分散反馈转成可处理的问题、文档修正、宣传修正或产品输入。首期先验证哪些渠道真的产生有效反馈，再决定是否需要机器人、聚合器或自动提醒。

## 1. 人工巡检范围

- [ ] Discord 的新成员问题、`help-and-feedback`、一般讨论和私信。
- [ ] GitHub Issues、Discussions、Release 评论和相关仓库引用。
- [ ] Obsidian Forum、Discord、插件市场评论或审核反馈。
- [ ] Product Hunt 评论、提问和评价。
- [ ] Dev.to 评论和文章引用。
- [ ] Reddit 帖子评论、相关讨论和必要的私信。
- [ ] 小红书评论、收藏问题、私信和二次讨论。
- [ ] 官网反馈入口、邮件和其他实际发布渠道。

渠道未产生真实信号时可以降低频率，不为了“监控完整”持续消耗时间。

## 2. 建议巡检节奏

- [ ] 发布当天：发布后尽快查看，并在当天至少完成早晚两次汇总。
- [ ] 上线后前三天：每天检查核心渠道并处理阻塞问题。
- [ ] 上线后两周：每一至两天汇总一次。
- [ ] 稳定期：根据真实活跃度调整为每周固定检查。
- [ ] 安全、数据丢失、安装全面失败或严重误导主张不等待固定巡检时间。

## 3. 反馈记录字段

每条值得处理的反馈至少记录：

- [ ] 发现时间、平台、原始链接和必要上下文。
- [ ] 用户场景、原话摘要和可观察问题。
- [ ] 类型：Bug、安装、文档、网站、误导主张、功能建议、性能、安全或正面案例。
- [ ] 严重度、影响范围、是否可复现和是否需要立即回复。
- [ ] Owner 的公开回复和承诺内容。
- [ ] 去向：产品任务、代码修复、文档修正、网站修正、FAQ、Roadmap 候选或不处理。
- [ ] 当前负责人、状态、完成证据和回访结果。

只记录处理问题所需的信息，不复制无关个人资料、私信内容或用户 Vault 数据。

## 4. 分级处理

### 立即处理

- [ ] 安全漏洞、凭证暴露、隐私风险或数据丢失。
- [ ] 大面积无法安装、无法启动或升级损坏。
- [ ] 宣传主张与实际产品存在严重不一致。

### 尽快处理

- [ ] 多名用户重复遇到的核心流程阻塞。
- [ ] README、安装、Provider 配置或权限说明不清。
- [ ] 网站链接、视频或 Discord 邀请失效。
- [ ] 明显影响首次成功体验的性能和交互问题。

### 汇总评估

- [ ] 单个功能建议和替代方案请求。
- [ ] 需要产品取舍、架构变化或长期研究的需求。
- [ ] 暂时无法复现、缺少环境信息或只适用于极少数场景的问题。
- [ ] 正面评价、用户案例和可用于宣传的结果。

## 5. 回复与回流规则

- [ ] 先确认已理解的问题，再说明当前事实、已知限制和下一步。
- [ ] 不在公开回复中承诺未评估的发布日期或功能。
- [ ] 可复现 Bug 建立可追踪任务，并把链接回复给反馈者。
- [ ] 重复问题合并到 FAQ、README、文档或固定回复中。
- [ ] 宣传造成的错误预期优先修正文案，而不是责怪用户误解。
- [ ] 修复完成后回到原讨论更新结果，并感谢提供反馈的人。
- [ ] 使用用户案例、评论截图或姓名前取得明确许可。

## 6. 是否引入自动化的判断

当前保持人工检查。只有出现以下情况时再单独评估自动化：

- [ ] 稳定活跃渠道过多，人工经常漏掉重要反馈。
- [ ] 重复分类和搬运已经明显占用产品开发时间。
- [ ] 平台提供合规、稳定且必要的 API、Webhook 或通知方式。
- [ ] 已经明确自动化产生的数据保存、隐私、权限和删除规则。

自动化只能帮助发现和整理，不能自动替 Owner 公开承诺、争辩、删除评论或发布产品结论。

## 完成条件

- [ ] 已建立一个私有、统一的人工反馈记录入口。
- [ ] 所有实际发布渠道都有巡检频率和 Owner。
- [ ] 严重反馈具有明确升级和私下联系路径。
- [ ] Bug、文档、网站、宣传和产品建议能够进入各自任务系统。
- [ ] 至少完成上线后两周的人工反馈闭环复盘。
- [ ] 已根据真实工作量决定继续人工执行，或另开自动化评估任务。

## 不要做

- 不为了监控而抓取、复制或长期保存不必要的用户数据。
- 不把点赞、投票和浏览量直接等同于产品价值。
- 不删除、掩盖或攻击合理的负面反馈。
- 不在多个平台作出互相冲突的承诺。
- 不让未分类的反馈无限堆积，也不把每个建议自动升级为 Roadmap 承诺。
- 不在缺乏真实需求前提前建设复杂的社区监控系统。
