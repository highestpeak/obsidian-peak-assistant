# 01 · 上线范围与历史任务审计

> 优先级：P0 · 上线闸门
>
> 状态：未开始
>
> 下游任务：[剩余功能完成与 Release Candidate 冻结](16-remaining-feature-closure.md)

## 任务目标

冻结首次公开版本，并把 Roadmap、Codex/Claude session、worktree 和历史待办收敛为一份有明确结论的上线任务集合。

本任务不负责继续实现所有旧需求。调研候选、远期 Backlog、过期方案和已被替代的 session 不会因为“存在记录”就自动进入上线范围。只有被判定进入首次公开版本的事项，才进入后续的剩余功能收口任务。

## 1. 冻结首次公开版本

- [ ] 明确本次是公开 Beta、正式版还是仅邀请试用。
- [ ] 冻结首次公开版本包含的功能清单。
- [ ] 为每项功能写一句对外能力主张。
- [ ] 标出需要联网、Provider API key、付费调用或额外系统依赖的能力。
- [ ] 明确桌面端、移动端、操作系统和 Obsidian 版本支持范围。
- [ ] 明确已知限制、暂不支持的流程和上线后再做的事项。
- [ ] 范围冻结后，除 P0/P1 问题外不再添加新功能。

## 2. 盘点历史任务

- [ ] 盘点 [Roadmap](../roadmap.html) 中所有已决策待建项。
- [ ] 盘点 [Progress Tracker](../progress.md) 中仍写着 pending、未验证或未完成的历史项。
- [ ] 盘点尚未结束的 Codex task 和 Codex session。
- [ ] 盘点尚未结束的 Claude Code session。
- [ ] 盘点隔离 worktree、未合并分支和未提交改动。
- [ ] 检查是否存在只在 worktree 中完成、尚未 cherry-pick 或已经失去 owner 的实现。
- [ ] 检查完成过代码但仍缺真实 Obsidian 交互验收的任务。

## 3. 为每个遗留项做判决

每个遗留项只能进入以下一种状态：

- [ ] 上线阻塞，必须完成。
- [ ] 已实现，只缺 owner 真机验收。
- [ ] 已实现，只缺文档、视频或网站同步。
- [ ] 已被新实现或新产品归属替代。
- [ ] 仅调研，不进入首次公开版本。
- [ ] 重复、失效或不再需要，可以关闭。
- [ ] 需要 owner 决策，暂时不能实施。

## 4. 对外主张检查

- [ ] 网站、README、视频和公开文档只介绍冻结清单中的能力。
- [ ] 每项公开主张都能对应到当前版本中的可达入口。
- [ ] 每项公开主张都有真实验证证据。
- [ ] 无法完成真实验证的能力被移出主宣传路径，或明确标记为 Preview / In development。

## 完成条件

- [ ] 不再存在“看起来没完成，但不知道是否还要做”的 session。
- [ ] 所有 task/worktree 都有明确 owner、状态和下一步。
- [ ] 所有必须完成的剩余功能已经进入统一的收口清单。
- [ ] 首次公开版本的功能、平台和限制已经冻结。
- [ ] Researching 和远期 Backlog 没有被误当成上线承诺。

## 不要做

- 不为了关闭数字而继续实现所有历史任务。
- 不根据旧 Progress 条目推断当前产品状态。
- 不把 source、build、mock 或 simulator 证据升级成真实用户验收。
