# 03 · 公开仓库边界与英文化

> [返回上线前 TODO](../pre-launch-todo.md)
>
> 优先级：P0 · 上线闸门
>
> 状态：未开始

## 任务目标

把 owner 私有历史与对外发布内容分离，并确保产品默认公开语言为英文，同时保留真正的多语言处理能力。

## 1. 盘点当前文档

- [ ] 将当前 `docs/` 内容分别标为公开、私有、历史、过期或待重写。
- [ ] 标出 Codex/Claude handoff。
- [ ] 标出内部审计和产品决策记录。
- [ ] 标出个人计划和历史 session。
- [ ] 标出仍可转化为公开说明的技术真值。
- [ ] 选择一个新的公开文档目录，从公开读者需求重新组织内容。

## 2. 建立公开边界

- [ ] GitHub Pages 不再把读者导向私有 `docs/`。
- [ ] README 和仓库链接不再把读者导向私有 `docs/`。
- [ ] release artifact 不包含内部文档、fixture、日志或本地数据。
- [ ] 在删除或迁移当前 `docs/` 前保留可靠的私有备份。
- [ ] 公开前将本组临时清单移入私有工作区，或从公开发布快照排除。

## 3. 检查 Git 历史

仅从当前目录删除文件不会清除 Git 历史。公开前必须选择一种方案：

- [ ] 保留现有私有仓库，创建干净的公开仓库或发布快照。
- [ ] 对现有仓库执行经过审查的历史清理。
- [ ] 证明历史内容可以公开，因此只调整当前目录和发布内容。

选择方案后还要验证：

- [ ] Git 历史中不存在凭证、私人 Vault 内容和不应公开的内部资料。
- [ ] 发布 tag 与 source archive 不会重新带出已排除内容。
- [ ] GitHub Pages artifact 只包含明确批准的静态站点内容。

## 4. 英文化范围

以下内容必须使用英文正稿：

- [ ] 产品 UI、命令、Notice 和错误信息。
- [ ] Settings、空状态和错误恢复文案。
- [ ] 默认模板和演示数据。
- [ ] README、公开文档和网站。
- [ ] 视频字幕和公开截图中的文字。
- [ ] 配置、Provider、隐私和贡献说明。

## 5. 有意保留的非英文内容

以下内容不能为了“源码零中文”而盲目删除：

- [ ] 多语言搜索规则。
- [ ] 语言检测和中文处理规则。
- [ ] 明确用于国际化能力的测试 fixture。
- [ ] 用户自己的 Vault 内容和迁移样例。
- [ ] 保留在私有空间的 owner 工作文档。

## 6. 扫描与 allowlist

- [ ] 对公开代码、模板、网站和文档执行中文扫描。
- [ ] 将每个合理保留的命中加入小型 allowlist。
- [ ] 为每个 allowlist 条目说明功能性理由。
- [ ] 复查截图、视频、图片 metadata 和示例文件中的文字。
- [ ] 复查生成产物、压缩包和 source archive。

## 完成条件

- [ ] 公开仓库、Git 历史、Pages 站点和发布包不存在不应公开的材料。
- [ ] 新公开文档目录只包含用户、贡献者和维护者需要的内容。
- [ ] 产品默认公开语言为英文。
- [ ] 多语言能力没有被错误删除。

## 不要做

- 不在没有备份和历史方案时直接删除私有 `docs/`。
- 不把“当前文件不可见”当成“Git 历史不可见”。
- 不为了源码零中文而破坏中文搜索和语言检测。
