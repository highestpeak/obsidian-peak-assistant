## 任务目标

在 Dev.to、Obsidian 社区、Product Hunt、小红书、Reddit 等社区和平台发布 Peak Assistant。所有渠道共享同一套事实、截图和链接，但根据社区语境分别写作，不进行机械复制粘贴或无关群发。

## 1. 发布母包

先建立一套可复用但不是直接群发的内容母包：

- [ ] 一句话定位和一段简短介绍。
- [ ] “自己使用半年、持续演进、朋友建议公开”的真实产品故事。
- [ ] Peak Assistant 如何帮助 Owner 使用并 sharpen AI coding 能力的个人视角。
- [ ] 三至五个已经上线且有证据的核心功能。
- [ ] 一段诚实说明：当前状态、安装方式、限制、AI Provider 成本和支持边界。
- [ ] 网站、README、GitHub、安装、文档和 Discord 的统一链接。
- [ ] 真实截图、短视频、Logo、封面图和必要尺寸变体。
- [ ] 常见问题、简短回复模板和已知问题。
- [ ] 发布版本号、发布日期和素材对应的构建版本。

## 2. 渠道清单与原生角度

### Dev.to

- [ ] 以 build story、技术复盘或实际工作流为主，不只发布广告。
- [ ] 说明为什么做、半年使用中的演进、架构选择和学到的 AI coding 方法。
- [ ] 使用真实 GIF、截图、代码库或文档入口支撑叙事。
- [ ] 根据平台当前规则检查标签、自我推广和重复内容要求。

### Obsidian 社区

- [ ] 分别确认官方 Forum、Discord 和插件市场允许的发布位置与格式。
- [ ] 聚焦 Obsidian 用户的真实问题：Vault 搜索、Graph、Composer、文件工作区和本地知识流。
- [ ] 明确插件状态、安装路径、桌面端限制和与 Obsidian 原生能力的关系。
- [ ] 尊重社区的自我推广、测试版和插件审核规则。

### Product Hunt

- [ ] 准备 Tagline、Description、Gallery、Demo、Maker Comment 和首条讨论回复。
- [ ] Product Hunt 页面、官网和 GitHub 使用同一版本与核心主张。
- [ ] 提前检查产品名称、分类、发布时间、账号和素材尺寸。
- [ ] 发布当天安排人工回复，不购买虚假投票或进行误导性拉票。

### Reddit

- [ ] 选择真正相关的 subreddit，并逐个阅读当前规则和既有讨论风格。
- [ ] 使用问题、经验复盘或真实 demo 开始讨论，清楚披露自己是作者。
- [ ] 不向多个 subreddit 同时投放完全相同的广告文本。
- [ ] 接受质疑并直接说明限制，不与负面反馈争辩或删改事实。

### 小红书

- [ ] 使用中文、封面图、短视频或连续截图讲清具体使用场景。
- [ ] 优先使用“我为什么做、我如何实际使用、前后对比”的个人叙事。
- [ ] 避免空泛的效率神器和绝对化 AI 宣传。
- [ ] 检查当前平台规则、外链限制、标签和评论区引导方式。

### 其他候选渠道

- [ ] GitHub Release、README 和 Discussions。
- [ ] Hacker News、Indie Hackers 或相关开发者论坛。
- [ ] AI coding、PKM、local-first 和知识管理社区。
- [ ] 个人博客、朋友网络和已有社交账号。
- [ ] 只在受众和内容真正匹配时加入，不以渠道数量作为成功指标。

## 3. 渠道记录表

每个渠道都要记录：

- [ ] 平台、社区和具体版块。
- [ ] 目标受众与该渠道的内容角度。
- [ ] 当前发布规则、自我推广限制和允许格式。
- [ ] 内容负责人、素材负责人和回复负责人。
- [ ] 草稿、审核、计划时间、实际时间和状态。
- [ ] 使用的标题、封面、视频、CTA 和落地页。
- [ ] 最终帖子 URL。
- [ ] 后续更新、编辑或二次发布条件。

## 4. 发布节奏

- [ ] 上线前完成账号、规则、草稿、素材和链接检查。
- [ ] 先选择两至三个最匹配的核心渠道，不要求同一天覆盖全部平台。
- [ ] Product Hunt 等集中发布渠道安排明确的 launch day。
- [ ] 长文、技术复盘和中文内容可以错峰发布，延长真实讨论周期。
- [ ] 根据前一批反馈修正后续文案，而不是一次性把所有帖子发完。
- [ ] 每次发布后进入[人工反馈监控](15-manual-feedback-monitoring.md)。

## 5. 发布前检查

- [ ] 所有功能主张与最终 Release Candidate 一致。
- [ ] 图片和视频不包含私有 Vault、账号、API key 或第三方敏感信息。
- [ ] 链接、安装步骤、Discord 邀请和文档入口真实可用。
- [ ] 明确披露作者身份、产品状态和必要商业关系。
- [ ] 不同渠道的标题和正文符合当地语言和社区习惯。
- [ ] 每个渠道都有人在发布后查看并回复。

## 完成条件

- [ ] 已建立渠道矩阵和分批发布排期。
- [ ] 每个首发渠道都有原生草稿、合规检查和对应素材。
- [ ] 核心渠道帖子已经发布并记录真实 URL。
- [ ] 所有公开帖子使用同一个版本真值且没有过度主张。
- [ ] 反馈已经进入统一的人工监控与回流任务。

## 不要做

- 不把同一段广告原样复制到大量社区。
- 不在不了解社区规则时直接发布或跨版刷屏。
- 不隐藏自己是作者，也不伪装成普通用户推荐。
- 不购买虚假投票、评论、成员或互动。
- 不用 mock、roadmap 或未来功能支撑当前时态宣传。
- 不只统计曝光和点赞，忽略安装成功、持续使用和真实反馈。
