三栏模型：一个工作面，两个共享 store

Chat Studio 不是把三个独立页面拼到一起。它在一个 Studio leaf 中并排渲染项目列表、完整 ChatView 和会话索引；三栏都读同一份 chatDataStore，中栏还读 chatViewStore 来决定目前是 Home、项目页还是会话线程。

共享状态、窗口与尺寸

打开 Studio命令先复用现有 Chat leaf；没有时创建 tab。它替换为 Studio view，卸下旧项目栏与旧会话索引 leaf，再尝试移到独立窗口；不支持 popout 时留在 tab。workspace lifecycle
默认宽度左栏默认 280px，可拖到 200–500px；右栏默认 320px，可拖到 240–480px；中栏占用剩余宽度。local only
选择同步左栏的项目 / 会话点击更新 active selection 并发出选择事件；中栏读取会话、同步 messages；右栏重新由 messages 生成时间线与 artifacts。single source of truth
宽度的边界左右拖拽宽度只存在 Studio 组件的本地 state；重新挂载后恢复默认值，不能当作持久的用户工作区偏好。not persisted

左栏：先确定工作范围，再进入一段对话

左栏复用 ProjectListViewComponent 的非 compact 版本。因此它承担的是项目导航与会话历史的混合职责，而不是一个纯粹的“聊天列表”。

顶部品牌与工具栏当前顺序是产品标识 → Home、Refresh、Collapse all → 单独的 “Find chat or project” 搜索行。Home 把中栏切回 Chat 首页；Refresh 重新加载项目和会话并清空展开状态；Collapse all 收起所有项目树。
搜索搜索条件只保存在左栏本地，按名称过滤 Projects 和 Conversations 两个区块。它不查消息正文、不跨会话、不查 Vault，也没有“只搜项目 / 只搜会话”的范围切换。
Projects 区块项目按新近程度排序。点项目行会展开 / 收起；展开时加载该项目的会话，并在首次展开时让中栏进入项目概览。项目下有 “New conversation” 和超出展示上限后的 “See more”。
项目操作项目右键菜单可改名或删除。删除后从共享项目 map 中移除；如果它正是 active project，active project 被清空。这里没有独立确认页，交互发生在上下文菜单。
会话行无论会话属于项目还是独立存在，点选后都会成为 active conversation，导航层把中栏切到对应会话。新建项目内会话会带着该项目；独立会话不带 projectId。
会话菜单会话可改名、打开源 Markdown、删除。删除当前会话时 active conversation 会被清空；因此中栏随后进入无 active 或 pending 的状态，而不是保留一份失效消息副本。
目标稿 · 查看全部最近区的“查看全部”打开独立标题 Picker，并按生产已有的 chat / agent / plan / canvas / template / custom 会话类型过滤。标题与类型使用 AND 语义；项目归属、主题 icon 和单轮 / 工作流都不是会话类型。重复会话去重，置顶 HTML 设计文档不混进结果，重新打开恢复“全部”。
左栏的用户任务它回答的是“我要在哪个工作容器继续、或者找回哪段历史”，不是“我该如何发送一句话”。如果后续视觉想极简，仍需保留项目容器和独立会话两种语义的可辨识性。

中栏：不是一块固定聊天记录，而是一台 Chat 路由器

中栏复用完整 ChatViewComponent。用户看到同一块区域，但 viewMode 会替换其内容；这既让功能完整，也让“我现在还在聊天吗”成为一个真实的 UX 问题。

Home继续最近对话、总结笔记、研究主题，以及最近会话和项目入口。
All projects浏览全部项目，而不是显示消息线程。
All conversations在中栏查看更完整的会话列表。
Project overviewProjectOverviewViewComponent 显示可编辑说明、对话数 / 消息数 / 收藏数 / 资源数，并切换 Conversations、Starred Messages、Resources；当前生产没有 Plans tab。
Project conversations项目内历史超出侧栏展示时的完整列表。
Pending / active新会话的启动面，或真正的当前会话线程：Header、消息、建议和 Composer。

当前会话线程的元素与交互

Header显示会话标题。有源 Markdown 时可打开源文件；Refresh 触发标题重生成。删除不在 Header，而在左栏会话菜单，避免从正在阅读的内容面直接触发高影响操作。thread identity
滚动消息体切换 active conversation 时同步消息数组，进入时滚到底。流式文本、reasoning 与工具调用改变时，自动滚动帮助用户继续阅读；日期分隔把跨天消息分组。reading continuity
用户消息以用户身份、时间、Markdown 正文、附件簇和发送状态呈现。附件仍属于产生它的消息，而非进入右栏的独立文件表。input record
助手消息富 Markdown / 代码可流式渲染；reasoning 可折叠；工具调用显示摘要；消息头显示工具数、token 数与耗时。最后一条正常回复可出现 capability suggestion 和建议追问。run result
PermissionAskCardHarness 遇到 kind:'edit' 的工具（MCP mutating、media_generate 等）时 PermissionGuard 走 ask 分支。消息里 inline 渲染 PermissionAskCard，展示工具名、参数摘要与 Allow / Deny；同时消息状态行覆盖 waiting-permission。用户决定后 loop 从挂起恢复；abort 期间未回答的 ask 记为 cancelled。双向挂起
成本确认卡视频 / 音乐 fal async job 在扣费前先落 awaiting-confirmation receipt，卡片显示真实 route / model / duration / 估算费用与 Confirm / Cancel。permission ask 与成本确认是两道独立的门，不合并为一次交互。video / music 前置
ArtifactReceiptCard 媒体态persist 的 ChatArtifactReceipt 按状态渲染：generating（spinner）/ saved（tooltip 显示 vaultPath）/ failed（错误消息 + Retry）/ needs-configuration（Configure 跳 configureAction tab）；成功态才解析 URI 渲染 preview，失败不会伪装 ready。media receipt
Agent Run 时间线ToolCallSummary 从 debugRun.spans + toolCalls 派生，AgentStepRow 展示 running / failed / completed / cancelled 与每步 duration / error。所有 chat turn 走同一个 Harness runtime，fixture-driven 假 spinner 已经不再存在。real steps
消息操作当前生产提供 Copy、Regenerate、Star、Branch、Copy trace；MessageMorePopover 提供 View raw、复制 Markdown / JSON、保存到 Vault、Reply inline 与可选 Delete。目标稿不让三点永久占位：核心五项始终保留，自适应动作按定向追问、保存、原始消息、Markdown、JSON 的优先级尽量展开，空间不足才反向收入 More；菜单只显示当前隐藏项。保存默认目录为 Peak Chat Saves，可由文案配置改变。reuse / audit
Suggested nextMessageSuggestedNext 默认显示前 2 条建议，其余进入 More；More 还包含 Rewrite simply、Create checklist、Save to Note / Vault 和 Ask Custom。目标稿会复用主 Composer，而不是生成第二个输入框。continue / transform
项目主页ProjectOverviewViewComponent 已有可编辑项目说明、Conversations、Starred Messages 与 Resources；目标稿额外提出 Plans，并保留完整项目主页结构，只把四格统计容器、Tabs 与列表间距压缩。目标稿不在 Hero 放置脱节的“编辑说明”按钮，而把说明文本本身作为就地编辑入口；AI 改写只产出可检查草稿，必须人工保存。同一个 Composer 内联到项目摘要之后、集合导航之前，并沿用“短问候 + 三个项目化起点”的新对话心智。项目主页没有当前会话，因此不显示右侧 Conversation Index；进入具体会话后 Composer 才回到底部、右栏才恢复。Plans 仍不是当前生产既有能力。compact project scope
转项目建议独立会话出现持续工作信号时，中栏能提出转换为项目的建议；它是“临时问答”转向“长期工作容器”的连接点。organization

Composer：把每次运行的输入、上下文与生成入口放在同一个工作面

Composer 使用 PromptInput 管理文字与附件；它不是另一个 chat mode 选择器。用户从这里写内容、加材料、查看当前模型 / context 摘要，启用工具上下文，从 + 打开资源三项，或从 / slash 打开 workflow + 生成动作。它在新对话与项目主页中靠近页面起点，在具体会话中才固定到消息体下方。

目标稿 · 新对话起点空态以 今天想推进什么？ 的短问候开始，接一行范围说明、居中的共享 Composer 和最多三个知识工作建议：继续最近工作、总结最近笔记、查找相关材料。点击建议只填入可编辑草稿，不自动发送；用户开始输入后建议退场。
文本与键盘输入内容成为本轮 user message。提交开始后，文字和附件会清空；有文字时发送按钮出现。流式中发送位变为停止按钮，旁边显示 “Planning and writing…” 的可访问状态。
入口语义：+ / / / [[+ 只承担资源三项：Files & images、Vault document、Link；生成动作全部迁走。/ slash 是动作面，含 WORKFLOW 组（Plan 单一命令）与 GENERATE 组（Image / Image edit / Video / Music / Document）。[[ Vault refs 与 @（保留未占用）不变。任一入口下的项按 ToolAvailability 门控：available 可点，unconfigured / unsupported / disconnected / permission-required 显示逐项原因并禁用，行末 Configure 按钮按 configureAction 跳 Media Generation / Profiles / MCP / Permissions tab。
Generate 表单点开某个 Generate 项后由 ComposerGenerateActions.tsx 展开 inline 表单：route（Auto / Native / fal）、model、数量（image）、宽高比（image）、duration（video / music，config 上限）、preflight 估算费用。Image edit 表单额外要求用户显式选择基图（来自会话附件或已生成图片）与可选 mask——system 不隐式推断；未提供基图时提交按钮禁用。视频、音乐、Sora native 提交后先落 awaiting-confirmation receipt，扣费前需二次确认。
Run chip 与 sources触发器显示当前模型（或 Auto）与 context tag 数。弹层包含 role、模型路由摘要、Vault Search 与 Web Search；后两者是真实开关，且从 ChatRuntimeStatePort.isVaultSearchAvailable 拿真值——不再硬编码"vault 恒可用"。requested vs actual sources 分别持久化到 composerStore，receipt 记 actualSources。
可见控件的真实边界role 选择只保留在 Composer 本地，尚未进入 message dispatch；模型行显示的是当前路由摘要，不是模型选择器；麦克风始终 disabled。UI 设计不能把这三项当成已完成的运行能力。

Assistant Builder：Advanced 区、完整生命周期与 ephemeral Preview

Assistant 定义不只是 name + instructions。Builder 的 Advanced 区、完整生命周期与 Preview 语义在 src/service/chat/assistant/ 与 src/ui/view/settings/ 里，Chat Composer 顶栏 Assistant picker 只是消费端。

Advanced 区Advanced 面板暴露 knowledgeRefs（explicit refs 流，被 TurnExecutionReceipt.actualSources.explicitRefsUsed 记为被真正 consulted 的 ref）、toolPolicy（allow + deny 列表，与 PermissionGuard 联动）、preferredModel（覆盖 profile 默认，仍经 modelRouter 能力过滤）。instructions 走 AssistantSlot priority 900 进 system prompt，是唯一路径——不由 Composer 或 UI 层拼进 user prompt。
生命周期Builder 支持 create / edit / duplicate / archive+restore / delete / reset defaults 六种操作；archive 是软删（可 restore），delete 是硬删（不可恢复）。持久化在 settings，与 profile 分开。
Preview = ephemeral apply-without-savingPreview 按钮把当前编辑草稿注册进 EphemeralAssistantRegistry——内存级，resolver 优先命中，reload 后消失。selector 显 "Preview" 徽标提醒；Save 才把草稿写入持久化 registry。这允许试用尚未成型的 assistant 而不污染定义列表。
Preview 边界Preview assistant 只影响本会话本 turn 的 assistant resolver 结果；跨会话切换或重开 Chat 后 ephemeral 记录不会自动携带。这个语义已锁在 test/assistant-builder-lifecycle.test.ts；owner 侧 Obsidian 内的完整生命周期人工回归尚未跑（credential-blocked 影响真实 turn 效果观察）。

消息动作：registry、Retry variant、Branch、permission 三态

消息级动作不是 MessageMorePopover 里 hardcode 的列表。核心 5 项走 registry 优先级永远保留 inline，其余按空间自适应；不足时反向收进 More。

核心 5 项永久 inlineCopy / Regenerate / Star / Branch / Copy trace 由 messageActionRegistry priority 最高，即使 More 打开也不进溢出——避免高频动作被隐藏。空间不足时反向优先级低的动作先进 More。
Trace 打开真实 AgentTraceTrace 动作按 debugRunId 打开真实 AgentTrace 面板，展示 spans 树、每步 duration 与 error；无 debugRunId 时降级为 copy JSON。runId = debugRunId = TurnExecutionReceipt.runId，可跨 UI / trace / receipt 串起。
Retry → variant ‹N/M› 切换器Retry 一条助手消息不覆盖旧内容，而是新增带 variantGroupId + variantIndex + isActiveVariant=true 的 message；旧同组翻 false。UI 上助手消息头部出 ‹N/M› 切换器，切换只翻转 active 标记不复制上下文。history 只取 active variant，见 Chat Context §Variant 与 Branch。
Branch → 新 conversation + "Branched from" 链回Branch 从某条消息分叉时新建 conversation 带 parentConversationId + parentMessageId；新会话顶部显示 "Branched from …" 链，点回可切到父 conversation。model 请求不合并两条线——branch 是"从这里起独立试一条思路"，不是并行分支。
PermissionAskCard 三按钮MCP mutating 工具 / media_generate 等 kind:'edit' 工具触发时，消息 inline 渲染 PermissionAskCard 三按钮：Deny / Allow once / Allow for this run；消息状态行覆盖 waiting-permission。Allow for run 的 run 级 allowlist 目前只在 useStreamChat 层强制（下一波下沉 harness 与 deny 语义对齐），是当前实现的收窄点。
More 与保存MessageMorePopover 承担 View raw、Copy Markdown / JSON、Save to Vault、Reply inline 与可选 Delete；保存默认 Peak Chat Saves（可由文案配置覆盖）。Suggested next 顶部 ≤2 条只填 Composer，其余进 More；targeted follow-up 复用主 Composer reply anchor，不生成第二个输入框。

媒体产物 UI：batch gallery、insert-as-reference、music terms

Chat 内媒体产物由 ArtifactReceiptCard 按状态渲染六态；batch 多输出与 music licensing 确认是本轮新增的重点。

Batch 多输出 gallery + lightboxOpenAI / fal 一次生成多张图时，每张落 N 条独立 ChatArtifactReceipt，UI 组成 batch gallery；点击任一图打开 lightbox 全屏预览（ownerDocument 感知，在 detached popout 内也定位到正确窗口）。lightbox 关闭键盘可达。
Insert as referenceSaved receipt 卡上有 "Insert as reference" 动作，把这张图作为下一次 / Image edit 的基图挂入 Composer 附件区（走同一 MediaReferenceResolver 稳定引用，不复制字节）。这是 edit 迭代的官方路径——不用手动把图存下来再拖回来。
Music terms 首次确认音乐生成第一次 Confirm 前，ArtifactReceiptCard 出 licensing checkbox（Lyria SynthID 水印 + 分发平台 AI 披露 + USCO 版权口径 + fal ToS 链接）。确认写 settings.ai.mediaDefaults.musicLicensingAccepted（含 policyVersion + confirmedAt）+ 该 receipt 上；后续 music 请求不再重复弹窗，除非 policy version 变。
ArtifactReceiptCard 六态generating（spinner）/ awaiting-confirmation（成本卡 + Confirm / Cancel）/ saved（tooltip 显示 vaultPath，成功态才解析 URI 渲染 preview）/ failed（错误消息 + Retry）/ cancelled（+ Retry）/ needs-configuration（Configure 跳 configureAction tab）。失败态禁止伪装 ready；permission ask 与成本确认是两道独立的门。

结构化产物：5 类 artifact 的 Chat 内闭环

Chat 除了图片 / 音视频，还能通过 artifact_create ToolDef 产 5 类结构化产物；每一类都由 producer 校验、写盘、生成 ChatArtifactReceipt，被 Resources / Outline 认得。

Dataviewartifact_create(kind='dataview') producer 校验 DQL dataview fence 有效性，写 .md 到 ChatFolder/Artifacts/Dataview/（AI_PATH_SUBFOLDERS.ArtifactsDataview），Open in Obsidian 直接生效。schema 与校验规则在 templates/config/artifact-create.json。
Excalidraw / drawioartifact_create(kind='drawing') 分流：Excalidraw producer 输出有效 .excalidraw.md 到 ChatFolder/Artifacts/Excalidraw/；drawio producer 输出有效 XML 到 ChatFolder/Artifacts/DrawIO/。Obsidian 打开可编辑；任一 schema / 写盘 / validate 失败渲染 failed receipt，保留原始 content 支持 retry，不静默丢。
Extractartifact_create(kind='extract') 从用户显式授权的 message / ref 生成 Markdown note，保留来源链接；写 ChatFolder/Artifacts/Extracts/。receipt kind extract 被 Resources / Outline 认。
Reminder + schedulerartifact_create(kind='reminder') 写 frontmatter（title / due / source / status）到 ChatFolder/Artifacts/Reminders/。ReminderSchedulerService 到期弹 Obsidian Notice，原位把文件 frontmatter status 从 pending 翻为 done，用户可继续编辑同一文件。
Kind='edit' 走 PermissionGuard所有 artifact_create 调用都标 kind:'edit'，因此第一次运行会触发 PermissionAskCard；用户 Allow for run 后本 run 内后续 producer 直通。receipt kind 扩展 dataview / extract / reminder，Resources 分组、Outline 归类、gallery 索引都认。
诚实边界15 场景由 test/artifact-create-producers.test.ts + test/reminder-scheduler.test.ts 锁定 producer 行为、schema 校验、失败回退与 scheduler 到期触发。Obsidian 内 5 类 producer 与 scheduler 的实机人工验收尚未跑——凭据不阻塞，是 Track 8 遗留的 10 条人工矩阵之一，见checklist 相关段。

Detached 窗口与 A11y：已落地面 + 未竟的人工矩阵

Chat Studio 支持在 Obsidian popout 独立窗口里运行，因此 UI 层必须严格用 ownerDocument 而不是 document——否则 lightbox、drop zone、focus 会全定位到主窗口。本轮把这条纪律落到 hook + 组件。

ownerDocument 纪律useOwnerWindow hook + 9 处 ownerDocument 修复覆盖键盘监听、drag/drop、confirm dialog、lightbox 定位、scroll-spy re-observe。任何新组件访问 document / window 都必须切成 ownerDocument。
Splitter 与 NavRow 键盘化三栏 splitter 加 role='separator' + aria-valuenow + Home/End/Enter reset；NavRow 完整键盘化（左右方向 + Enter），不再只依赖鼠标。
msg-list live region消息列表容器加 role='log' + aria-live='polite'，让屏幕阅读器在流式 append 时能宣告新片段，而不是保持沉默。
图片布局分档batch 多图 gallery 走纯函数分档规则（1 / 2 / 3+ 图不同布局），配合 lightbox；分档规则可测，不再随消息数量随机浮动。
诚实边界：人工矩阵未跑下面 4 项属于 Track 8 遗留的 10 条人工矩阵，代码已 pass 相关自动测试（test/a11y-structure.test.ts 等），但在 Obsidian 内的真人回归尚未完成：detached popout 键盘全流程、light / dark 双主题、894 / 1440 视口 + 125% zoom、VoiceOver。在这些矩阵跑完之前，A11y / detached 面的完整验收状态是部分待人工矩阵。

右栏：从“当前会话”提取一份可回跳的索引

右栏不是第二个聊天记录，也不是一个文件管理器。它只读当前会话的 messages，并把“消息顺序、topic、资源和代码 fence”压缩成可定位的导航结构。

顶部与搜索Studio 的非 compact 版本显示 Conversation Index 标题、当前 tab 的搜索输入和 ⌘K 提示。搜索只作用于内存中的当前时间线或 artifact 名，不会查询其他会话或 Vault。
Overview tab相邻、同名的 message.topic 被折为一个可开合 topic block；无 topic 的消息保持独立。第一组默认展开，topic 内的消息与 artifacts 按发生位置交错排列。
Artifacts tab将资源和 Markdown code fence 推导成 Images、Diagrams、Files、Code 四组。代码块因此也会成为 artifact；这里的“产物”比“已保存文件”更宽。
Resources 面板从持久化的 chat_artifact_receipt 表读取，按方向（用户上传 / 助手产物）与类型（image / audio / video / music / file / code）筛选，可回跳到源 message。视频与音乐使用独立的 mediaKind 语义，不与 TTS 合并。
点击行为消息行和 artifact 行都会平滑滚动到中栏的源消息。artifact 不直接打开或预览文件；它的职责是解释“这一项来自哪一次对话”，不是对文件做管理。
右栏的正确命名它更接近 conversation recall / navigation index，而不是 Workspace、Library 或 Assets 面板。目标稿只在存在当前会话时显示；项目主页已经在中栏拥有对话、收藏、资源和计划，不再复制一套右栏目录。后续如果要做真正的 artifact 工作区，需要另建保存、打开、版本和文件归属的能力合同。

体验边界：后续重构不应掩盖的事实

下面不是视觉偏好清单，而是当前功能结构带来的 UX 约束。它们决定三栏为什么显得杂，以及视觉设计需要先解决哪一种语义冲突。

品牌与对象竞争Studio 已经是独立工作面，左栏却仍展示产品标识和一组全局工具。用户进入会话前先看到产品身份，而非当前项目或当前线程。
项目与会话混合导航Projects 是长期容器，Conversations 是线程历史；它们共用搜索、排序和选中态，却没有明确的范围模型。项目展开会再次出现会话层级。
中栏状态切换中心区既是聊天线程，又会变成 Home、项目概览和列表。功能完整，但它不是单一稳定的阅读面，这会影响标题、Composer 和右栏在各状态下应否出现。
控件与能力不完全一致Vault/Web 为真实开关；role、模型行、麦克风则没有相同的执行效力。任何新 UI 应用“可操作、可解释、不可用”三种清晰状态，而不是混在一个弹层里。
Artifacts 的名称风险右栏把附件和代码 fence 都称为 artifact，但点击只回跳消息。若想让它成为产物库，需先补齐保存、打开、预览与生命周期，而不是仅改变视觉层级。
窗口偏好不可持久栏宽和 popout 都是当次 UI 状态。把 Studio 设计成长期高频工作台前，需要决定是否保存布局、是否允许折叠、窄宽度时如何给中栏保留优先级。
媒体生成的诚实边界image generate / image edit（含 mask）/ video（fal + Sora native）/ music 与音视频附件理解的代码链路全量落地并锁在测试里：MediaGenerationRequest.operation='edit' + MediaReferenceResolver、OpenAINativeVideoAdapter（Sora /v1/videos submit/poll/download）、fal edit codec（nano-banana/edit / flux-pro/v1/fill）、OpenAITranscriptionAdapter（whisper-1）、WebAudioVideoAudioExtractor。Usage Dashboard 已加 "Media generation · run detail" 恒标 estimated；music licensing 首次确认写 policyVersion + confirmedAt；Settings 已加 route×kind×operation 能力矩阵与 Validate 按钮。凭据阻塞未跑：fal 付费 edit / video / music，OpenAI 付费 image generate / edit / Sora / whisper-1，MEDIA-04 九步实机——见 checklist §5.5。未配置 provider 时 / slash Generate 组诚实禁用并给出逐路由原因。
做视觉方案前的产品选择先决定中栏的主对象是“一个会话线程”，还是“项目中的 AI 工作台”。当前左栏偏项目容器、右栏偏线程回忆，而中栏在两者之间切换；这个选择不明确，换皮很难真正减少杂乱感。
