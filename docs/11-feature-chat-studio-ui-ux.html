11A · Feature Detail · Chat Studio UI/UX

Chat Studio 的任务，是把“找会话、做工作、回看结果”变成一条连续路径。

这份文档只解释当前 Chat Studio 的 UI/UX：左、中、右三栏各有何种元素、用户点下去发生什么、三栏怎样共享状态，以及哪些可见控件还不代表真实能力。Context 如何进入模型请求，仍以 11 · Chat Context 为准。

先分清：当前实现、讨论结论与目标交互稿

本页继续作为当前生产 Chat Studio 的功能地图。2026-07-13 至 07-14 的 owner 反馈已经单独整理，不会把设计提案倒写成现成功能。

权威实施规格Chat Studio 完整实施规格是目标行为、数据契约、实施 DAG 和验收的唯一权威；本页任何目标性描述若与其冲突，以该规格为准。
讨论总图Chat Studio UI/UX 讨论总图按左栏、中栏、Composer、右栏、Search 与运行时边界汇总了已确认、已否定和待定结论。
产品论证产品定位与 Composer V2保留定位、竞品与设计理由，已经吸收到权威实施规格，不再单独定义目标行为。
可交互提案三栏 HTML mock和 Composer Lab用于验证信息层级与状态，不替代源码事实。
已锁定方向不展示 Peak 品牌头；保留紧凑三栏；中栏与 Composer 是主工作面；Quick Search 仍由原生 surface 拥有；模型、Assistant、工作流、来源和附件各有唯一入口；任何未被运行时消费的控件都只能标为 proposal。

三栏模型：一个工作面，两个共享 store

Chat Studio 不是把三个独立页面拼到一起。它在一个 Studio leaf 中并排渲染项目列表、完整 ChatView 和会话索引；三栏都读同一份 chatDataStore，中栏还读 chatViewStore 来决定目前是 Home、项目页还是会话线程。

共享状态、窗口与尺寸

打开 Studio命令先复用现有 Chat leaf；没有时创建 tab。它替换为 Studio view，卸下旧项目栏与旧会话索引 leaf，再尝试移到独立窗口；不支持 popout 时留在 tab。workspace lifecycle
默认宽度左栏默认 280px，可拖到 200–500px；右栏默认 320px，可拖到 240–480px；中栏占用剩余宽度。local only
选择同步左栏的项目 / 会话点击更新 active selection 并发出选择事件；中栏读取会话、同步 messages；右栏重新由 messages 生成时间线与 artifacts。single source of truth
宽度的边界左右拖拽宽度只存在 Studio 组件的本地 state；重新挂载后恢复默认值，不能当作持久的用户工作区偏好。not persisted

左栏：先确定工作范围，再进入一段对话

左栏复用 ProjectListViewComponent 的非 compact 版本。因此它承担的是项目导航与会话历史的混合职责，而不是一个纯粹的“聊天列表”。

顶部品牌与工具栏当前顺序是产品标识 → Home、Refresh、Collapse all → 单独的 “Find chat or project” 搜索行。Home 把中栏切回 Chat 首页；Refresh 重新加载项目和会话并清空展开状态；Collapse all 收起所有项目树。
搜索搜索条件只保存在左栏本地，按名称过滤 Projects 和 Conversations 两个区块。它不查消息正文、不跨会话、不查 Vault，也没有“只搜项目 / 只搜会话”的范围切换。
Projects 区块项目按新近程度排序。点项目行会展开 / 收起；展开时加载该项目的会话，并在首次展开时让中栏进入项目概览。项目下有 “New conversation” 和超出展示上限后的 “See more”。
项目操作项目右键菜单可改名或删除。删除后从共享项目 map 中移除；如果它正是 active project，active project 被清空。这里没有独立确认页，交互发生在上下文菜单。
会话行无论会话属于项目还是独立存在，点选后都会成为 active conversation，导航层把中栏切到对应会话。新建项目内会话会带着该项目；独立会话不带 projectId。
会话菜单会话可改名、打开源 Markdown、删除。删除当前会话时 active conversation 会被清空；因此中栏随后进入无 active 或 pending 的状态，而不是保留一份失效消息副本。
目标稿 · 查看全部最近区的“查看全部”打开独立标题 Picker，并按生产已有的 chat / agent / plan / canvas / template / custom 会话类型过滤。标题与类型使用 AND 语义；项目归属、主题 icon 和单轮 / 工作流都不是会话类型。重复会话去重，置顶 HTML 设计文档不混进结果，重新打开恢复“全部”。
左栏的用户任务它回答的是“我要在哪个工作容器继续、或者找回哪段历史”，不是“我该如何发送一句话”。如果后续视觉想极简，仍需保留项目容器和独立会话两种语义的可辨识性。

中栏：不是一块固定聊天记录，而是一台 Chat 路由器

中栏复用完整 ChatViewComponent。用户看到同一块区域，但 viewMode 会替换其内容；这既让功能完整，也让“我现在还在聊天吗”成为一个真实的 UX 问题。

Home继续最近对话、总结笔记、研究主题，以及最近会话和项目入口。
All projects浏览全部项目，而不是显示消息线程。
All conversations在中栏查看更完整的会话列表。
Project overviewProjectOverviewViewComponent 显示可编辑说明、对话数 / 消息数 / 收藏数 / 资源数，并切换 Conversations、Starred Messages、Resources；当前生产没有 Plans tab。
Project conversations项目内历史超出侧栏展示时的完整列表。
Pending / active新会话的启动面，或真正的当前会话线程：Header、消息、建议和 Composer。

当前会话线程的元素与交互

Header显示会话标题。有源 Markdown 时可打开源文件；Refresh 触发标题重生成。删除不在 Header，而在左栏会话菜单，避免从正在阅读的内容面直接触发高影响操作。thread identity
滚动消息体切换 active conversation 时同步消息数组，进入时滚到底。流式文本、reasoning 与工具调用改变时，自动滚动帮助用户继续阅读；日期分隔把跨天消息分组。reading continuity
用户消息以用户身份、时间、Markdown 正文、附件簇和发送状态呈现。附件仍属于产生它的消息，而非进入右栏的独立文件表。input record
助手消息富 Markdown / 代码可流式渲染；reasoning 可折叠；工具调用显示摘要；消息头显示工具数、token 数与耗时。最后一条正常回复可出现 capability suggestion 和建议追问。run result
消息操作当前生产提供 Copy、Regenerate、Star、Branch、Copy trace；MessageMorePopover 提供 View raw、复制 Markdown / JSON、保存到 Vault、Reply inline 与可选 Delete。目标稿不让三点永久占位：核心五项始终保留，自适应动作按定向追问、保存、原始消息、Markdown、JSON 的优先级尽量展开，空间不足才反向收入 More；菜单只显示当前隐藏项。保存默认目录为 Peak Chat Saves，可由文案配置改变。reuse / audit
Suggested nextMessageSuggestedNext 默认显示前 2 条建议，其余进入 More；More 还包含 Rewrite simply、Create checklist、Save to Note / Vault 和 Ask Custom。目标稿会复用主 Composer，而不是生成第二个输入框。continue / transform
项目主页ProjectOverviewViewComponent 已有可编辑项目说明、Conversations、Starred Messages 与 Resources；目标稿额外提出 Plans，并保留完整项目主页结构，只把四格统计容器、Tabs 与列表间距压缩。目标稿不在 Hero 放置脱节的“编辑说明”按钮，而把说明文本本身作为就地编辑入口；AI 改写只产出可检查草稿，必须人工保存。同一个 Composer 内联到项目摘要之后、集合导航之前，并沿用“短问候 + 三个项目化起点”的新对话心智。项目主页没有当前会话，因此不显示右侧 Conversation Index；进入具体会话后 Composer 才回到底部、右栏才恢复。Plans 仍不是当前生产既有能力。compact project scope
转项目建议独立会话出现持续工作信号时，中栏能提出转换为项目的建议；它是“临时问答”转向“长期工作容器”的连接点。organization

Composer：把每次运行的输入和上下文放在同一个状态化工作面

Composer 使用 PromptInput 管理文字与附件；它不是另一个 chat mode 选择器。用户从这里写内容、加材料、查看当前模型 / context 摘要，并启用两种实际工具上下文。它在新对话与项目主页中靠近页面起点，在具体会话中才固定到消息体下方。

目标稿 · 新对话起点空态以 今天想推进什么？ 的短问候开始，接一行范围说明、居中的共享 Composer 和最多三个知识工作建议：继续最近工作、总结最近笔记、查找相关材料。点击建议只填入可编辑草稿，不自动发送；用户开始输入后建议退场。
文本与键盘输入内容成为本轮 user message。提交开始后，文字和附件会清空；有文字时发送按钮出现。流式中发送位变为停止按钮，旁边显示 “Planning and writing…” 的可访问状态。
附件底部左侧 + 打开文件选择器。纸夹、第二个 plus、重复的 Vault/Web 图标都没有在底栏重复出现，避免同一能力有两个入口。
Run chip触发器显示当前模型（或 Auto）和 context tag 数。弹层包含 role、模型路由摘要、Vault Search 与 Web Search；后两者是会改变 chatViewStore 的真实开关。
可见控件的真实边界role 选择只保留在 Composer 本地，尚未进入 message dispatch；模型行显示的是当前路由摘要，不是模型选择器；麦克风始终 disabled。UI 设计不能把这三项当成已完成的运行能力。

右栏：从“当前会话”提取一份可回跳的索引

右栏不是第二个聊天记录，也不是一个文件管理器。它只读当前会话的 messages，并把“消息顺序、topic、资源和代码 fence”压缩成可定位的导航结构。

顶部与搜索Studio 的非 compact 版本显示 Conversation Index 标题、当前 tab 的搜索输入和 ⌘K 提示。搜索只作用于内存中的当前时间线或 artifact 名，不会查询其他会话或 Vault。
Overview tab相邻、同名的 message.topic 被折为一个可开合 topic block；无 topic 的消息保持独立。第一组默认展开，topic 内的消息与 artifacts 按发生位置交错排列。
Artifacts tab将资源和 Markdown code fence 推导成 Images、Diagrams、Files、Code 四组。代码块因此也会成为 artifact；这里的“产物”比“已保存文件”更宽。
点击行为消息行和 artifact 行都会平滑滚动到中栏的源消息。artifact 不直接打开或预览文件；它的职责是解释“这一项来自哪一次对话”，不是对文件做管理。
右栏的正确命名它更接近 conversation recall / navigation index，而不是 Workspace、Library 或 Assets 面板。目标稿只在存在当前会话时显示；项目主页已经在中栏拥有对话、收藏、资源和计划，不再复制一套右栏目录。后续如果要做真正的 artifact 工作区，需要另建保存、打开、版本和文件归属的能力合同。

体验边界：后续重构不应掩盖的事实

下面不是视觉偏好清单，而是当前功能结构带来的 UX 约束。它们决定三栏为什么显得杂，以及视觉设计需要先解决哪一种语义冲突。

品牌与对象竞争Studio 已经是独立工作面，左栏却仍展示产品标识和一组全局工具。用户进入会话前先看到产品身份，而非当前项目或当前线程。
项目与会话混合导航Projects 是长期容器，Conversations 是线程历史；它们共用搜索、排序和选中态，却没有明确的范围模型。项目展开会再次出现会话层级。
中栏状态切换中心区既是聊天线程，又会变成 Home、项目概览和列表。功能完整，但它不是单一稳定的阅读面，这会影响标题、Composer 和右栏在各状态下应否出现。
控件与能力不完全一致Vault/Web 为真实开关；role、模型行、麦克风则没有相同的执行效力。任何新 UI 应用“可操作、可解释、不可用”三种清晰状态，而不是混在一个弹层里。
Artifacts 的名称风险右栏把附件和代码 fence 都称为 artifact，但点击只回跳消息。若想让它成为产物库，需先补齐保存、打开、预览与生命周期，而不是仅改变视觉层级。
窗口偏好不可持久栏宽和 popout 都是当次 UI 状态。把 Studio 设计成长期高频工作台前，需要决定是否保存布局、是否允许折叠、窄宽度时如何给中栏保留优先级。
做视觉方案前的产品选择先决定中栏的主对象是“一个会话线程”，还是“项目中的 AI 工作台”。当前左栏偏项目容器、右栏偏线程回忆，而中栏在两者之间切换；这个选择不明确，换皮很难真正减少杂乱感。
